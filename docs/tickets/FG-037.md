# FG-037 — no Jenkins-style steps-per-stage ceiling in Fogell

Status: **PARTIAL**. The 400-step acceptance and pinned-Jenkins boundary were
measured from consolidated source commit
`65674f9a4af80e358f645ad3409765a8738c68b4`; exact-head publication review,
hosted checks, and merge remain.

## Scope

Fogell already represents a stage's steps as a list and had no configured step
limit. What was missing was an executable regression and retained evidence for
the competitive claim. This slice changes the differential harness but not
Fogell's pipeline execution semantics. It adds:

- an in-process Differential test that synthesizes 400 ordered top-level `echo`
  steps, runs the real Fogell parser/walker, and requires all 400 unique markers
  exactly once and in order;
- a live, non-build-gated probe of exact 250-, 251-, and 400-step inputs against
  the pinned Jenkins 2.568.1 lab;
- a fail-closed semantic checker, controller-identity binder, and 23-arm hostile
  proof; and
- a manifest-bound evidence bundle holding the exact case bytes and sealed
  receipts.

The intentional divergences live only in retained evidence. They are not under
`differential/cases` or `differential/receipts`, so they cannot poison the
compatibility suite or change its denominator.

## Measurement

All three inputs have one stage. Step 1 writes `reached-agent.txt`; every later
step emits its own numbered marker. The 250- and 251-step inputs are byte-for-byte
the same except for the added `FG037-251` step.

| steps | Jenkins 2.568.1 | Fogell | sealed observation |
|---:|---|---|---|
| 250 | success, sentinel workspace, 250 output lines | success, identical workspace/output | tier-1 `PROVEN` |
| 251 | failure, empty workspace, no sentinel/marker output | success, sentinel workspace, all 251 output lines | `DIVERGED (3)` |
| 400 | failure, empty workspace; compiler reports 400 arguments above its 255 maximum | success, sentinel workspace, all 400 output lines | `DIVERGED (3)` |

The differential runner repeated each divergence three times before sealing it.
The semantic checker does not pass on the runner's expected exit code alone. It
binds each receipt to the retained case digest, requires Jenkins core 2.568.1,
parses each engine block, checks the exact result and sealed workspace hash, and
requires Fogell's complete ordered marker sequence. For the Jenkins-negative
cases it requires an empty workspace and absence of the first-step xtrace and all
markers. The raw 251 console additionally proves the exact 251-object
`ArrayUtil.createArray` `NoSuchMethodError` and ordered pre-execution
`WorkflowScript`/`CpsFlowExecution` stack; the 400-step case requires the exact
400-over-255 compiler diagnostic. Other controller narration is allowed because
it is not a build effect.

The mutation proof demonstrates that the checker rejects a substituted core, a
forged Jenkins success, a missing final marker, promotion of a divergence to
`PROVEN`, a weakened `DIVERGED (1)` line, a forged suffix on the exact 250-step
verdict, a missing 400/255 diagnostic, an unrelated infrastructure failure, a
250-object causal-signature substitution, a claim that Pipeline execution began,
a missing CPS parse frame, fixture drift, an extra receipt, and a missing receipt.
Three identity substitutions additionally prove that a same-version stale URL,
a wrong endpoint core, and a controller restart during the run are refused.
Four collector/configuration arms prove that a dirty shared workspace collector
and a failed collector Base64 encoding are refused before network access or
evidence-directory creation, and that hostile SSH host and remote-inspect
container overrides are inert through both local and remote shell parses. Two
manifest arms prove that an unlisted retained file is rejected and that a payload
plus self-consistent replacement manifest cannot bypass the trusted digest.

The runner's source preflight covers tracked and untracked `src/`, `tools/`,
`Fogell.slnx`, `global.json`, existing or future root `Directory.Build.*` and
`Directory.Packages.*` files, and root `NuGet.Config` under a case-insensitive
pathspec. It also covers every load-bearing focused probe/checker script. The
identity checker, exact-inventory manifest checker, and shared workspace collector
are snapshotted from `HEAD`, compared to the worktree, executed only from those
snapshots, and recorded by SHA-256. Before and after all builds, the HTTP endpoint and container-loopback
must report the same `X-Jenkins` core and `X-Jenkins-Session`, with the core also
matching the selected container artifact. It then builds the
exact `tools/Fogell.Differential.Cli/Fogell.Differential.Cli.fsproj` Release
project with `--no-incremental` before invoking that project with `--no-build`,
so a stale CLI or engine binary cannot satisfy the probe. Planted untracked
future `Directory.Build.*` and conventional-case root `NuGet.Config` files were
each refused before an evidence directory was created.
The exact initial commit/tree and every governed engine/probe input are checked
again after the semantic/hostile proofs and immediately before manifest creation;
any final drift refuses publication. The differential harness exports the exact
251 job/build console atomically before deleting its disposable job; every retry
replaces the prior attempt, and a configured export failure makes the run
non-comparable. The ordinary repository gate independently pins the trusted
manifest digest, requires its exact file inventory and hashes, then recomputes all
three receipt seals.

## Limits

- Exercising 400 steps proves the ticket's 400-step bound, not mathematical
  infinity. “No configured ceiling” remains a source property of the list-backed
  implementation.
- The live Jenkins probe is not a CI gate. It requires the pinned lab; the fast
  400-step Fogell regression is the standing build coverage.
- The normalised 251 receipt omits engine-specific compiler wording. Its
  manifest-bound raw-console companion supplies the affirmative 251-object
  `ArrayUtil` cause and pre-execution CPS stack; the receipt separately binds the
  adjacent 250 success, terminal failure, empty workspace, and absence of effects.
  The 400-step receipt retains the explicit 255-argument compiler diagnostic.
- Only the 250-step control is compatibility evidence. The 251/400 receipts
  demonstrate a deliberate Fogell capability advantage and must not be counted
  as tier-1 parity.
