# `AgentSpec -> Placement` seam: labels as capability sets, refused at admission when not offered

Priority: **P1**

Verb: **route** a build to a labelled node.

Status: **TODO**. Filed 2026-09-10 by the Track 4 re-cut (`adr/0009`). FG-050
is SUPERSEDED by this row; its re-measure is the demand.

## Demand

The `agent { label }` row of [FG-263](FG-263.md)'s table, which includes the
`agent { node { label } }` form (FG-050's 2026-08-17 re-measure read 26 by a
wider pattern, and FG-263 records both). `docker` agents are FG-273's count,
not this row's. FG-253 made the engine
refuse them where it used to run them on the built-in node, so the class is
guarded and no file in it is receipted. Today only `any`, `none` and the
literal `label 'built-in'` are executed (`Fogell.fs`, the `unsupported_agent`
refusal); the scheduler's `required_capabilities` column and containment claim
exist (`Store.fs`, `ClaimNextExecution`) but the API hard-codes `["linux"]`.

## Design

- `src/Fogell.Domain/Placement.fs`: `Placement = { TrustPool; Capabilities: Set<string>; Runtime: Host | Container of ContainerSpec }`
  and `PlacementRefusal = LabelNotOffered | LabelExpressionUnsupported | AgentKindUnsupported`.
- A pure `Placement.place : offered -> trustPool -> AgentSpec -> Result<Placement, PlacementRefusal>`
  in the walker project. `AgentAny` maps to `{"linux"}`, Host. `AgentNone`
  maps to the EMPTY requirement (it allocates nothing), so a pipeline with
  `agent none` and one `agent { label 'windows' }` stage requires only
  `{windows}`; a stage that would execute steps with no agent from any level
  refuses at preflight (`stage_without_agent`), which is what Jenkins does at
  run time (Codex, PR #446).
  `AgentLabel l` maps to `{l}` if offered, else `LabelNotOffered`, refused at
  admission as `unsupported_agent_label` naming the label — refusal rather
  than Jenkins' queue-forever, for the reason `adr/0009` gives. `&&` in a
  label expression is a union; `||` and `!` refuse.
- Stage-level agents: the claim is whole-pipeline, so a build's capability set
  is the union over the pipeline agent and every stage agent, all satisfied by
  one worker.
- `Store.ExplainWait` today reports "N attempt(s) claimable now" when the
  capabilities match and nothing is missing; it gains a third arm that
  reports how many executor slots the offering worker has and that all are
  busy, which is the only wait an offered label can have once FG-271 lands.
- `ControllerConfig` gains `FOGELL_WORKER_LABELS` (default `built-in,linux`);
  the submit route replaces its `["linux"]` literal with the placement's
  capabilities; `NODE_NAME` becomes the configured worker name.
- `docker`/`dockerfile` map to `Container` and stay refused until FG-273
  supplies the launcher; the refusal code becomes `unsupported_agent_docker`
  so the blanket `unsupported_agent` retires into per-kind codes.
- Scripted `node('label')` (FG-263's scripted `node(label)` row) goes through
  the same seam once FG-265 hosts `node`.

## Acceptance

A tier-1 receipt for a corpus file declaring `agent { label 'x' }` with the lab
node labelled `x` on both engines; admission refuses an unoffered label by
name with a diagnostic listing the offered labels (there is no queued attempt
for `ExplainWait` to inspect in that case, as Codex noted on PR #446, so the
admission response is what is tested); `ExplainWait` names the wait reason
for an OFFERED label whose executor slots are all busy; the union rule is
proven by a hand-written case with two stage agents.

## Jenkins probe first

Measure on luigi: `NODE_NAME` and `NODE_LABELS` values on the built-in node
with an added label; console narration when a stage agent differs from the
pipeline agent (`Running on <node> in <workspace>`); and whether a label
expression with `&&` is accepted by the pinned version.
