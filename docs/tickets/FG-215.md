# FG-215 — JUnit namespaced XML local names

Status: **DONE** on 2026-08-23. The authoritative gate passes on the final
ticket tree; exact-head CI and review are the remaining repository merge
controls, not ticket implementation work.

## Bounded claim

Inside JUnit report ingestion only, direct element and attribute lookup matches
an exact, case-sensitive local name while ignoring XML namespace URI and
prefix. Direct-child reachability, child-first document order, marker
precedence, identity faults, count aggregation, and binary32 duration behavior
remain unchanged. Attribute collisions select the first matching local name in
document order. Namespace declarations are not attributes.

The document root remains reached unconditionally. Only direct `testsuite`
children are traversed; only direct `testcase` children and direct
`error`/`failure`/`skipped` markers contribute. Wrong capitalization, longer
lookalikes, and suites hidden behind arbitrary wrappers remain ignored. This
ticket does not change general XML behavior outside the JUnit parser.

## Implementation

`Publish.parseJUnitWithAbort` now has two local helpers. `directElements`
filters immediate children by `XName.LocalName`, preserving LINQ document
order. `firstAttribute` filters ordered attributes the same way while explicitly
excluding `IsNamespaceDeclaration`. All previous JUnit expanded-name lookups
use those helpers; the iterative traversal and every aggregation/fault phase are
otherwise untouched.

Focused coverage proves default, prefixed, and independently mixed namespaces;
namespaced failure/error/skipped markers; exact case and longer-name rejection;
prefixed `name`, `classname`, and `time`; first-local-attribute order in both
lexical orders; and the `xmlns:name` missing-identity trap. Execution passes
51/51.
