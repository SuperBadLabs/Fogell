HeMan but not in the Jenkins oracle container. FG-245, FG-247, and the Tier-1

## Exact toolchain pin

HeMan's `/usr/bin/make` comes from Ubuntu package
`make 4.3-4.1build2 amd64`. The executable is GNU Make 4.3, built for
`x86_64-pc-linux-gnu`, with SHA-256
`d78b8f1d099fbcfb6f2f49ab87223b9b68fb3956642f92d6ec6de812e8afa965`.

The live Jenkins image had no `make`, and its Debian 13 apt cache had no
candidate. Rather than install an unbound package into the container's writable
layer, the exact HeMan executable was copied into an offline derivative of the
pinned oracle image. The build used `--network=none --pull=never --no-cache`,
copied the executable to `/usr/local/bin/make`, and made this SHA check a build
step:

```text
d78b8f1d099fbcfb6f2f49ab87223b9b68fb3956642f92d6ec6de812e8afa965  /usr/local/bin/make
```

## Probe before permission to execute

Before the corpus allowlist changed, the real invocation was run three times on
each side from a directory containing only `script.sh.copy`:

```text
+ make build-base
make: *** No rule to make target 'build-base'.  Stop.
```

All six attempts exited `2`, byte-identically. The oracle attempts ran as uid
1000 (`jenkins`) inside the active derived-image container with `LANG=C.UTF-8`;
the HeMan attempts used the same locale and the same executable bytes. The
allowlist then bound the corpus digest and executed surface to structured
runtime pin `gnu-make-4.3-d78b8f1d`. That pin names the command, both resolved
paths, their one expected SHA-256, the Jenkins image ID and digest, container
port `8080/tcp`, and host binding `0.0.0.0:18083`. The corpus lane fails closed
unless it verifies that tuple under the cross-host lease before execution and
again before receipt promotion. The execution URL must be exactly HTTP, name
the same host used for SSH inspection, and use the port published from that
container port; it cannot independently select an uninspected oracle. A
service-free hostile proof rejects local or Jenkins command shadowing, either
tool hash drifting, image-ID or image-digest drift, endpoint host/port/path or
container-binding drift, unavailable inspection, malformed and duplicate rows,
missing pin IDs, or either runner check being removed.

## What this proves and does not

This proves the Declarative walk through `agent any`, the first stage and a
one-line `sh`; the exact Make executable and diagnostic; failure propagation;
empty-workspace identity; and ordered skipping of both later stages. It does not
prove any intended Make target, Docker build, `ls`, or JUnit behavior because
none is reached. It does not turn an operator-built oracle derivative into a
general package-distribution claim.

The retained image and tool identities make this receipt reproducible on the
current lab. The recorded 154-plugin inventory digest is context, not a lane
prerequisite: the mutable `jlab_home` volume is not frozen by the image ID, so
plugin-volume reproducibility is not claimed. Promoting the toolchain to a
separately published, supply-chain-attested oracle image is outside this
compatibility slice.

The receipt seal itself binds the case digest, results, compared output, and
workspace hashes; it does not encode tool identities. The signed source commit
binds that seal to the allowlist's structured pin and the fail-closed lane which
checks it. The publication record below binds both exact identities.
