# FG-212 — JUnit missing testcase name

Status: **DONE** on 2026-08-22.

## Measured boundary

Pinned Jenkins 2.568.1 with JUnit plugin `1416.vd753e036de5e` distinguishes a
missing testcase `name` from FG-211's unresolved class identity. When a reached
testcase has neither `classname`, an owner `name`, nor its own `name`, the case
constructor terminates with the exact diagnostic
`Cannot invoke "String.contains(java.lang.CharSequence)" because "nameAttr" is null`.
The fault occurs before pass/failure/error/skipped classification, publishes no
summary, prevents continuation, and is not suppressed by `allowEmptyResults`.

The testcase `name` is not independently required. An explicit testcase
`classname`, including `classname=""`, or the reached owner's raw `name`,
including `name=""`, supplies the class fallback before the constructor reads
the testcase name. A missing or empty testcase name is then normalized by the
pinned object to `(?)`; its case still contributes ordinary typed counts. If no
class fallback exists, a present empty or simple testcase name remains FG-211's
later null-`className` terminal path, while a dotted name supplies the legacy
class prefix and remains admissible.

The pinned recursive parser visits direct `testsuite` children first in document
order, then the current owner. That order was not observable when Fogell only
published totals; it becomes observable when missing-name and missing-identity
faults compete, but the two faults occur in different global phases. Construction
reads globally sorted distinct report paths and walks every reached case
child-first/document-order. Missing testcase name and unrecovered report reads
fail immediately, so the first such problem in that global construction pass
wins. A simple or empty name with no class fallback constructs a `CaseResult`;
its FG-211 null-className fault is deferred until tally, after all reports have
constructed. Consequently a later missing-name construction fault outranks an
earlier unresolved identity, while two immediate problems retain sorted-file
order.

## Implementation boundary

`Publish.parseJUnitWithAbort` now keeps missing testcase name distinct from
missing class identity. Each direct case is classified in the pinned order:
explicit testcase classname, owner raw name, then testcase-name handling. An
absent testcase name without either class fallback publishes the exact pinned
missing-name line; an empty or simple present name without a fallback retains
FG-211's exact missing-identity line; a dotted name remains valid.

Traversal remains iterative so hostile nesting cannot consume the native call
stack, but enter/exit frames preserve child-first document order. The construction
pass records unresolved identity and continues through later cases and reports;
only after construction completes does the deferred FG-211 tally failure win.
Missing-name and generic unreadable problems instead stop construction at the
first globally sorted report that exposes either one. Speculative counts are
never published on any terminal path. Interruption still outranks all parser
problems, malformed lowercase-`.xml` and zero-byte recovery remain synthetic
failed cases, and checked aggregation plus typed zero-result behavior remain
separate established paths.

## Residual boundary

FG-212 models the four-count projection and exact terminal diagnostics, not the
raw `(?)` UI decoration, class/package grouping, history identity, or the rest of
`TestResultSummary`. Namespaced or otherwise nonexact XML, duplicate attributes,
exotic whitespace, arbitrary nested wrappers, and unrelated report dialects
remain outside the bounded reached-owner contract.

JUnit duration, stdout/stderr attachment, remaining object/UI operations,
numeric-width arithmetic, explicit preexisting-build-result behavior, and other
options remain open under FG-177.
