# FG-085 — byte-verified PostgreSQL backup and restore

Status: **DONE**. The bounded backup/restore drill, its hostile proof, and the
hosted PostgreSQL 16 lane are part of the blocking repository gate. The scripts
retain the historical internal label `FG-085a`; that label is this ticket's
implementation slice, not a separate open board item.

## Closed contract

`scripts/backup-restore-drill.sh` creates a private source database, applies the
complete ordered migration set, and loads non-empty durable state spanning
organizations, projects, builds, nodes, retry lineage, events, outbox, logs, the
migration ledger, and sequence state. It then:

1. creates a PostgreSQL custom archive with client tools whose major version
   exactly matches the server;
2. records the archive SHA-256 and proves that `pg_restore --list` can read it;
3. creates a separate empty target database and refuses any pre-existing user
   relation;
4. re-hashes the archive immediately before a single-transaction,
   exit-on-error restore; and
5. rebuilds canonical schema, sorted data, and sequence inventories from both
   databases and requires byte equality plus equal SHA-256 for each inventory.

The acceptance property is therefore **canonical schema, data, and sequence
byte identity after restore**. The old execution-board shorthand, "restored DB
hash matches source", was too broad: PostgreSQL database storage and custom
archive bytes are not reproducible physical images, and the drill never claimed
that they were.

The destructive boundary is deliberately small. Generated database names must
match `fogell_fg085a_<token>_(source|target)` before any access or cleanup; the
drill owns exactly those two databases and exact files beneath one private
`mktemp` directory. Success is emitted only after every comparison completes
and cleanup succeeds.

## False-green resistance

`scripts/prove-backup-restore-drill.sh` executes the real candidate through a
purpose-built container-command protocol surrogate, mutates only private
scratch copies, and requires fifteen unique byte-changing defects to become
observable. The mutations cover source-vs-source comparison, row-count-only
comparison, omitted schema/sequence checks, unsorted data, ignored
dump/restore/cleanup failures, empty archive or inventory acceptance,
contaminated targets, archive mutation after hashing, an overbroad database
namespace, raw random schema guards, and a regression to PostgreSQL's
non-canonical deparse shape. Separate controls refuse empty schema and sequence
inventories, a truncated archive, a client/server major mismatch, and omission
or regression of the canonical constraint migration.

The hosted workflow then runs both the hostile proof and the genuine drill
against its PostgreSQL 16 service using the service container's own `psql`,
`pg_dump`, and `pg_restore`. The fake boundary proves that named false greens
are rejected; the live boundary proves that PostgreSQL actually performs the
round trip. Neither substitutes for the other.

## Boundaries and nonclaims

FG-085 proves one full-schema logical backup/restore round trip over a
deliberately non-trivial fixture. It does **not** establish physical database or
dump-byte reproducibility, point-in-time recovery, WAL archival, encryption,
off-host retention, scheduling, rotation, production credentials, workspace or
artifact backup, production-scale duration, or an operational RPO/RTO.

FG-081 separately owns N−1 → N → N−1 → N migration rollback. FG-023 owns
restore-epoch and lease invalidation. FG-082 owns controller/process crash and
reboot recovery. FG-223 owns evidence-bundle publication. None of those claims
is imported into this closure.
