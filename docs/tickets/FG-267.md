# FG-267 — Immutable source identity and reproducible submission

Status: DONE. Owner: source/client implementation subagent. Milestone: M2. Depends on: M1 observations.
Completion scope: local implementation and measured acceptance (2026-09-23); publication remains separate.

Problem: a pipeline source and build ID alone do not prove which proposed code
revision was tested, especially with dirty worktrees or moving branches.

Scope: versioned submission manifest binding verified repository revision or
explicit content snapshot, pipeline digest, tool/environment identity and
parent correction-loop ID. Keep caller assertions separate from worker-verified
identity. Define dirty-tree handling and bounded snapshot transport before code.

Acceptance: moving branch and dirty-tree negative controls cannot produce a
result falsely attributed to a clean commit; duplicate identical submission is
idempotent, changed manifest conflicts; a second fresh workspace reproduces
the selected fixture with the same inputs; controller credentials/environment are
not collected and credential metadata/paths are refused; feedback exposes identity
and its verification state. Explicitly selected source is caller-controlled and
may contain embedded secrets; snapshot transport does not claim secret scanning.

No automatic remote checkout of arbitrary caller URLs or uncertain-effect replay.


Implementation and bounded transport design:
- [Source snapshot runbook](../runbooks/source-snapshots.md) defines explicit
  file inventory, content-only authority (no Git clean/commit assertion),
  path/type exclusions, 16 MiB decoded / 24 MiB JSON / 4096-file bounds,
  pipeline/environment/parent identity and optional exact tool-closure pin.
- `SourceSnapshot.fs` validates all declared content hashes and canonical tree
  identity; strict unknown/duplicate property refusal keeps arbitrary caller
  metadata and credentials out of the manifest schema.
- The client packs snapshots offline, computes tool identity, submits the full
  envelope idempotently and downloads the original envelope for reproduction.
- Existing immutable definition bytes bind idempotency atomically. Migration
  0016 adds tenant-isolated verification metadata; worker publication checks
  attempt/build lineage, lease, fence, restore epoch and admitted definition.
  Run.Host materializes source after its fresh workspace wipe and before steps.
- Feedback separates pending from verified content identity; client refuses
  successful snapshot completion lacking verification or matching tool pin.
  Retention tombstones refuse replay with 410 and preserve bounded provenance.

- Controls cover changed source/pipeline hashes, fake clean/branch/revision

  symlinks, environment mismatch, exact bytes in two fresh workspaces, executable

  pass exact replay, changed-manifest conflict, byte-identical source download,

passes all 1,385 tests and every required proof lane.
