# FG-217 — JUnit Ant default excludes

Status: **DONE** on 2026-08-23. The bounded implementation, canonical proof,
and retained evidence bundle are complete; exact-head CI and review remain as
repository merge controls.

## Bounded claim

On the pinned Linux Jenkins/JUnit boundary, JUnit report selection applies the
exact 28 case-sensitive default excludes from Ant 1.10.17. The excludes apply
before report construction, including when `testResults` names an excluded path
literally. An excluded-only selection therefore follows the existing no-report
or `allowEmptyResults` path; excluded reports cannot affect counts, duration,
result, or continuation.

The list is private to JUnit report selection. Existing case-sensitive include
matching, comma tokenization, supported wildcard translation, deduplication,
global sorting, interruption, XML construction/tally, count, duration, and
build/stage result behavior are unchanged.

This slice is both narrow and corpus-facing. The pinned corpus contains 36
direct `junit` invocations across 31 files. Twenty-five of those invocations,
across 22 files, use recursive `**` selection and can cross a default-excluded
directory unless the scanner boundary is preserved.

## Implementation and focused proof

`Publish.compileGlobRegex` owns the pre-existing supported glob translation.
The JUnit-only entry point filters its case-sensitive matches through the exact
pinned Ant list. The public/shared `Publish.expandGlob` path used by archive and
stash remains unchanged.

Focused Execution coverage supplies one filesystem witness for every one of the
28 Ant entries, plus exact-case near misses (`.SVN`, `.gitx`, `CVSx`, and an
ordinary backup suffix). It also proves:

- excluded failures stay out of counts, duration, and result;
- a literal include cannot override a default exclude;
- the excluded-only default path is terminal no-report behavior;
- `allowEmptyResults: true` returns the existing zero summary; and
- the shared archive/stash matcher still returns the same excluded path.

`Fogell.Execution.Tests` passes 53/53.

case explicitly selects a sole valid `.svn/report.xml`; both engines produce the

## Non-goals

This ticket does not change or claim:

- archive or stash default-exclude behavior, including FG-044b;
- scanner pruning, inaccessible-directory behavior, symlink traversal, or
  platform-specific separators;
- runtime mutation of Ant's process-global default-exclude set;
- `skipOldReports`, richer Ant syntax, or unmeasured wildcard edges;
- JUnit object/raw-UI storage such as stdio, attachments, checks, or health;
- generic decimal or numeric-width behavior; or
- XML name lookup, construction/tally precedence, identity diagnostics, counts,
  duration aggregation, or marking semantics beyond excluding reports before
  those established paths run.
