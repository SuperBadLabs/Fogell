# Extend the queue-row audit and its proof to Track 4

Priority: **P1**

Verb: bookkeeping — rides with the board PR that creates Track 4 (`adr/0009`, product rule 1).

Status: **TODO**. Filed 2026-09-10 with Track 4 itself. A CODE change, so it
ships in its own PR AFTER the board PR that creates Track 4 lands: the reverse
order would make the required-track check refuse a board with no Track 4.

## Defect

`scripts/audit-queue-rows.py` finds queue tables by the heading regex
`^### Track ([123]) ` and requires exactly that set. The 2026-09-10 board
re-cut adds `### Track 4 — Capability`, whose rows the checker therefore never
scans. A ranking table the checker cannot see is the FG-198 shape exactly: a
guarantee held by whoever is looking. The board says so on the Track 4 table
by pointing at this ticket's status cell rather than with an instruction that
expires.

## Fix

- The heading regex admits `[1234]`; the required-track set includes `4`.
- `scripts/prove-queue-rows.sh` gains an arm that plants a deny-listed phrase
  INSIDE Track 4 and watches the audit reject it, and an arm that removes
  Track 4 entirely and watches the audit refuse to pass (a checker must be
  proven to fail).
- `scripts/fsx/audit-board-numbers.fsx` is NOT changed by this ticket; Track 4
  sits above the canonical wave region and is not accounting.

## Acceptance

The committed board passes; the two planted-mutation arms fail as planned
three times in a row; the gate's `build` lane runs both on the exact head.
