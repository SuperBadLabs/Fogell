## The script.sh.copy identity — measured, fixed, sealed

`ProcessGroup.fs` materialised every shell step to
`<workspace>@tmp/durable-<8hex>/script.sh` and ran `sh -xe` on that path,
with a comment claiming this was "the same OBSERVABLE identity durable-task
gives a script (`$0` basename `script.sh`)". It is not, on the pinned lab.
durable-task (686 here) writes `script.sh`, then `cp script.sh
script.sh.copy` and executes the COPY — JENKINS-70874: a writable handle to
the original, inherited by a fork, raised "Text file busy" — so `$0` ends in
`script.sh.copy`, the original stays beside it, and the copy carries the
original's mode (`cp` preserves it: a plain script is 0644 and not
executable, a shebang script is chmod 0755 first and its copy is
executable). All of that was measured with a probe case before the fix —
Jenkins printed `…/script.sh.copy`, `noexec`, `original-present` for the
plain step and `…/script.sh.copy`, `exec` for the `#!/bin/bash` step; Fogell
printed the same with `script.sh` — and the probe became
`differential/cases/sh-script-identity.Jenkinsfile`, PROVEN after the fix.

The fix writes the copy beside the original, owner-only from the first byte
with the same mode (the copy is written from the same text rather than
`cp`'d, so it never exists with a wider mode), passes the copy's path as the
positional script argument, and deletes both files before the directory. The
`applyDurableShape` normaliser on the Jenkins side and the exact-id
replacement on the Fogell side both rewrite the `@tmp/durable-<hex>/script.sh`
prefix and leave `.copy` in place, so no comparison rule changed; the
workspace hash already excluded `script.sh.copy` as a spool file
(`Trace.fs`), which is how the name was known to this repository before
anything ran it. Every receipt whose output names `$0` — dash's `not found`
and `can't cd` lines, `$0`-printing scripts — depended on this; the 301
existing receipts did not, and still verify.
