## The class this pass found, and what it is not

FG-242's table filed `sixeyed_jenkins-pipeline-demos` as "no — the script
comes from the repository the Jenkinsfile lives in, which neither engine
checks out", and `llknur` and the two `linuxacademy` files under "the other

question "can this file SUCCEED here?", and the answer is still no. The
differential asks a different question: does Fogell do what Jenkins does
with this file, in this harness, with an empty workspace. For these four
the answer is measurable without any tool, because the first shell command
fails on the empty workspace and the failure text is emitted by a program
both sides already have, identically:

| file | first command | who emits the failure | measured on both sides |

So each receipt proves: the declarative walk to the first `sh`; the `-x`
trace of the body (a three-line body in `sixeyed`, so the trace and the
output interleave); the failing program's text arriving through the merged
stream; a non-zero exit failing the step, the stage and the build; and,
in `llknur`, a second stage SKIPPED with Jenkins' own sentence
(`Stage "run" skipped due to earlier failure(s)`). `sixeyed` also
interpolates `$BUILD_NUMBER` and an `environment { DEMO='1.3' }` literal
into one `echo`, and both engines print `This is build number 1 of demo 1.3`.

What a receipt in this class does NOT prove: anything about the pipeline's
intended build. `test.sh`, `Hello.java` and `gradlew` live in repositories
neither engine checks out, and no receipt here says what Fogell would do if
they were present. The allowlist rows say "a failure receipt on an empty
workspace" for that reason, and the board row says the same. The harness
already treats failure parity as PROVEN — `nonzero-exit`,
`archive-empty-fails` and `stash-empty-fails` are hand-written receipts
with `result: failure` on both sides (and `junit-failing` is `unstable` on
both; a first draft of this sentence filed it under failure, and the
verifier read the receipt) — and a corpus file is not excused from the same
verdict rule.

## The script.sh.copy identity — measured, fixed, sealed

`ProcessGroup.fs` materialised every shell step to
`<workspace>@tmp/durable-<8hex>/script.sh` and ran `sh -xe` on that path,
with a comment claiming this was "the same OBSERVABLE identity durable-task
gives a script (`$0` basename `script.sh`)". It is not, on the pinned lab.
durable-task (686 here) writes `script.sh`, then `cp script.sh
script.sh.copy` and executes the COPY — JENKINS-70874: a writable handle to
the original, inherited by a fork, raised "Text file busy" — so `$0` ends in
`script.sh.copy`, the original stays beside it, and the copy carries the
original's mode (`cp` preserves it: a plain script is 0644 and not
executable, a shebang script is chmod 0755 first and its copy is
executable). All of that was measured with a probe case before the fix —
Jenkins printed `…/script.sh.copy`, `noexec`, `original-present` for the
plain step and `…/script.sh.copy`, `exec` for the `#!/bin/bash` step; Fogell
printed the same with `script.sh` — and the probe became
`differential/cases/sh-script-identity.Jenkinsfile`, PROVEN after the fix.

The fix writes the copy beside the original, owner-only from the first byte
with the same mode (the copy is written from the same text rather than
`cp`'d, so it never exists with a wider mode), passes the copy's path as the
positional script argument, and deletes both files before the directory. The
`applyDurableShape` normaliser on the Jenkins side and the exact-id
replacement on the Fogell side both rewrite the `@tmp/durable-<hex>/script.sh`
prefix and leave `.copy` in place, so no comparison rule changed; the
workspace hash already excluded `script.sh.copy` as a spool file
(`Trace.fs`), which is how the name was known to this repository before
anything ran it. Every receipt whose output names `$0` — dash's `not found`
and `can't cd` lines, `$0`-printing scripts — depended on this; the 301
existing receipts did not, and still verify.

## What this class leaves

when the failing program exists on BOTH sides with the same message. Read
the same way, the remaining declarative `sh`-only files divide as:

  (`buildit`, `jenkins-infra`, `holdennguyen`, `qiuhuanhen`) and
  `zhangjian-ai_AutomationTestPlat` (`docker-compose`): the tool exists on

## The allowlist, stated

The executed surface is `sh` running, in order, `echo` of a literal then
`chmod` on an absent file; `javac` on an absent source; and `./gradlew`
when no such file exists. No process reaches the network, nothing is
written to either workspace (the hash on both sides is the empty-tree hash
on every receipt), and the fence stood on both sides for every run — the
lane refuses to promote otherwise. `java Hello`, `./test.sh` and
`archiveArtifacts` are in the files and were never reached; the allowlist
rows say so.
