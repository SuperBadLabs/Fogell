## Why a generated count

`corpus/BASELINE-DECLARATIVE-SCORE.tsv` reads 87 declarative-ok, 6
declarative-err, 109 scripted-ok, 26 scripted-err of 228, and
`scripts/fsx/generate-scorecard.fsx` (the `scripted-ok` fold, near line 193)
folds the 109 into "admitted". The first 2026-09-10 demand pass counted by
plain substring (`rg -l`) and the pre-push verifier refuted it: `script` 80
(the block appears in 47 files), `parameters` 30 (17), `mail` 25 (6),
`library` 48 (5), `docker` 74 (the global appears in 24), `build` 179 (`build
job:` appears in 4). The second pass used construct patterns but counted
commented-out lines, and the verifier found nine rows inflated by one to three
files that way and three rows under-reading a spelling. The second-pass
readings that differ from the table below: `currentBuild` 38, `withCredentials` 23, `parameters` 18,
`@Library` 17, `env.X =` 17, `triggers` 12, `tools` 10, `agent { docker }` 9,
`emailext` 7, `mail` 5 (which also missed the `body:` spelling), `library` 4
(missed `identifier:`), `input` 13 (missed the bare-string form). The third
pass is the script below; both earlier readings are recorded here so the next
survey does not repeat them.

## Construct counts, 2026-09-10 (interim one place)

Generated by this script, run on HeMan against the pinned corpus (228 files,
manifest matching `corpus/CORPUS-SHA256SUMS`). A count is a FILE count, not an
occurrence count. Lines whose first non-blank characters are `//` are removed
before matching; block comments are not removed, which is a stated limitation
the committed instrument must close. "Decl" restricts the same match to the 93
files with a top-level `pipeline {` block; a Decl of 0 means the construct is
scripted-only until FG-265 lands and unlocks nothing before it.

## Design

1. The scorer already emits the form; the generator stops folding. New tokens
   `admitted_declarative=N`, `scripted_admitted=N`, `scripted_refused=N` in
   `docs/COMPATIBILITY-SCORECARD.md` and the ledger, with
   `scripts/fsx/audit-board-numbers.fsx` verifying each against the ledger
   exactly as it verifies `tier1=`/`tier3=`/`admitted=` today. `admitted=`
   keeps its current meaning for one release with a generated note that it
   includes scripted files; the board quotes the split, not the fold.
2. The count above moves from a script in a ticket to a committed tool under
   `tools/` that uses the engine's own parsers (so comments, strings and
   receivers are handled by the grammar, not by regex), runs in the gate, and
   regenerates this table. Where the generated count disagrees with the table
   above, the table is corrected and the disagreement recorded, never
   defended.
3. Track 4 rows cite this ticket; when the instrument lands they cite its
   output.

## Acceptance

The generated scorecard carries the three form tokens; `audit-board-numbers`
refuses a board token that disagrees with the ledger for each of them
(`prove-board-numbers.sh` gains a planted-drift arm per token); the
per-construct count is produced by a committed tool with the rule it applies,
re-run in the gate, and the table above is replaced by its output.
