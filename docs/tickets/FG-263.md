# FG-263 — Bounded feedback read API

Status: DONE. Owner: API subagent.
Milestone: M1. Depends on: FG-262 contract.
Completion scope: local implementation and acceptance.

Problem: clients must compose status and logs and can observe inconsistent
completion; raw log pages lack a byte-bound agent feedback contract.

Scope: implement the version-1 feedback endpoint in the
[design](../architecture/AI_FEEDBACK_LOOP.md), backed by one database snapshot.
Reuse tenant/project checks, masked stored logs and existing status authority.
No schema migration or raw event export is required.

Acceptance:
- Authorized live and terminal builds return versioned status plus bounded logs.
- Missing/wrong organization or project is 404; auth and cursor errors retain
  named codes. No cross-project disclosure.
- Count and 64 KiB UTF-8 content caps hold, including a multibyte oversized
  chunk; truncation and continuation are explicit and cursors make progress.
- Empty pages and terminal-with-backlog remain distinguishable. No false
  completion from separately sampled status/log reads.
- Focused real-PostgreSQL API tests cover these behaviors and negative cases.

Evidence (2026-09-22): primary integration review completed.
- `Store.ReadFeedback` reads status, cancellation and ordered log candidates in
  one PostgreSQL statement/MVCC snapshot, with tenant/project/build lineage.
  SQL transfers body text only for the bounded prefix; rune-aware clipping
  preserves valid UTF-8 within 65,536 content bytes. A truncated chunk consumes
  its sequence and defers subsequent chunks, including empty chunks.
- `/feedback` returns schema version 1, explicit terminality, continuation and
  page/chunk `truncated` flags. Unknown statuses and unrepresentable next
  sequences receive named 503 refusals. Existing full logs remain unchanged.
- `dotnet build src/Fogell.Controller.Api/Fogell.Controller.Api.fsproj
  --no-restore -v quiet` and the API test project build passed with no warnings
  or errors.
- Against dedicated real PostgreSQL, `dotnet run --project
  tests/Fogell.Controller.Api.Tests/Fogell.Controller.Api.Tests.fsproj
  --no-build -- --filter-test-list FG-263`: 5 passed, 0 ignored, failed or
  errored (four behavioral cases plus server teardown). Coverage includes live
  and terminal empty pages; terminal backlog; cancellation; count/byte bounds;
  three/four-byte Unicode clipping; oversized then empty/tiny chunks; complete
  logs retrieval; cursor/auth/lineage errors; committed/uncommitted evidence;
  known status vocabulary and unknown-status refusal.
- Initial `--filter FG-263` selected zero tests; the corrected test-list filter
  above selected and executed the new cases. No skipped database run is counted
  as validation.
- The combined Release run passed all 114 API-project tests with real
  PostgreSQL, and the [M1 campaign](../../evidence/20260922-feedback-loop/README.md)
  exercised this endpoint through the actual controller and worker.
  Repository-wide gate evidence is retained with that campaign. Publication
  and production readiness remain separate from this local ticket acceptance.
