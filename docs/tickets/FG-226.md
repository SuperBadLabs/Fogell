# FG-226 — Porting the gate's audit tools off babashka

Status: **PARTIAL**. The work is complete and the authoritative HeMan gate passes
on the exact committed head, with 932 tests plus every blocking proof and lane and
`GATE EXIT: 0`. Exact-head hosted review, CI and publication remain, which is what
keeps this short of DONE.

The gated head is the commit that contains this file, and the pull request
records it explicitly. It is NOT copied into this paragraph: an earlier version
named `724e68ae`, the head was amended four more times, and the SHA silently
stopped matching. An earlier fix then pointed readers at "the commit's own
message", which does not carry a SHA either — a pointer chain that closed on
nothing. A ticket file is the wrong place for a value that changes on every
amendment; the PR is the right one.

## Problem

Eight of the gate's audits and generators were babashka scripts, so a blocking
compliance gate depended on a Clojure runtime being installed on every host that
runs it. The repository's own scripting rule prefers a self-contained native
binary where one is available on a controlled box.

This is a TOOLCHAIN change and not a defect fix. It is class E: it changes no
engine behaviour and misleads nobody, which is why it is filed P3 despite its
size.

## What replaced what

`scripts/*.bb` — 2155 lines across eight tools — became nine F# scripts under
`scripts/fsx/` (2361 lines, of which 221 are the shared `prelude.fsx`), compiled
to native binaries in `scripts/bin/` by `scripts/build-audits.sh`.

| tool | what it does |
|---|---|
| `audit-board-numbers` | derives board accounting and compatibility tokens; blocking |
| `audit-claims` | every MEASURED comment must name a receipt; blocking |
| `audit-stale-refs` | comments naming a deleted F# binding; blocking |
| `generate-scorecard` | generates the ledger, scorecard and KNOWN-LIMITATIONS |
| `count-options` | corpus `options` directive census |
| `probe-input` | the pinned-lab measurement behind `input` semantics |
| `review-rounds` | per-review-round finding triage for a PR |
| `sync-scm-cases` | pushes SCM-marked cases to the fixture repo |

`fflat` is one file per binary, so the eight tools cannot share a module the way
a library would. `#load "prelude.fsx"` is the seam that keeps one definition of
the shared helpers instead of eight copies that drift.

## Why the binaries are not committed

**An fflat build is not reproducible.** The same source compiled twice differs by
six bytes in `.rodata` — an embedded per-build module GUID — and `fflat` exposes
no determinism flag (measured 2026-08-27, `fflat 2.1.3.0`).

That single fact settles the question. "Rebuild and compare hashes" is therefore
unavailable as a CI guard, so a committed binary could not be shown to correspond
to the source beside it. Edit an `.fsx`, forget to rebuild, commit both, and the
gate would run the OLD logic and go green — a fix indistinguishable from a no-op,
which is the FG-158 shape exactly, in the machinery that exists to catch it.

Building inside the run that consumes them makes the source-to-binary link true
by construction rather than by discipline. The cost is stated under MEASURED COST
below and is real.

The eight binaries total ~31.7 MB. Repository weight was NOT the deciding
argument and is recorded here so nobody re-derives it as one: git deltas them
well, and against a 160 MB repository the growth is noticeable over months rather
than prohibitive. The auditability argument is the load-bearing one.

## Verification: byte-identical first, optimised second

FOUR of the eight were proven byte-identical to their babashka originals BEFORE
any performance work, against the same inputs on the same tree, and a fifth
matches as an identical FINDING SET:

- `audit-board-numbers` — identical on the live board, and identical across all
  23 known-bad states in `prove-board-numbers.sh`;
- `audit-claims --strict` — identical across the whole F# tree;
- `generate-scorecard --check` — the ledger and the scorecard regenerate
  byte-for-byte;
- `review-rounds` — identical on a real five-round pull request;
- `audit-stale-refs` — identical finding SET and identical counts, but NOT
  byte-identical: on a base where its ordering deviation can express itself
  (`HEAD~90`, 9 hits; `HEAD~110`, 44 hits) the raw output differs by order. The
  first two comparisons used bases yielding 0 and 1 hits, where the deviation is
  unobservable, and this section called it byte-identical until the third
  verifier round measured it.

THE OTHER THREE CARRY WEAKER EVIDENCE, named rather than folded into the claim:

- `count-options` — multiset-identical, deliberately reordered (see deviations),
  so it is NOT byte-identical and must not be described as such;
- `sync-scm-cases` — compile-verified only: exercising it pushes to the fixture
  remote, and this ticket did not license that;
- `probe-input` — compile-verified, plus an AOT smoke test of its HTTP path
  (status, crumb parsing, `Set-Cookie` jar) against a local server. It was never
  compared against the babashka original, which needs the pinned lab.

An earlier version of this section said "every tool" was byte-identical and then
listed five. The pre-push verifier counted.

## Three defects the comparison caught

These are the argument for proving equivalence by RUNNING both rather than by
reading the two programs side by side. Each would have changed a verdict without
changing a visible character.

1. **`str/blank?` on a non-breaking space.** Java's `Character.isWhitespace`
   excludes U+00A0, U+2007 and U+202F on the grounds that they are not breaks;
   .NET's `Char.IsWhiteSpace` includes all three, and .NET also counts U+0085
   NEL where Java does not. The naive spelling flips `blank?` on any of them.
   **THE EXPOSURE IS LATENT.** This file said "the execution board contains many
   NBSP"; the verifier counted ZERO in the board and zero in the tracked tree.
   The fix is right, the evidence cited for it was invented.
2. **Line-based process capture appends a newline the child never wrote.** The
   event-based reader hands back lines with terminators stripped, so
   reassembling them fabricates a trailing newline. `sync-scm-cases` compares
   captured `git show` output against a case body byte for byte to decide
   whether to push; under that spelling every body lacking a final newline
   compares unequal and the sync pushes on every run — the sealed-sha churn
   that tool exists to prevent.
3. **`\Q...\E` does not exist in .NET.** Both large audits quote citation names
   with it. Copied across unchanged, .NET reads those four characters literally,
   no citation ever matches, and `audit-claims` becomes a no-op that passes
   everything. `Regex.Escape` is the equivalent and is used at both sites.

`javaRx` in the prelude rewrites Java's ASCII `\s`, `\d` and `\w` explicitly,
because .NET's are Unicode-aware and a pattern copied across unchanged matches a
different set of lines.

## Three deliberate deviations

None moves a count or changes membership; each is stated in the source that
performs it. The heading said TWO until the pre-push verifier found the third.

- **Equal-count tie order.** Clojure's `group-by` returns a hash map above eight
  keys, so rows with equal counts came out in hash-bucket order — an accident of
  a hash implementation, not a decision. Ties are now broken by name.
  `KNOWN-LIMITATIONS.md` regenerates with 43 lines reordered, an identical
  multiset; `count-options` reorders its count-1 directives and the count-14 pair
  (`timeout`/`timestamps`).
- **Report order in `audit-stale-refs`.** The original walked the tree in
  filesystem order, making the ORDER of its report host-dependent. Files and
  identifiers are now ordinally sorted.
- **Glob order, prelude-wide.** `prelude.fsx`'s `glob` sorts ordinally where
  `babashka.fs/glob` walked in filesystem order. This is a THIRD deviation and
  the section claimed there were two; it affects every caller, and in
  `sync-scm-cases` it changes the order in which branches are pushed to the
  fixture remote — in the one tool never executed. Found by the pre-push
  verifier. It changes order only, never which branches move.

## Four further defects the VERIFIER caught

The three above were caught by comparing engines. These three survived that
comparison and were caught by the pre-push verifier, because they are latent —
no input in this tree exercises them, so equivalence held while the semantics
were wrong. All three are in the SHARED prelude, so each affected all eight
tools.

1. **`javaTrim` implemented the wrong function.** `clojure.string/trim` trims by
   `Character/isWhitespace`, NOT by `java.lang.String.trim`. The comment asserted
   `String.trim` and the code followed it, so em space (U+2003) and ideographic
   space (U+3000) survived a trim Clojure removes. Measured against babashka:
   `trim "\u2003x\u2003"` gave `8195,120,8195` against Clojure's `120`.
2. **`javaIsWhitespace` counted U+0085 NEL.** Java's list excludes it as a
   control character; .NET includes it, and the non-breaking-space guard did not
   cover it. `blank?` disagreed with babashka on that code point.
3. **The `\s` rewrite dropped VERTICAL TAB.** The file's own header states Java's
   `\s` is `[ \t\n\x0B\f\r]`; the code emitted `[ \t\n\f\r]`. Every pattern
   built through `javaPattern` was silently narrower than its original.
4. **`cljSplit` was not `clojure.string/split`**, three ways: `Regex.Split`
   interleaves captured groups where `Pattern.split` discards them, .NET emits a
   leading empty on a zero-width match at position 0 where Java suppresses it,
   and the two disagree on empty input. Its two pinned fixtures passed under
   either semantics — the same decoration failure as `trim`, one function below
   it. It had ZERO production callers and is DELETED rather than fixed. Found
   when the verifier was asked to assume a fourth divergence existed.

**THE PROOF COULD NOT HAVE CAUGHT ANY OF THEM.** Its two trim fixtures pass
under either candidate semantics, which is the "decoration, not proof" failure
this repository names. Four rows and three mutations were added; each is proven to fail.

**THE EXHAUSTIVE CHECK IS WHAT ACTUALLY CONFIRMS THESE.** Re-running both
engines on the live tree cannot: the tree contains ZERO of the divergent code
points, so both engines agree whether the fix is right or wrong, and that run
only shows nothing else broke. The pre-push verifier instead dumped
`Character.isWhitespace`, `\s`, `\S`, `\d`, `\D`, `\w` and `\W` from babashka
over all 65 536 UTF-16 code units and diffed them against the compiled prelude:
identical across every one. That is the evidence for the character-class claims;
the head-to-head runs are evidence only for the absence of regressions.

**THAT DIFFERENTIAL IS NOW GATED, NOT REMEMBERED.** Citing it while nothing in
the repository reproduced it made it exactly the shape FG-104 refuses — a claim
nobody can check. `prove-fsx-prelude.sh` now builds the same 65 536-row table
from the compiled prelude and compares its SHA256 against the digest derived
from babashka. Proven by reverting the U+0085 exclusion: one code point out of
65 536 turns the proof red.

**ITS FIRST VERSION WAS BLIND AT ITS OWN EDGE.** It emitted only `\s \S \d \D
\w \W`, every one of which takes `javaPattern`'s NON-CLASS branch, so the
in-class arms were exercised at two code points and in-class `\d` and `\w` at
none. The verifier removed vertical tab from the in-class `\s` arm alone: the
digest matched, all sixteen fixtures passed, and `[\s;]` had stopped matching
VT. The table now emits `[\s] [\d] [\w]` and the class-reset probe `[;]?[,]?\d`, and
four mutations — in-class `\s`, in-class `\d`, a never-resetting class tracker,
and a tracker that closes ONCE and never again — die against the DIGEST. The
probe carries TWO classes for the last of those: with one, only the first close
is exercised, and a close-once defect reproduced the digest, passed every
fixture, and still moved `audit-stale-refs` from 156 identifiers to 148 on a
real base. No standing mutation ARM covers them; saying
"both in-class mutations die" implied one did.
That is the same shape as the vertical-tab defect this file exists to prevent,
reproduced inside the check written to prevent it.

**TWO FURTHER FINDINGS WERE IN THE PROOF ITSELF**, and the second is the sharper
of the two. The vertical-tab mutation did not compile, its row was therefore
absent from the output, and the harness read an absent row as a changed one and
reported a KILL it never earned. `prove-stale-refs.sh` has carried a
compile-failure guard since it was written; this file did not.

The first fix was only half a guard. It keyed on the `COMPILE-FAILED` marker, so
a mutant that COMPILES and then CRASHES still printed no rows, and an absent row
still read as a kill. The verifier built exactly that mutant — a malformed regex
assembled at module initialisation — and drove it through the judging block to
produce a kill with an empty right-hand side. A kill now requires a row that is
PRESENT and DIFFERENT. Both paths are proven to fail by planting: an
uncompilable mutant and a compiling-but-crashing one, each as a one-off check
rather than a standing arm, which is the same standard `prove-stale-refs.sh`
holds itself to.

`stage_mutation` also ran raw `sed` where its sibling `replace_line_once`
refuses a non-unique target; it now requires a mutation to change exactly one
line, so a kill can be attributed to the rule under test.

## An eighth defect, found by Codex on the pull request

**`babashka.process/shell` ABORTS on a non-zero exit; `runIn` returns a record.**
Every ported call site that dropped that record turned an abort into a silent
success. Measured on the originals: `sync-scm-cases.bb` made nine shell calls of
which only two carried `:continue true`, and `review-rounds.bb` made two with
none — so a failed clone, push or `gh api` stopped the babashka script and did
not stop the port.

The visible consequences were fail-OPEN in both tools. `review-rounds` printed
`PR #N — 0 comments across 0 review(s)` on an authentication failure, which a
person triaging a pull request reads as "nothing to triage" — the FG-002d defect
that tool exists to prevent, reintroduced through its own error path.
`sync-scm-cases` printed `synced <branch>` for a branch whose push had been
rejected.

Codex raised it as two findings. It is one class, and auditing for the class
found EIGHT sites rather than two: six in `sync-scm-cases`, one in
`review-rounds`, one in `probe-input`. `runOrDie` in the prelude now mirrors
babashka's throwing default, and the two sites the original marked
`:continue true` keep a tolerant variant so a missing branch stays an ordinary
answer rather than a failure.

**WHY NEITHER THE EQUIVALENCE RUNS NOR SIX VERIFIER ROUNDS CAUGHT IT.** Every
comparison ran both engines on inputs where the subprocess SUCCEEDS, so both
printed the same thing and the divergence lived entirely in an error path
nothing exercised. It is the same blind spot as the latent character-class bugs,
in a different dimension: there, the inputs were absent; here, the failures were.
A third tool, `generate-scorecard`, was already correct — its original used
`:continue true` and the port checks the exit code explicitly.

## The proofs

- `prove-fsx-prelude.sh` (new) pins the Java string and regex semantics as
  constants derived from the babashka twin, so the gate needs no `bb` to check
  them. It is proven to fail under six planted divergences.
- `prove-stale-refs.sh` COMPILES each of its ten mutants rather than editing
  source text, because a native binary cannot be `sed`-ed. A mutant that fails to
  compile fails the proof rather than reading as a kill — verified by planting an
  uncompilable mutation and confirming the proof refuses.
- `prove-claim-citations.sh` needed only its path repointed; it copies the audit
  into a fixture repository rather than mutating it. The copy lands in
  `scripts/bin/` because the compiled tool derives the repository root as three
  parents from its own location, one deeper than the `.bb` it replaced.
- `gate.yml` installs `fflat` pinned to `2.1.3`, plus its documented
  `libc++-dev` prerequisite, in place of the pinned, checksummed babashka. A
  one-maintainer toolchain on the blocking path is a decision, not a default.
  **THE MITIGATION IS STRICTLY WEAKER THAN THE ONE IT REPLACED**, and this file
  claimed it was the same: the babashka step pinned a version AND verified a
  SHA256 of the downloaded tarball; `dotnet tool install --version` pins the
  version only, with no digest check. Restoring an equivalent guarantee would
  mean vendoring or hashing the nupkg.

## Measured cost

| step | babashka | fflat |
|---|---:|---:|
| `audit-stale-refs --strict` | 18 400 ms | 209 ms |
| `audit-claims --strict` | 3 640 ms | 102 ms |
| `prove-claim-citations.sh` | 210 ms | 92 ms |
| `prove-stale-refs.sh` | 2 919 ms | 13 594 ms |
| `build-audits.sh` | — | 12 971 ms |
| `prove-fsx-prelude.sh` | — | 6 623 ms |

Net gate cost is about **+8.6 s** for the steps above. THE TABLE OMITS THE
TOOLCHAIN INSTALL, which is the larger CI change: `fflat` is a **199 MB** nupkg
downloaded on every hosted run with no cache step configured, against
babashka's 24 MB tarball — roughly 8× the download, both measured by
`Content-Length`. It unpacks to **496 MB**; the 929 MB the install directory
reports is that plus 398 MB of retained nupkg copies plus a 35 MB `runtimes/`
tree — all three by `du -sm`, since mixing block-allocated with exact-byte
figures is what left the previous decomposition 1 MB short. An earlier version quoted 929 MB as the unpacked size, double-counting the
download; the version after it gave a decomposition that did not sum.
Windows and cross-architecture AOT libraries this repository never invokes are
~170 MB of the 496 MB extracted, about a THIRD — the same paragraph said over
half. Both figures were corrected by the pre-push verifier.
An `actions/cache` keyed on the exact fflat version now wires that up, so a
version bump is a cache miss by construction and no stale toolchain can be
served. WHETHER IT ACTUALLY HELPS IS UNVERIFIED: restoring the 496 MB extracted
tree may or may not beat re-downloading the 199 MB nupkg, and GitHub's cache
throughput cannot be measured from HeMan. The first hosted run settles it; if
restore is slower, the step should be removed rather than tuned. The audits themselves are 36–88× faster; the gate pays for
compiling the tools and for the ten mutant builds. Compiles run in
parallel, capped at `nproc/3` because each `fflat` invocation saturates roughly
three cores — unbounded parallelism would be slower than sequential on a 4-core
hosted runner.

`prove-stale-refs.sh` is genuinely 4.7× SLOWER than the babashka original. Its
fixtures are tiny scratch repositories where `bb` was fast, and ten mutant
compiles is the price of proving a compiled checker fails.

## Boundary — what this does NOT claim

- It does not claim the ported tools are CORRECT, only that they agree with the
  programs they replace on the inputs measured. Both could be wrong together.
- It does not claim reproducibility. The opposite is measured and is the reason
  the binaries are built rather than committed. FG-080's byte-identical rebuild
  is a separate and unmet bar.
- It does not remove a toolchain dependency from the gate; it exchanges babashka
  for fflat/bflat, which is a lateral move on supply-chain risk chosen by the
  owner, not a reduction.
- Windows is untouched. The binaries are linux-x64 and the audits would need a
  per-platform build before FG-038a's runner could run them.
- `count-options` tie order differs from the babashka original by design, so its
  output is not byte-comparable against pre-FG-226 transcripts.
