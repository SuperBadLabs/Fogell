# Refuse unknown steps and unresolved libraries at preflight, before any effect

Priority: **P1**

Verb: **refuse** an unknown step or a dropped library reference before anything runs, so the author sees it first.

Status: **TODO**. Filed 2026-09-10 by the Track 4 re-cut (`adr/0009`).

## Demand

Not a corpus unlock; a class-A hazard wearing a class-D label. Today a
Declarative step the walker does not model reaches
`src/Fogell.Execution/Executor.fs` (`runStep`, the fall-through arm) at run
time and fails closed with `step 'X' is not implemented` — after every earlier
step in the build has already had its effect. Separately, a library reference
is discarded without a word: the Groovy parser's `annotationStmt`
(`src/Fogell.Groovy.Parser/Parser.fs`) lowers `@Library('x') _` to a
`library('x')` call statement, so the preamble parses and its `def` helpers ARE
extracted, but `preambleFuncs` in `WalkerOrchestration.fs` keeps only `SFunc`
entries and the lowered call is dropped. A preamble that does not parse at all
is refused at preflight as `unsupported_preamble_analysis` (`Fogell.fs`), so
that path is already loud; the lowered-and-dropped path is the silent one.
File counts: the `@Library` and `library` step rows of [FG-263](FG-263.md).

## Design

`preflightExecution` in `Fogell.fs` (the walker's preflight, beside the
`unsupported_agent` and `unsupported_tools` refusals) gains two passes that run
before workspace preparation:

1. Every step name in every `steps { }` and `post { }` block must be in
   `WalkerRules.stepDescriptors` or the hosted wrapper set, else
   `unsupported_step: <name>` with source position. `script { }` bodies stay
   dynamic; the interpreter's denial already names the call.
2. Every `library(...)` step in a `steps { }` block and every lowered
   `library(...)` call statement in the parsed preamble refuses
   `unsupported_shared_library` with position, until FG-269 replaces the
   refusal with resolution. The preamble scan must look at every top-level
   statement, not only `SFunc`, so a non-function statement Jenkins would run
   is refused by name rather than dropped.

New codes in `src/Fogell.Admission/Errors.fs`; `ErrorCode.isInputDefect`
classifies both as engine gaps, not input defects.

## Acceptance

A hand-written case whose second step is unknown leaves NO workspace effect
from its first step and refuses with the named code at preflight; a case with
`@Library('x') _` above a `def` helper refuses by name at preflight, where
today it runs with the reference dropped; a case with a non-function preamble
statement refuses by name. Mutation proof: removing either pass is killed by a
focused test.

## Jenkins probe first

Measure what Jenkins prints for an unknown step in a Declarative `steps { }`
(it is a compile-time refusal naming the step) so the engine's message is
compared, not guessed.
