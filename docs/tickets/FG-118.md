## Implemented contract

A tagged line captures whether its raw source carried a timestamp prefix before
decoration is stripped. That provenance remains attached to the same line
through replacements, canonicalization and every contextual suppression. The
new companion normalizer returns the text projection and `(stamped,total)` from
one final survivor list in one input enumeration; the existing text-only API is
preserved as a projection of that same result. Both Jenkins and Fogell consume
the companion result, so neither side recomputes a raw-line numerator or a
different denominator.

`Trace.timestampCountsValid` is the shared hostile-input rule:
`0 <= stamped <= total`. Valid coverage is `none` when stamped is zero, `all`
only on exact positive equality, and `partial` only strictly between them. An
invalid tuple contributes a named divergence for each engine, so invalid versus
valid and equally invalid sides cannot cancel into PROVEN. Invalid zero-stamped
tuples such as `(0,-1)` render explicitly as `INVALID` instead of disappearing
behind the old positive-stamped display gate.

Receipt verification accepts numeric `PARTIAL` only for `0 < stamped < total`
and numeric `all` only for a positive total. Recognized malformed, negative,
zero-denominator, equal-partial and over-count forms are unreadable. An unknown
lexical class follows the historical verifier contract by projecting to
`<unparseable>` and therefore failing by seal mismatch; it is not silently
changed into a different rejection category.
