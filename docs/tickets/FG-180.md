## Candidate contract

- An ordinary double-quoted named-argument key with constant text is decoded to
  `EStr`, matching the existing constant-name representation. Parenthesised and
  command-form calls use the same rule.
- Ordinary supported escapes share the value-string decoder. For example,
  `\t`, `\n`, `\r`, escaped quotes, and an escaped dollar become literal key
  text; the AST does not retain their source spelling.
- An unescaped `$` makes the key interpolated rather than constant. Such
  `EGString` keys remain refused; this slice does not silently freeze a computed
  key into text.
- Raw physical LF, CR, and CRLF inside an ordinary double-quoted key are
  refused. A backslash followed by a physical line break is also refused.
  Groovy accepts that line-continuation spelling, so this is a conservative,
  explicitly open false-refusal residual rather than a parity claim.
- Triple-double literal behavior is unchanged. The dedicated named-key parser
  does not broaden the general multiline string grammar or add triple-double
  named keys.
- Duplicate detection still runs on decoded names. A single-quoted and a
  double-quoted key that decode to the same text are rejected together, keeping
  the FG-174 duplicate-name boundary load-bearing.

Implementation is confined to
`src/Fogell.Groovy.Parser/Parser.fs`; focused coverage is in
`tests/Fogell.Groovy.Tests/Tests.fs`.
