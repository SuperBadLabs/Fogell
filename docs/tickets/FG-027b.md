# FG-027b — durable retry arbitration and aggregate reopening

Status: **PARTIAL**. This slice makes the persisted retry decision internally
consistent and executable. Parent FG-027 still requires runtime retryability
policy and scheduler/controller invocation.

## Closed invariant

`Store.DecideRetry` serializes on restore metadata and the immutable terminal
parent. The one fresh `ChildCreated` writer now locks and reopens the exact
parent node and build in the repository-wide attempt → node → build order,
then creates the queued child and immutable decision in the same transaction.
The parent remains terminal history. A failed child insert, lineage mismatch,
restore race, or publication failure rolls the entire transition back.

The aggregate transition is deliberately limited to a fresh child:

- `BudgetExhausted` leaves node/build terminal and records the exact durable
  dead-letter reason;
- replay validates and returns the original creation snapshot without changing
  a child or aggregate that has since advanced; and
- `cancellation_requested` is preserved. If cancellation authority is already
  present, execution consumes it and aborts the queued child before launch.

Migration `0011_retry_reopens_lineage.sql` is forward-only and checksum-pinned.
Its `BEFORE INSERT` trigger independently enforces the same aggregate invariant
for direct SQL and future call paths. The exact-once `retry.decided` event/outbox
payload now binds the build and carries `buildStatus: queued` for child creation,
making it the append-only compensation for the preceding `build.terminal`
publication. No terminal history is deleted or rewritten.

The migration also repairs pre-0011 queued/offered children whose aggregates
still carry their parent result. It enumerates every tenant under a temporary,
transaction-scoped lowering of forced RLS, restores the boundary before commit,
and appends one build-bound `build.reopened` event/outbox pair per repaired
decision. An aggregate outside the exact parent-result/queued repair domain is
left unchanged and remains ineligible for the FG-224 claimant; the migration
does not overwrite state that may be owned by a different live attempt.

`ClaimNextExecution` also requires the attempt, node, and build to all be
`queued`, preventing user code from launching through a partially updated or
administratively inconsistent aggregate.

## Proof surface

The live PostgreSQL suite proves:

- fresh Store creation commits a queued child, queued node, queued build, one
  immutable decision, one event, and one outbox record;
- cancellation after reopening is accepted, and `BeginExecution` returns
  `ExecutionCancelledBeforeStart` with an aborted child rather than launching
  user code;
- a direct SQL child/decision transaction is reopened by the database trigger
  and publishes the exact build-bound queued compensation;
- a `NOSUPERUSER NOBYPASSRLS` schema-owner upgrade repairs a pre-0011 decision
  across forced tenant RLS and emits exactly one repair publication;
- replay after the child reaches `running` returns the original queued creation
  snapshot without regressing the live aggregate;
- budget exhaustion leaves the terminal build closed to cancellation; and
- 16 concurrent writers still converge on one fresh result and 15 replays.

The focused retry list passes 15/15 and the complete Store suite passes 95/95 on
an isolated PostgreSQL 16 database. Authoritative full-gate and exact-head hosted
evidence are recorded in the external handoff because a commit cannot attest to
its own final identity.

## Deliberate boundary

There is no production caller that decides retry policy or schedules
`DecideRetry` yet. A cancellation request that completes while a build is
terminal, before a later independent retry decision begins, can therefore
return `AlreadyTerminal`; that answer is correct for the state it serialized
against. Removing the interval requires retry arbitration before terminal
exposure (or a durable pending-retry marker) in the FG-027 runtime integration.
This slice does not claim that broader policy or timing guarantee.
