## Measured, 2026-09-03

One transient pipeline job on the pinned Jenkins 2.568.1 lab (deleted after
the run) and the same Jenkinsfile through `Fogell.Run.Host` at `origin/main`
`2f2af43a`:

```groovy
stage('paren') {
    when { expression { return 'ab' ==~ /a)b|ab/ } }
    steps { echo 'paren-ran' }
}
stage('after') {
    steps { echo 'after-ran' }
}
```

Jenkins: the `when` expression throws
`java.util.regex.PatternSyntaxException: Unmatched closing ')' near index 0`
(`a)b|ab`), the stage does not run, `Stage "after" skipped due to earlier
failure(s)`, `Finished: FAILURE`. Fogell: `Stage "paren" skipped due to when
conditional`, `after-ran`, `completed: success`.

## Why

`src/Fogell.Groovy.Interpreter/Interpreter.fs`, the `=~`/`==~` arm (abridged;
the source spells the types out and computes the match in full):

```fsharp
try
    let re = Regex(p, RegexOptions.None, TimeSpan.FromMilliseconds 100.0)
    VBool(…)
with _ ->
    VBool false
```

Every failure of constructing or running the pattern — an invalid pattern
(.NET `RegexParseException`), and the 100 ms catastrophic-backtracking
timeout the comment says is the guard's purpose — becomes `false`. A
`when` expression that is `false` skips the stage; a `script { }` block
gets a wrong answer with no fault. Jenkins raises `PatternSyntaxException`
(by the JDK's class hierarchy an `IllegalArgumentException`, catchable by
`Exception` — unmeasured here) for the first and, by the JDK's documented
behaviour, has no timeout for the second.

## What would close it

Raise a `Thrown` value for an invalid pattern, so a `when` expression fails
the build and a `script { }` `catch (Exception)` intercepts it as on Jenkins
(measure the catch boundary and the message shape first); make the timeout a
refusal by name (`unsupported_regex_budget` or similar) rather than a wrong
`false`; then a differential case of the `when` shape sealed as a matching
FAILURE (the exception narration is not compared — measure what the
comparison excludes before claiming it) and a `script { }` catch case.

## Implemented boundary

`src/Fogell.Groovy.Interpreter/Interpreter.fs`: the `=~`/`==~` arm now
constructs the pattern outside the guarded match. A construction failure
(.NET `ArgumentException`, which `RegexParseException` derives from) raises
a new typed fault `RegexPatternInvalid of pattern * detail`; the `try`
statement intercepts it for `catch (Exception)`, `Throwable`,
`RuntimeException`, `IllegalArgumentException`, `PatternSyntaxException`
(bare or qualified) and an untyped `catch (e)`, binding the variable to
`java.util.regex.PatternSyntaxException: <detail>` — Jenkins' `${e}` shape,
class then message, with the HOST engine's diagnosis as the message (the
text is not Jenkins'; a case must not print it). `catch (ArithmeticException)`
lets it escape, as measured. Uncaught, it leaves the script as a fault: in a
`when { expression }` the gate becomes unanswerable and the walker's
existing fail-closed arm prints `ERROR: stage '…' has a `when` condition
this engine cannot evaluate` and fails the build; in a `script { }` step the
step fails with the fault as its reason. The 100 ms matching budget, which
Jenkins does not have, is now a named refusal
(`unsupported_regex_budget: …`) instead of `false`. Every other outcome of
the arm is unchanged.

Tests (`FG-241 invalid regex patterns fault instead of answering false`,
4/4; Fogell.Groovy 236/236): both operators fault with the pattern carried;
the four intercepting clauses catch and `ArithmeticException` does not; the
bound value starts `java.util.regex.PatternSyntaxException: ` and valid
patterns (including FG-140's `/a}b/`) still answer; the catastrophic
`(a+)+$` pattern refuses by name.

## Residuals and non-claims

- The caught value's MESSAGE is the .NET engine's diagnosis, not Jenkins'
  (`Invalid pattern 'a)b|ab' at offset 2. Too many )'s.` against
  `Unmatched closing ')' near index 0` plus two lines); only the class
  prefix matches. `e.class`, `e.message` and `e.getMessage()` on the bound
  value are not modelled here (Jenkins measured: class name and message).
- `catch (java.util.regex.PatternSyntaxException e)` — a QUALIFIED type in a
  catch clause — is a parse refusal on Fogell (`Expecting: ')'`), before and
  after; the bare spelling is accepted and the qualified one is listed in
  the intercepting set for when the parser admits it. Not filed: Groovy
  needs the import or the qualification, so a Jenkinsfile can only reach
  the bare spelling with an `import`, which this probe did not measure.
- Patterns the two engines disagree on VALIDITY for (Java accepts, .NET
  refuses, or the reverse) would fault here where Jenkins answers, or
  answer where Jenkins throws; none was measured, none is claimed.
- The uncaught `when` and `script` shapes are unsealed (FG-243).
