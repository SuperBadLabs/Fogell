# FG-213 — JUnit count accessors

Status: **DONE**.

## Bounded claim

This ticket covers only the four integer counts already carried by Fogell's
nominal `hudson.tasks.junit.TestResultSummary` projection. The candidate admits
the explicit zero-argument methods `getTotalCount()`, `getFailCount()`,
`getSkipCount()`, and `getPassCount()` on that nominal receiver. Each method and
its matching property returns the same `java.lang.Integer`-provenance value;
none is represented as Long. Total, fail, and skip also retain the exact
arithmetic/range surface their existing property spellings already exposed;
passCount arithmetic remains refused.

The four method names are globally visible to the interpreter's closed sandbox
only so this receiver can dispatch them. A free call, another receiver, any
positional or named argument, or a trailing closure remains a catch-opaque
refusal. `duration`, `getDuration()`, rendering, indexing, truthiness,
equality/identity, mutation, spread/reflection, hosted-step coercion, and new
arithmetic beyond the retained total/fail/skip surface remain outside the
ticket.

## Implementation

`Sandbox.junitSummaryCountGetters` is the single admitted-name set. Interpreter
dispatch accepts an exact getter only for `VJUnitSummary` with no positional or
named arguments and no trailing closure; a guard rejects every other use of a
name in that set. Total/fail/skip properties and getters return the explicit
`VArithmeticInteger` compatibility scalar: it proves Integer-not-Long but keeps
their former VInt unary, arithmetic, comparison, truthiness, and range behavior
and result types. PassCount property/getter returns strict `VInteger`, reusing
its established provenance and refusal boundary. Report parsing and execution
transport do not change.

Focused Groovy tests exercise positive and zero summaries directly at the
nominal-value seam, including getter/property parity, Integer-not-Long checks,
the retained arithmetic surface for all six total/fail/skip accessors, strict
passCount arithmetic refusal, and a denial matrix for every admitted getter
name. Focused differential tests exercise the same positive and matched-zero
report shapes through `junit` while retaining explicit refusal coverage for
`duration` and `getDuration()`. They also pin the compatibility scalar as a
typed `retry` count through representative property/getter reads and as
`Integer` in the Java type-name advisory. Broader numeric promotion, overflow,
and decimal semantics remain an FG-177 residual.
