## What the lane now proves

Scenario QF runs a pair whose pipelines differ only by `failFast true`. Neither
peer faults. Before the answer is written, the exact pending-marker inventory is
checked, the peer's one completed marker is used as a deterministic barrier, the
input step has one start and no finish, and the host remains live. After the
answer, the effects are exactly `peer` then `after`, once each, and the approval
inbox is empty.

The ordinary-parallel control has exactly one `input-decision` and zero
`input-prompt-cancellable` or `input-answer-provisional` records. The failFast
run has zero `input-decision` records, exactly one cancellable-prompt record and
exactly one provisional-answer record. The cancellable record must precede the
provisional answer. This paired control prevents a blanket rule that makes every
parallel prompt provisional from satisfying the lane.

The existing deadline scenario Q proves that a provisional answer is usable in
the attempt that read it and is not actionable from its reconstructed crash
state. QF adds the missing failFast-capability classification before a sibling
has faulted; it does not silently widen Q into a claim about a different run.

## Evidence boundary

This is a Fogell-host regression lane. It does not compare the behavior with a
live Jenkins controller, change engine source, or establish general scheduling
or cross-process interleaving equivalence. QF does not itself replay its
failFast-classified answer after a crash, and it does not exercise the separate
race in which a sibling actually faults while the human answer is being
published. Those nonclaims are why the local package remains PARTIAL.
