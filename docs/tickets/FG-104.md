# FG-104 — **Comment-as-specification drift.** A doc comment that describes behaviour must be covered by a test or receipt, or say it is unimplemented

**Status:** **DONE**  ·  **Priority:** P1

Archived from the execution board on 2026-08-02. The board carries the
outcome; this file carries the reasoning, which is what a future reader
needs and what a planning table cannot hold.

---

Three times a comment of mine became the specification the code disagreed with — `resolveName` promising `env['X']`, a case comment asserting Jenkins does not mask usernames (a reviewer cited it and was wrong because I was), and `#0` provenance documented but never produced. **Half done: the rule is now MECHANICAL.** `scripts/bin/audit-claims` scans every F# file under `src/`, `tools/` and `tests/` for a comment asserting MEASURED behaviour and reports any that names no existing receipt — because a claim nobody can check is not evidence. It found **30**, none of which cites the receipt that proves it, so today a reader must hunt and drift cannot be detected. Wired into `build-and-test.sh` as ADVISORY: making it blocking now would fail every build on a pre-existing backlog. Its FIRST review found the script's own scope narrower than its description — it globbed only `src/`, hiding four more claims — which is the exact defect it exists to catch, in the script that catches it. **Both halves done.** All 30 resolved: 23 now cite the receipt that proves them, and **6 admit UNPROVEN** — every one of the same kind, a Jenkins REJECTION, where a receipt would require both engines to fail and only their narration to differ, so forcing one to PROVEN would mean pattern-matching a compiler's error layout. The seventh is `post`'s `fixed`/`regression`, proven only for build #1 because the harness cannot produce build history (FG-110/FG-049b). The check is now **`--strict` and blocking**, verified both ways: a planted unbacked claim exits 1, a clean tree exits 0. An admission is a valid answer and is counted separately so it stays visible rather than quietly passing. **Known limit, recorded in the script itself:** it verifies a receipt is NAMED, never that the named receipt EXERCISES the claim — its first review found three of my own citations pointing at receipts covering only part of their sentence. The check is a floor, not a ceiling. Across two review rounds it accepted **six** wrong citations of mine — receipts that emit no output cited for a masking claim, a file-writing case cited for a stdout claim, an accepted-forms case cited for a rejection. Every one was settled in seconds by OPENING the receipt, which is the step I kept skipping: I was citing from memory of what a case was called rather than from what it contains.
