# FG-308 — Schedule paired backups and retention

**Wave:** W3 · **Priority:** P0 · **State:** Blocked on FG-315 · **Depends on:** FG-315

Define an unattended maintenance schedule for matching PostgreSQL and complete
state-root recovery points, with recorded hashes and age. Keep writers quiesced
for a paired point as required by the recovery runbook. Only then schedule the
bounded retention sweep for explicitly selected organizations. Retention has no
dry run and may leave `Pending` work or a held journal; never treat exit 0 as
proof that all cleanup finished.

**Done when:** a staged schedule produces multiple verifiable recovery points
at an interval consistent with the 24-hour RPO; a restore of a selected point
is checked in disposable destinations; retention catches up without touching
active/uncertain work; and held or incomplete sweeps are surfaced to operators.

**Local slice 2026-09-29:** `eafebe8a` added a paired backup/check helper. A
synthetic state root and disposable PostgreSQL 16 database produced a point
with schema `0017`; its database archive restored into a fresh disposable
database, which was removed after verification. The
[partial operations report](../../reports/native-operations-progress-2026-09-29/REPORT.md)
records hashes and remaining gates. The staged schedule, multiple points,
application restore, and retention catch-up remain its exit criteria.

**Reprioritized 2026-09-29:** the helper is ready for an operator-verified
quiesced point, but no supported admission/drain/host extinction contract exists
for an unattended timer. [FG-315](FG-315.md) owns that prerequisite. FG-308 is
blocked until it is qualified; no timer will assert quiescence based only on a
service stop or an arbitrary shell hook.
