## Why

Both parsers ended their escape decoder in a catch-all. The scripted
parser's letter map was a five-arm `function` ending in `| c -> c`, and its
`escaped` parser tried the two continuation spellings, then `numericEscape`,
then `anyChar` through that map, so any backslash spelling at all produced
the bare character. The Declarative lexer's `decodedEscape` chained
`numericEscape`, the one-spelling `\8` refusal FG-126a added, and the same
catch-all over its own copy of the letter map; so `\8` alone was refused
and `\9`, `\/`, `\q` and every other spelling became the bare character.
The letter map existed twice, the drift FG-122 spent a branch deleting once
already.

## Implemented boundary

- `src/Fogell.Admission/Errors.fs`: a new `GroovyEscapes` module holds the
  ONE definition both parsers read — `simpleLetters` (the nine measured
  letters), `simpleEscape` (the control-character map) and
  `invalidMessage`, whose `\8`/`\9` sentence is FG-126a's, pinned by its
  receipt `compile-refusal-invalid-eight` and tests, with `\u` and every
  other spelling worded to name the accepted set.
- `src/Fogell.Pipeline.Parser/Lexeme.fs`: `decodedEscape` is numeric
  decoding, then the letter set, then `invalidEscape`, which calls the
  existing `refuse` so the raw-argument fallback cannot re-admit the
  source. A numeric escape that decodes to the NUL/SOH provenance markers
  (`\0`, `\00`, `\000`, `\1`, `\01`, `\001`, `\u0000`, `\u0001`), which
  `numericEscape` declines, used to fall to the catch-all and silently
  produce `000X`; the digits are re-read without the sentinel check so the
  case refuses by name citing FG-127 — loud where that was silent, and
  still not a claim that the valid escape is supported (the verifier found
  the first cut wording `\u0000` as a malformed `\u`).
- `src/Fogell.Groovy.Parser/Parser.fs`: the state record gains a `Refusal`
  ref cell and a `refuse` mirroring the lexer's, read by `parseWithLimits`
  after the scalar refusal on both the success and failure arms, so the
  first positioned refusal survives every statement-alternative rewind;
  `escaped` and the constant-name form `escapedWithoutPhysicalBreak` use
  the shared letter set and refuse the rest (the narrow form still fails
  closed on a backslash-newline without an escape diagnostic). The
  Declarative parser's nested-syntax route carries the diagnostic for
  `script { }` and `when { expression { } }` bodies unchanged.
- `src/Fogell.Pipeline.Parser/Parser.fs`, the raw-argument scanner (Codex
  on PR #410): a quoted literal that is only PART of a step argument —
  `sh 'ok ' + '[\q]'` — is skipped by `skipEscapedCharacter`, never decoded,
  so it was admitted and failed only when the step ran, after earlier steps
  had produced effects (measured: `early.txt` written, then the build
  failed; Jenkins refuses the file). The skip now classifies the spelling
  with the shared grammar and records the same positioned refusal; the
  skip itself is unchanged so `\"` still cannot close its literal.
- Slashy strings on both parsers are untouched: delimiter escape only.

  backslash or a newline, and `\u` inside slashy strings.
- Dollar-slashy strings `$/…/$`: measured above for completeness; the
  scripted parser does not admit the form at all (a parse refusal), which
  is FG-014's territory, not an escape question.

  (FG-250, found while writing the executed case; the verifier then showed
  it refuses one corpus file today); the case escapes those quotes as `\"`
  on both stages so the two parsers see the same bytes.
- The malformed-unicode refusal envelope Jenkins prints without a
  `WorkflowScript:` line is not one the harness classifies as a refusal;
  no receipt claims that shape.
- A backslash inside a `${…}` placeholder of a Declarative GString (FG-252,
  from Codex on PR #412): the Declarative consumers and the raw-argument
  scanner run the outer literal's escape rule over placeholder CODE, so
  `echo "R: ${/\s/}"` is refused here where Jenkins prints `R: \s` — and
  where the previous head printed `R: s`, a silently wrong value. Zero
  corpus placeholders carry a backslash.
