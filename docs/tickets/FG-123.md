# FG-123 — Two exotic `ansiColor` argument forms are mishandled

Status: **PARTIAL — the evaluated-argument shape is measured, fixed, tested and
receipted; the trailing-closure shape landed earlier as FG-123a; exact-head
hosted gate and review coverage are outstanding** (P3). Raised on PR #35 after
CI and the verifier had both gone green, and deferred on measured risk: all
four corpus uses of the option are plain `ansiColor('xterm')`.

## The two shapes

- **(a) An evaluated argument.** `ansiColor("${'xterm'}")` was copied from the
  parser's UNEVALUATED source into `TERM`, where Jenkins evaluates it first.
- **(b) A trailing closure.** `ansiColor('xterm') { ... }` was accepted because
  the validation checked positional and named arguments but not the block;
  Jenkins rejects an option carrying a closure.

Shape (b) was closed by **FG-123a**, signed commit
`d1e94b97…` ("FG-123a reject ansiColor trailing blocks"), which reached `main`
inside PR #148 (FG-224, merged 2026-08-27T03:55Z as `20d4b638`):
`rejectInvalidAnsiColor` in `src/Fogell.Differential/Fogell.fs` refuses a
duplicate declaration, then any trailing block (empty and trivia-only bodies
included), then a bad arity, with one production-owned diagnostic per case,
before any stage, post or checkout effect; the `FG-123a ansiColor trailing
closure` test list pins the precedence, the positional/named/brace-text
controls, and the SCM path. That commit was never accounted on this row; this
ticket accounts it.

## Shape (a), measured

Transient pipeline jobs on the pinned Jenkins 2.568.1 lab (luigi, 2026-09-02,
created and deleted through the REST API), each `options { ansiColor(<arg>) }`
over `sh 'echo "TERM=[$TERM]"'`; the Fogell column is the pre-fix Release
build under `Fogell.Run.Host`:

| argument | Jenkins | Fogell before this ticket |
|---|---|---|
| `"${'xterm'}"` | `TERM=[xterm]`, SUCCESS | `TERM=[${'xterm'}]`, success |
| `"xterm"` | `TERM=[xterm]`, SUCCESS | `TERM=[xterm]`, success |
| `"${env.JOB_NAME}"` | `TERM=[<job name>]`, SUCCESS | `TERM=[${env.JOB_NAME}]`, success |
| `'xt' + 'erm'` | `TERM=[xterm]`, SUCCESS | `TERM=[xt' + 'erm]`, success |
| `"${env.MAPNAME}"` with `environment { MAPNAME = 'xterm' }` | `TERM=[null]`, SUCCESS | `TERM=[${env.MAPNAME}]`, success |
| `"${env.NOPE}"` | `TERM=[null]`, SUCCESS | `TERM=[${env.NOPE}]`, success |
| `"${NOPE}"` | `groovy.lang.MissingPropertyException: No such property: NOPE`, FAILURE | `TERM=[${NOPE}]`, success |
| `"${MAPNAME}"` with the declaration above | the same exception, FAILURE | `TERM=[${MAPNAME}]`, success |

Jenkins evaluates the argument — a GString placeholder, an environment read
and an unquoted expression alike — before setting `TERM`, and it evaluates it
BEFORE the `environment` block applies: a declared variable read through
`env.` is `null` there, exactly as an unknown one is, while a bare unknown
name fails the build. Fogell reported success with the wrong bytes in five of
the eight shapes (the plain double-quoted string was already right) and a
false success against a Jenkins failure in the other two, which is ADR 0001's
worst outcome and makes this **class A**, not the P3
hygiene it was filed as. (The fourth row's `xt' + 'erm` is the old code's
quote-trim applied to the expression's source text.)

## Implemented boundary

In `src/Fogell.Differential/Fogell.fs`, beside FG-123a's shape refusals and
AHEAD of the SCM block, so the judgement precedes any checkout:

- the argument is rendered through `GString.render`, the same strict entry
  point every step argument uses, so the literal / GString / expression
  distinction is made once, by `GString.kindOf`, and not re-derived here. The
  key is `#0` for the positional spelling and `colorMapName` for the named one.
- the environment the renderer sees is the Jenkins-provided baseline ONLY
  (`BUILD_NUMBER`, `JOB_NAME`, `WORKSPACE`, the FG-222 PATH/HOME baseline and
  their siblings). A declared `environment { }` value is not visible, which
  is the measured Jenkins order; `env.<unknown>` renders the text `null`,
  which is the measured step-argument rule (receipt `gstring-env-missing-null`)
  and, as measured above, the option's rule too. The SCM wrapper values are
  not visible either (see residuals).
- a placeholder the renderer cannot resolve (`MissingProperty`, a bare
  unknown name) or evaluate (`UnsupportedExpression`) is refused by name —
  `ERROR: pipeline declares an unusable ansiColor option: the
  ansiColor(<colorMapName>) argument …` — through the same compile-shaped
  refusal path as FG-123a's, before any stage, post or checkout effect.
  Of those, only the bare unknown name is measured on Jenkins (it fails with
  `MissingPropertyException`, so the terminal result matches and the wording
  is Fogell's own, not claimed); what Jenkins does with an expression the
  sandboxed evaluator here declines — `${new Date().year}`, a whitelisted
  method call, a `currentBuild` or `params` read — is UNMEASURED, and the
  refusal there is the fail-closed direction, not a parity claim.
- the old `.Trim().Trim('\'', '"')` is gone: the parser already stores the
  plain value for a quoted argument, and trimming quotes off an EXPRESSION's
  source text is how `'xt' + 'erm'` became `xt' + 'erm`.

The first cut of this change rendered over the Jenkins-provided AND SCM
wrapper values and therefore sat after the SCM block; the pre-push verifier
measured an SCM-defined pipeline narrating its checkout and leaving the
Jenkinsfile in the workspace before the refusal. The render moved ahead of
the block, and a test now pins the SCM path.

Tests, in `tests/Fogell.Differential.Tests` (`FG-123a ansiColor trailing
closure`, 9/9): the TERM control table gains five evaluated rows — a GString
literal, `env.JOB_NAME` (renders the host's job name), the named spelling
with a suffix, the concatenation expression, and `env.NOPE` rendering
`null`; a declared `MAPNAME` read through `env.MAPNAME` renders `null`; an
unknown name, an unterminated placeholder and an unknown name in the named
spelling refuse before every effect; and the same unknown name on an
SCM-defined pipeline refuses before the checkout, with empty output and an
empty workspace. The full project passes 340/340.

Receipts, sealed tier-1 PROVEN on the pinned lab (2026-09-02, 6 of 6
including the pre-existing control, same result, output and workspace hash
on both engines): `options-ansicolor` (control), `options-ansicolor-gstring`
(`"${'xterm'}"`), `options-ansicolor-env` (`"${env.JOB_NAME}"` — the harness
gives both engines the same job name), `options-ansicolor-expression`
(`'xt' + 'erm'`), `options-ansicolor-declared-env` (`env.MAPNAME` over a
declared `MAPNAME`, `null`) and `options-ansicolor-env-unknown`
(`env.NOPE`, `null`). All 292 receipt seals verify; the generated scorecard
moves from 286 of 286 to 291 of 291 expected cases. The control receipt was
regenerated with the current contract prose (the FG-118 and FG-234 wording)
and an unchanged seal and verdict.

## Residuals and non-claims

- **The SCM wrapper values (`GIT_COMMIT`, `GIT_BRANCH`, …) are not visible to
  the option argument, and what Jenkins gives an option that reads them is
  UNMEASURED.** On Jenkins the checkout runs inside the option's wrapper, so
  they are not expected to exist when the argument is evaluated; on Fogell a
  bare `${GIT_COMMIT}` refuses and `${env.GIT_COMMIT}` renders `null`. A
  receipt on an SCM case would settle it.
- **The refusal wording is not compared.** Jenkins fails an unresolvable bare
  name with a Groovy `MissingPropertyException` where Fogell refuses by name
  before any effect; the terminal result matches and a receipt for that shape
  is not claimed (FG-129: a refusal seals no output evidence).
- **Whitespace, numeric and `null` arguments are unmeasured.** `"  xterm "`
  now renders with its spaces (the old trim is gone), `42` renders as `42`
  and `null` as `null`; none of these is measured on Jenkins or claimed.
- **Stage-level `options { ansiColor(...) }` is refused as before**, by the
  FG-053 rule that reads the option only from `pipeline.Options`.
- **The corpus is untouched**: its four `ansiColor` uses are the plain literal
  spelling; this is correctness on measured shapes, not corpus recovery.
- **Only `ansiColor` renders its argument this way.** `timeout`'s `time`/`unit`
  and the other valued options keep their existing readers; whether Jenkins
  evaluates GStrings in those is outside this ticket.
- **Pre-existing, found by the verifier while probing this change:** the
  parser's expression marker test (`esc.StartsWith "\u0001"`) is
  culture-sensitive; production pins `InvariantGlobalization`, so it is inert
  there, but under ICU (a bare `dotnet fsi`) every argument classifies as an
  expression. Not this ticket.
