# FG-251 — Bind the global API bearer to one secure token-file descriptor

Priority: **P1**

Status: **DONE**. Signed source head
`bfe9db1807944e6f066aa7512e1a1963b32bde9a` passed the full exact-head HeMan
gate, both independent Codex review lanes, and hosted gate run `33932226683`,
then merged through protected PR #416 as

## Defect

Controller startup accepted any absolute path for `FOGELL_API_TOKEN_FILE` that
`File.Exists` recognized, then reopened that pathname with `File.ReadAllText`.
It did not reject a final symlink, verify that the opened object was a regular
file owned by the effective service identity, enforce the documented `0400` or
`0600` mode, or bound the number of bytes read. Validation and use were also
separate pathname operations, so replacing the entry between them could select
different bytes.

This file contains the one global operator bearer. Disclosure grants every API
operation the controller exposes; a FIFO could hold startup indefinitely, and
an oversized file could consume unbounded startup memory. The runbook and
threat model previously placed all of these checks on the deployer rather than
the process.

## Acceptance boundary

On Linux, startup must:

- open the configured absolute path once with `O_NOFOLLOW`, `O_NONBLOCK`, and
  `O_CLOEXEC`, using the architecture-correct no-follow flag table;
- classify that descriptor with `statx(AT_EMPTY_PATH)`, requiring a regular
  file owned by the effective service uid with exact mode `0400` or `0600`;
- reject metadata that the kernel did not return and files over 4096 bytes;
- read at most 4097 bytes through that same descriptor, so growth after the
  metadata sample cannot turn the size check into an unbounded read; and
- keep the existing trailing-CR/LF and 32-non-padded-character content rules.

Every failure is a stable configuration refusal. A non-Linux host or an
architecture without a tabulated `O_NOFOLLOW` value refuses rather than opening
with a guessed flag.

## Candidate and proof

`ControllerConfig.readTokenFileSecurelyWith` performs one `open(2)`, invokes
test-only post-open and post-metadata seams, obtains type/uid/mode/size from
that descriptor, and constructs the reader from the owning `SafeFileHandle`.
The kernel's fixed-size `statx` record avoids the architecture-dependent layout
of legacy `struct stat`.

Focused test list `FG-251 descriptor-bound API token file` proves:

- service-owned regular files at `0400` and `0600` are accepted;
- production startup selects the secure reader, and the configuration loader
  consumes the descriptor result without reopening the pathname;
- every individual execute, group, other, set-id, and sticky bit is refused;
- a final symlink, directory, FIFO, and 4097-byte file are refused, with the
  FIFO proved to return within two seconds and a blocked mutant reaped;
- malformed UTF-8 and a UTF-16 BOM are refused rather than normalized;
- per-architecture no-follow flags, `stx_uid` extraction, incomplete kernel
  metadata, wrong-owner metadata, and special modes are discriminated without
  privileged tests;
- the opened descriptor is close-on-exec, and replacing the pathname with an
  insecure file leaves the original inode as the only source of metadata and
  token bytes; and
- growing the opened inode after metadata validation is still bounded.

The focused list passed 8/8 on HeMan. On the exact signed source head, the
complete project suite passed 1,133 tests: 47 Controller API, 373 Differential,
41 Domain, 161 Execution, 243 Groovy, 31 Journal, 141 Pipeline Parser, and 96
Store tests. The complete gate also passed every blocking mutation, evidence,
live Jenkins denial/environment, compatibility, seal, restart, and approval
lane; all 228 corpus files retained their accepted set (200/200), and all 316
receipts resealed.

The blocking `scripts/prove-fg251-token-file.sh` lane copies the exact candidate
to scratch, establishes the green baseline, then compiles and kills hostile
mutants for an x86-only no-follow flag, incomplete and wrongly mapped `statx`
metadata, loader and stream pathname reopens, blocking/inheritable descriptors,
permissive special modes, replacement decoding, and loss of the extra growth
byte. The proof passed locally before the full candidate gate.

## Limits stated

This closes startup's final-component, metadata, descriptor-substitution, and
bounded-read checks. It does not isolate a pipeline running as the same uid
from a file that uid can read, prevent the owner from modifying the already
opened inode in place, validate every ancestor component, implement token
rotation, create tenant principals/RBAC, or prove TLS deployment. Those remain
deployment and architecture boundaries in `docs/THREAT_MODEL.md`.
