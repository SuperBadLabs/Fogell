# The `docker` global inside `script { }`: `build`, `image`, `inside`

Priority: **P2**

Verb: **build** and **use** a container image from a script.

Status: **TODO**. Filed 2026-09-10 by the Track 4 re-cut (`adr/0009`). Depends
on FG-273 for the launcher and on FG-263 for its count.

## Demand

The `docker.` global row of [FG-263](FG-263.md)'s table (`docker.build(...)`,
`docker.image(...).inside { }`, `docker.withRegistry`; a substring count of 74
for the word `docker` was withdrawn the same day). The row depends on FG-273
for the launcher.

## Design

- `Value.fs` gains `VDockerImage` (nominal); `docker.build(tag, ctx)` runs a
  local build with no egress, `docker.image(x)` names a pre-loaded image, and
  `.inside { }` becomes a hosted wrapper in `WalkerRules.scriptWrappersWithHostedBody`
  that switches the launcher for its body (FG-273's container arm).
- `.push()`, `.pull()`, `withRegistry`, `withTool` refuse by name under the
  fence and in general until a registry story exists.

## Acceptance

A tier-1 receipt for a corpus file using `docker.image(...).inside { sh … }`
with the image pinned on both engines; a hand-written case per refused member.

## Jenkins probe first

Measure on luigi: the console lines for `docker.build` and `.inside`
(`docker build -t …`, `docker run …`) and the return value of `docker.build`
as seen by a following `.inside`.
