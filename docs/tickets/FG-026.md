## Closed Store contract

`Store.PrepareEffect`, `Store.AdvanceEffect`,
`Store.MarkStaleEffectsUncertain`, and `Store.ListUncertainEffects` implement a
tenant-scoped four-state ledger:

- `prepared`, `applied`, `confirmed`, and terminal `uncertain` are the only
  states, with ordered transitions and exact replay;
- the key binds organization, attempt, and caller-supplied effect identity;
- SHA-256 binds the exact payload bytes while the ledger stores no payload;
- attempt owner, fence, unexpired lease, restore epoch, and state authorize
  preparation and advancement;
- changed payload, stale authority, illegal transitions, and direct-SQL state
  bypass are refused; and
- stale prepared/applied rows can be atomically marked uncertain, and the
  listing API selects one organization. The complete restricted-runtime Store
  suite separately proves the table is hidden without context and isolated by
  its forced-RLS policy.

The executable boundary is deliberately narrow:

- `src/Fogell.Store/Store.fs`
- `src/Fogell.Store/migrations/0003_effect_checkpoints.sql`
- `src/Fogell.Store/migrations/0005_forced_tenant_rls.sql`
- `src/Fogell.Store/migrations/0007_canonical_effect_key_check.sql`
- `tests/Fogell.Store.Tests/Tests.fs`
- `scripts/prove-fg026-effect-ledger.sh`
- the blocking invocation in `scripts/build-and-test.sh`

## Hard non-claims

No production runtime or connector currently calls `PrepareEffect`,
`AdvanceEffect`, or `MarkStaleEffectsUncertain`. This ticket therefore does not
claim universal external-effect safety, destination exactly-once behavior,
automatic stale-effect reconciliation, or safe automatic replay of ambiguous
prepared/applied work. FG-026b owns those runtime and crash-window obligations.
