# FG-229 — Fail-closed test-project inventory

Status: **PARTIAL** (P1). The source candidate closes the local false-green;
exact-head publication, hosted gate, review coverage, and protected merge remain.

## Defect

The authoritative `scripts/build-and-test.sh` gate enumerated only
`tests/<directory>/<directory>.fsproj`. A tracked project with a different file
name, at the root of `tests`, or below another directory was still part of the
solution and dependency-lock graph, but the gate silently skipped its tests.
The evidence sealer had a stronger recursive Git inventory, so a local gate and
a sealed candidate could also describe different test populations.

The old summary check accepted the last line containing `EXPECTO!` whenever the
process exited zero. It did not require a positive test count, zero failures and
errors, one summary, or Expecto's success terminator.

## Implemented boundary

`scripts/run-project-tests.sh` now owns one recursive, NUL-delimited inventory
of every tracked `tests/**/*.fsproj`. It explicitly waits for the Git producer,
refuses an empty or partial inventory, runs every project with `--no-build`, and
requires exactly one positive-count Expecto summary whose run count equals its
passed, ignored, failed, and errored counts, with zero failed and zero errored
tests. Expecto's terminal colour and logger envelope are normalized before
those semantic checks; full original output is retained on every refusal.

Both `scripts/build-and-test.sh` and `scripts/seal-evidence.sh` call that runner.
The sealer asks it for uniquely keyed per-project logs containing the project
identity, execution root, and exact summary; the gate prints the same summaries
from the same population.

`scripts/prove-project-tests.sh` is the blocking hostile proof. It plants root,
nested, differently named, and space-containing projects, then demonstrates
refusal for a partial/failed Git inventory, an empty inventory, a nonzero test
exit even with a success-looking summary, no summary, zero tests, failing and
errored summaries, multiple summaries on separate or shared physical lines,
inconsistent counts, and malformed success text. Its fake executor requires the
complete `dotnet run --project <path> -c Release --no-build` vector from the
candidate root, and a runner mutant that drops `--no-build` is killed. An
always-green mutant proves the proof's refusal oracle is live. The existing
FG-223 proof independently exercises the shared runner through the isolated
candidate and still proves that test prerequisite failures publish no seal.

## Acceptance

- a tracked nested or differently named test project is executed by both the
  authoritative gate and the evidence sealer;
- inventory failure or an empty test population refuses before publication;
- zero tests, any failed/errored test, malformed/multiple summaries, or a
  nonzero process refuses with full diagnostics;
- the hostile runner proof and FG-223 sealer proof both pass;
- every current project suite and the full HeMan gate pass at the exact source
  head; and
- exact-head hosted checks and required reviews pass before protected merge.

This ticket does not claim that an untracked local project is part of a
publishable candidate. Git's tracked candidate inventory is the explicit
boundary; other repository checks separately refuse untracked source at
publication.
