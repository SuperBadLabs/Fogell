## Claim

The admitted corpus contains two JUnit calls in one file with the literal include
`**//*target/surefire-reports/TEST-*.xml`. Pinned Jenkins 2.568.1 / JUnit
`1416.vd753e036de5e` / Ant 1.10.17 treats the doubled internal separator exactly
like a single separator. Fogell previously kept an empty regex segment and
therefore selected no report.

FG-218 normalizes separator characters and collapses repeated separator runs only
at the private JUnit include boundary. The public matcher used by archive/stash is
unchanged. JUnit case sensitivity and the exact 28 default excludes from FG-216
and FG-217 remain in force.

delegates to `SelectorUtils.tokenizePathAsArray`, whose adjacent-separator guard
does not emit empty tokens. Fogell now mirrors that behavior before its existing
case-sensitive JUnit regex compilation.
