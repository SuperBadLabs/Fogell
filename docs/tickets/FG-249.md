# FG-249 — Groovy decodes `\uXXXX` BEFORE lexing, so a unicode escape can terminate a literal, escape the next character, or decode inside a slashy string

Status: **TODO** (P3). Filed 2026-09-04 (committer's local clock) from the
FG-248 second probe sweep; measured on Jenkins 2.568.1 before filing, not
implemented.

## Measured, 2026-09-04

Forty-eight transient jobs on the pinned lab, one per (form, spelling), each
`def v = <literal>` followed by `writeFile` and `od` (the FG-248 runner);
every job deleted after its console was read.

| literal | Jenkins | Fogell at the FG-248 head (`Fogell.Run.Host` for the seven single-quoted and slashy shapes marked †; the parser alone for the rest, confirmed by the verifier) |
|---|---|---|
| `'[\u0027]'` | compile refusal `unexpected char: '''` — the decoded quote ends the literal | decodes to `[']` and runs † |
| `'[\u005c]'`, `'''[\u005c]'''`, `"[\u005c]"`, `"""[\u005c]"""` | compile refusal `unexpected char: '\'` — the decoded backslash escapes `]` | decodes to `[\]` and runs † |
| `'[\u000a]'`, `"[\u000a]"` | compile refusal (`expecting ''', found '\n'`; `expecting anything but ''\n''`) | decodes to a newline and runs † |
| `'''[\u000a]'''`, `"""[\u000a]"""`, `/[\u000a]/`, `$/[\u000a]/$` | compile failure inside the compiler (`StringIndexOutOfBoundsException` or a bare `MetaMethod` stack, no `WorkflowScript:` line) | decodes to a newline (quoted forms, † for triple-single) or keeps the text (slashy forms) and runs |
| `"[\u0022]"` | compile refusal `expecting anything but ''\n''` — the decoded quote ends the literal | decodes to `["]` |
| `"[\u0024]"`, `"""[\u0024]"""` | compile refusal `illegal string body character after dollar sign` — the decoded `$` opens an interpolation | not measured on this engine |
| `/[\u002f]/` | compile refusal `expecting '}', found ']'` — the decoded `/` closes the slashy string | keeps the text and runs |
| `'[\u0022]'`, `'[\u0024]'`, `'[\u002f]'`, `'''[\u0027]'''`, `'''[\u0022]'''`, `'''[\u0024]'''`, `'''[\u002f]'''`, `"[\u0027]"`, `"[\u002f]"`, `"""[\u0027]"""`, `"""[\u0022]"""`, `"""[\u002f]"""`, `$/[\u002f]/$` | runs | decodes the same character (the single-quoted `\u0022` probe's own shell quoting broke on the quote, so its bytes were not compared) † |

The refused rows are the FG-126 class (a script Jenkins refuses runs
here); the `\u0041` row is a VALUE divergence, the ADR 0001 worst class,
inside a string form whose other escapes FG-125 measured as literal.

Corpus: one file (`jjasghar_jenkinsfile_cookbook_pipeline`) uses a unicode
escape at all, `\u27A1` in quoted stage names, which both engines decode
alike; no corpus file has a `\u` inside a slashy string or a unicode
escape decoding to a delimiter. Ranked P3 on that absence.

## What would close it

A pre-lex pass, or an equivalent rule in each string form, that treats a
unicode escape as the character it denotes before the form's own grammar
runs — refusing when the character is the form's delimiter, a backslash or
a line ending in a single-line form, and decoding inside slashy and
dollar-slashy strings — measured per form first; the malformed-`\u`
refusal envelope is not one the harness classifies as pre-execution, so a
receipt for that shape needs a comparator change (a bounded second
envelope) before it can be sealed. The `$`-in-a-GString question is
unmeasured and must be measured before any interpolation claim.
