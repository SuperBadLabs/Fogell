**52 findings.** Today the rules are re-derived per consumer: `environment`, `withEnv`, `input`, `echo`, `equals`, `when` each learned them separately, and four PR #17 rounds were spent on it. **Done.** `src/Fogell.Differential/GString.fs` owns it: `ArgKind` (Literal / Interpolating / Expression), `kindOf`, `sourceOf`, `render`. The model was a CLOSURE inside `run` — unreachable from any test, which is why every consumer re-derived it; 7,232 characters moved out. Ad-hoc kind decisions in the walker: **12 → 1**. The acceptance table lives in `Fogell.Differential.Tests` and covers literal × GString × dotted-env × expression × Groovy-arithmetic × division-vs-slashy × slashy-brace × escaped-dollar × escaped-and-live-in-one-string — every row a behaviour a receipt already proved, restated where it runs in milliseconds. Adding a consumer is now adding a row. Original acceptance: **CORRECTED before this ticket was ever started.** My first draft said `sh`/`bat` "provably do NOT pre-expand". That is wrong, and `tests/Fogell.Groovy.Tests` already proves it: `sh "echo ${name}"` with a Groovy LOCAL must become `echo world` before execution, because the shell cannot see a Groovy local or call a Groovy function. The real rule is that **Groovy interpolates a GString for EVERY step, `sh` included**; what survives to the shell is an ESCAPED `\$` and anything inside a SINGLE-quoted string, which Groovy never touched. The declarative walker currently skips interpolation for `sh` and gets away with it only because the shell expands `$VAR` itself — that breaks the moment a `${…}` names something the shell cannot see; a table test covers literal × GString × expression × escaped-dollar × slashy × division × nested-brace for EVERY consumer, so adding a consumer means adding a row, not rediscovering the rules | **MERGED as PR #23 (d8f18e6) after THIRTY-SIX review rounds** — the highest-round PR in the project's history and the strongest argument yet recorded for FG-105: the reviewers kept finding real defects because the string model is where Groovy's semantics concentrate. Final state: 77/77 tier-1 receipts (+14 new cases measured against the pinned Jenkins during review), 200 tests, a real two-tier interpreter environment (mutable script Binding vs functional locals), strict step-argument rendering that REFUSES by name everything it cannot faithfully evaluate (unknown names, unmodelled methods/operators/parses, wrong arities, unterminated placeholders, non-integral division), Jenkins' own warning and advisory dialects emitted rather than suppressed, and a run-scoped ScriptBinding shared by every render path. Two reviewer findings were REFUTED by measurement (value-based secret detection is Jenkins' own; transformed credentials escape Jenkins' warning AND mask). CI (gate.yml) went live mid-PR and stayed green from its first run.
