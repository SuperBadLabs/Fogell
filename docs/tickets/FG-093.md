# FG-093 — Exact release provenance before downstream execution

`8b59a1e01fd6ef8f1ab6a2cc202dbdf6f18eb982` records historical tree

candidate cannot name its own final commit, so exact current identity and
authoritative-gate evidence belong in the external handoff. The candidate does
not create Fogell's canonical release artifact

## Contract

The live command is deliberately explicit:

```text
scripts/release-provenance-gate.py \
  --manifest /trusted/outside/fogell-provenance.json \
  --artifact /release/staging/fogell-release.bin \
  -- downstream-command [arguments...]
```

The manifest is a trusted input produced outside the checkout being judged. The
checker never writes or refreshes it: regenerating expected values from the
candidate would make a wrong candidate agree with itself. Its JSON root has
exactly five keys:

```json
{
  "schema_version": 1,
  "commit": "40 lowercase hexadecimal characters",
  "tree": "40 lowercase hexadecimal characters",
  "artifact_sha256": "64 lowercase hexadecimal characters",
  "corpus_manifest_sha256": "64 lowercase hexadecimal characters"
}
```

`schema_version` must have JSON type integer exactly — `true` is refused even
though Python otherwise treats booleans as integers. Duplicate, missing, unknown,
non-string, short, mixed-case, malformed, non-UTF-8, and oversized manifests are
refused; no field is lowercased, expanded, defaulted, or guessed.

The gate derives the repository from its own installed path and then requires:

1. Git's top level is that repository.
2. Every gitlink is an initialized, non-symlink Git worktree whose exact HEAD
   commit equals the index gitlink, recursively. A missing checkout or plain
   directory at a gitlink path refuses even when ordinary status would hide it.
3. The root and every recursive submodule have no `refs/replace/*`. Replacement
   objects are disabled for every Git command even while this invariant is
   checked, so repository-admin refs cannot substitute bytes behind trusted IDs.
4. Every worktree has `core.fileMode=true`, no assume-unchanged or skip-worktree
   index entry, no physical untracked path from NUL-safe `git ls-files --others`
   (deliberately without `--exclude-standard`), and an empty `git status
   --porcelain=v1 --untracked-files=all --ignore-submodules=none`. This includes
   ignored build products, local/global exclude tricks, staged, unstaged,
   executable-bit, case-collision, and nested submodule dirt. Sparse/
   skip-worktree checkouts are intentionally ineligible for release provenance.
5. Every NUL-safe stage-0 regular-file entry has the indexed executable mode and
   raw worktree bytes whose filter-free `git hash-object --stdin` ID equals its
   index blob. Every symlink's raw link-target bytes likewise equal its blob;
   gitlinks are handled by the exact recursive rule above. Clean/smudge filters,
   autocrlf/eol conversion, working-tree encoding, ident expansion, or any other
   transformation that makes worktree bytes differ from the index makes the
   checkout release-ineligible.
6. Manifest `commit` equals the full exact `HEAD^{commit}`.
7. Manifest `tree` equals the full exact `HEAD^{tree}`.
8. The resolved artifact path is outside the checkout, and manifest
   `artifact_sha256` equals SHA-256 of that exact regular, non-symlink file.
9. Manifest `corpus_manifest_sha256` equals SHA-256 of this checkout's canonical
   `corpus/CORPUS-SHA256SUMS` bytes.

The artifact in this ticket means only those exact caller-supplied bytes. It is
not yet a canonical package, image, or reproducible-build claim; FG-080 owns that.
The corpus binding covers the pinned manifest file, not a mounted corpus's current
contents. `scripts/verify-corpus.sh` remains the separate content check.

Manifest and artifact reads use `lstat`, no-follow open, `fstat`, and a second
`fstat` after the read. Symlinks, non-regular files, path/open identity changes,
and size/time/identity changes during hashing are refused. While hashing, the
artifact is copied into an anonymous Linux `memfd`; write, grow, shrink, and
further-seal operations are then sealed, the descriptor is rewound, and its
`/proc/self/fd/N` identity is verified before inheritance. Unsupported sealing or
descriptor handoff refuses before downstream execution.

Every Git subprocess drops all inherited `GIT_*` values, forces
`GIT_NO_REPLACE_OBJECTS=1`, disables system/global configuration, and applies
fixed `core.fileMode=true`, `core.ignoreCase=false`,
`core.trustctime=true`, `core.checkStat=default`, `core.fsmonitor=false`,
`core.untrackedCache=false`, and `core.ignoreStat=false` overrides. Thus ambient
Git configuration, alternate indexes, or alternate Git/work-tree pointers cannot
select a different cleanliness view.

Only after every check matches does the process print `PROVENANCE VERIFIED`, set
the five `FOGELL_VERIFIED_*` environment values, remove inherited `GIT_*` names,
restore only protective `GIT_NO_REPLACE_OBJECTS=1`, and replace itself directly
with the supplied argument vector through `execvpe`. `FOGELL_VERIFIED_ARTIFACT`
is the inherited sealed `/proc/self/fd/N`, not the mutable caller pathname. There
is no shell or command string evaluation. A refusal exits non-zero first.

## Offline acceptance proof

`scripts/prove-release-provenance.sh` copies the candidate checker into a new
scratch Git repository and commits it there. The manifest and artifact remain
outside that repository so the positive checkout is genuinely clean.

The positive arm verifies an exact tuple and runs one downstream marker. Every
negative arm removes the marker first and asserts it remains absent. Its committed
positive fixture includes `100644`, `100755`, `120000` symlink, gitlink, and a
newline-containing filename, exercising the raw audit's supported modes and
NUL-safe record parsing. The proof rejects:

- a validly shaped but wrong commit, tree, artifact digest, or canonical corpus-
  manifest digest, one field at a time;
- schema version 2 and boolean `true` masquerading as integer 1;
- short and mixed-case commit/digest values;
- malformed JSON, duplicate keys, missing keys, unknown keys, and non-string
  tuple values;
- a manifest placed inside the checkout;
- a tracked in-checkout file supplied as the artifact;
- tracked, ordinary untracked, executable-bit, case-collision, or nested
  submodule checkout dirt, including root and recursive assume-unchanged/
  skip-worktree masks and local `core.fileMode=false`;
- a `.git/info/exclude`-hidden physical file, an uninitialized/plain-directory
  gitlink, or an initialized submodule at a different commit than its gitlink;
- a clean-filter attack whose status, index flag, and index blob look clean while
  the raw tracked worktree bytes contain different release-visible content;
- inherited `GIT_CONFIG_COUNT`, `GIT_INDEX_FILE`, and `GIT_DIR`/`GIT_WORK_TREE`
  attempts to alter the repository view;
- a clean-looking checkout materialized through a malicious Git tree replacement
  ref while the trusted commit/tree names still appear to match;
- a symlink supplied as the artifact; and
- a non-executable or symlink repository checker before fixture setup. The
  checker copy preserves its source mode, so the proof cannot conceal a committed
  executable-bit or file-type regression by repairing the fixture.

The corpus mismatch mutates only the external expected digest. It does not dirty
the canonical file and therefore cannot pass by tripping the cleanliness check
first. Every rejection separately checks the named diagnostic and proves the
downstream marker did not run.

Four planted checker mutations comment out one `require_match` call each. The
proof verifies each edit changed the checker, commits the mutant so its checkout
is clean, recomputes the other three correct bindings, and observes the associated
known-bad tuple become executable. An artifact-boundary mutation similarly makes
a tracked in-checkout artifact executable. Thus each comparison and the external
artifact invariant are load-bearing rather than sharing an earlier guard.

The downstream probe hostile-preseeds all five `FOGELL_VERIFIED_*` names plus
representative `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, and
`GIT_CONFIG_COUNT` state. It asserts exact verified bindings, exact sealed bytes,
absence of inherited Git values, and protective `GIT_NO_REPLACE_OBJECTS=1`.
Another probe atomically swaps the caller pathname before consumption and still
reads the original digest through the sealed descriptor. Five assignment
mutations and a downstream-scrub removal mutation are detected individually.
Separate mutations remove assume-unchanged,
skip-worktree, file-mode, recursive-submodule, required-gitlink, physical-
untracked, raw-tracked-identity, case-safety, and Git-subprocess-environment
defenses; each associated proof control detects the regression. Two further
mutations jointly remove replacement-object defenses and rebind the artifact to
its mutable source pathname; the corresponding hostile arms then execute or
consume modified bytes. A third mutation removes the kernel seals and exposes
writable snapshot bytes. The complete focused proof reports 65 outcomes.

The offline proof runs blocking in `scripts/build-and-test.sh`. The live gate does
not: there is no trusted external manifest or canonical release artifact during a
pre-publication source gate, and synthesising either there would erase the trust
boundary this ticket exists to enforce.

## Limits and non-claims

- The checker does not establish who created or approved the external manifest,
  authenticate it, sign it, or protect its storage. The live release system must
  supply that trust.
- The sealed artifact handoff is Linux-specific and inherited-descriptor-lifetime scoped.
  Downstream must consume or copy `FOGELL_VERIFIED_ARTIFACT` before closing the
  inherited descriptor or crossing a container/remote-process boundary. The
  caller pathname is origin metadata only and is no longer authoritative.
- The gate cannot prove an arbitrary downstream command did not close or ignore
  `FOGELL_VERIFIED_ARTIFACT` and release different bytes.
- Manifest, checkout, command, kernel, and hostile-administrator replacement
  after verification remain outside the local boundary; only the artifact bytes
  handed downstream are snapshotted and sealed.
- Live release requires a pristine checkout and an artifact outside it. Ignored
  build products are physical untracked paths and therefore make it ineligible;
  the ordinary build gate may create them because it invokes only the isolated
  scratch proof, not the live release checker. Empty untracked directories remain
  outside the claim because Git inventories paths, not empty directories.
- The `git` executable selected through `PATH` and its runtime are trusted host
  dependencies. The gate controls Git configuration/environment inputs but does
  not authenticate the binary or defend a hostile local administrator.
- This is not an artifact signature, transparency log, SBOM, dependency audit,
  reproducible build, image attestation, corpus-content verification, or release
  authorization policy.
