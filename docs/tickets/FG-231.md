# FG-231 — The runnable-controller proof could not finish refusing

Status: **PARTIAL** (P1). The bounds, the proof that they fire, and the gate
timeouts are implemented and measured on HeMan; publication, exact-head review
and merge are pending.

## Defect

`scripts/prove-runnable-controller.sh` is the FG-224 vertical-slice proof and
runs twice in the hosted gate: natively, and inside a digest-pinned container
as PID 1. On 2026-09-01 two hosted PID1 lanes hung after the proof had already
refused:

| run | job | trigger | step started | refusal printed | cancelled |
|---|---|---|---|---|---|
| `33564807004` (main, `42f7455d`) | `100045425020` | push | 22:24:34Z | 22:24:47Z (+13.7 s) | 23:41:39Z (77 min) |
| `33567964629` (PR #294, `d5b83eed`) | `100055372746` | pull_request | 23:02:22Z | 23:02:36Z (+13.7 s) | 23:41:35Z (39 min) |

Both logs end the step with the same line and then nothing until the
cancellation:

```
FG-224 REFUSED: container PID1 was unreadable, expected /home/runner/work/Fogell/Fogell/src/Fogell.Controller.Host/bin/Release/net10.0/Fogell.Controller.Host
```

The runner's cancellation cleanup reported exactly two orphans in each job, one
`bash` and one `docker`. The sibling push run on the same PR commit
(`33567962039`, job `100055364529`) passed the identical step in 51 s, and a
later main run passed, so the hang was intermittent and independent of the
change under test. The `gate` job declared no `timeout-minutes`, so GitHub's
360-minute default was the only bound.

The refusal comes from `launch_controller`: a 200 x 50 ms loop reading
`/proc/1/exe` through `docker exec` until it names the controller apphost.
That budget started at the backgrounded `docker run --rm ... &` and so also
covered whatever `docker run` had to do before the container existed. The
refusal then called `exit 1`, and the EXIT trap ran

```
docker stop --time 10 "$controller_container" >/dev/null 2>&1 || true
[[ -z "$host_pid" ]] || wait "$host_pid" 2>/dev/null || true
```

with no bound on either call. The step log cannot say which of two readings
applied, and both are recorded rather than one asserted:

- **The container did not exist yet.** The identity loop consumed its whole
  10 s budget on fast `docker exec` failures (a daemon that had stopped
  answering would have stalled each of them, and the refusal would not have
  arrived on the budget). A cold pull of the ~850 MB image was measured at
  14 s on run `33567174871` (PR #300's accounting). Under this reading
  `docker stop` fails fast on a name that does not exist, is swallowed by
  `|| true`, and `wait` blocks on a `docker run` client whose pull completes a
  second later and whose controller then serves indefinitely with nothing left
  to stop it. The orphan `docker` is the `run`.
- **The daemon stopped answering.** `docker stop` itself never returns. The
  orphan `docker` is the `stop`.

Reproduced on HeMan against the original script (`origin/main` at
`23dcc469`) with a fast-failing `docker stop` on `PATH` and an outer 120 s
timeout: the proof printed its refusal, exited only when the outer timeout
killed it (rc 124 at 120 s), and left `fogell-fg224-proof-<pid>_1` running
afterwards. A second reproduction, native mode with the synchronous same-child
Run.Host restart replaced by `sleep 1000`, also exited only by the outer
timeout. Neither is a claim about which reading held on the runner; both end
in an EXIT trap with no bound on either call.

By inspection the same proof had further unbounded external waits, none of
which the logs implicate: 34 `curl` invocations without `--max-time` (four
already carried `--max-time 1`), including the deliberately oversized chunked
POST whose server may stop reading without closing; the three synchronous
controller start-up refusals and the direct Run.Host restart; and every
`docker exec`, `docker top` and `docker inspect` in the controller-death lane.

## Implemented boundary

Every wait in the proof is now a named wall-clock bound, and a bound that
expires is a refusal that names its call.

- **Poll loops are deadlines.** Each `for _ in $(seq 1 N); do ...; sleep`
  loop is a `while before_deadline` loop over the same budget in
  milliseconds (200 x 50 ms = 10 s, 600 x 50 ms = 30 s, 300 x 50 ms = 15 s,
  800 x 100 ms = 80 s, 400 x 50 ms = 20 s), measured with `EPOCHREALTIME`, so
  a slow iteration cannot multiply the budget.
- **Every HTTP request carries `--max-time 10`**, the shortest poll budget;
  the four existing `--max-time 1` liveness probes are unchanged.
- **Every docker CLI call, each synchronous controller start-up, and the
  direct Run.Host restart run under `timeout -k 5`** (30 s for docker and
  processes; 900 s for the one-time image pull). The three start-up refusals
  distinguish 124 from the exit code they assert.
- **Every reap is `wait_bounded`**: poll `kill -0` to a 15 s deadline, then
  `kill -KILL`, reap, name the wait, and return 124. `stop_controller` and the
  new `release_controller` (called as the body's last act and again from the
  EXIT trap) fall through to `docker rm -f` by container name when the
  `docker run` client had to be killed, so a container that came up after the
  stop cannot survive the proof.
- **The identity budget measures the controller.** In container mode the
  image is inspected, or pulled under its own bound, before any launch; a slow
  registry is now a named refusal before the first `docker run`. The identity
  refusal itself now prints the container's state (`absent` when it does not
  exist) and the client's last output, which is where a pull in progress
  reports itself.
- **An `errtrace` ERR diagnostic** names the line, command, and call chain of
  any command that fails under `errexit`, marks 124 as a budget expiry, writes
  to the proof's original stderr (the failing call's own stderr may be a
  scratch file that cleanup removes, which is how the first draft of this
  diagnostic went missing), and ends the proof with status 1. Failures inside
  command substitutions are reported once, by the consuming assignment, with
  the substituted command's own status. `set -E` is what makes the trap fire
  inside the helper functions that own every bound; without it bash does not
  run an ERR trap for a function body, which the first draft also found out by
  measurement.

`.github/workflows/gate.yml` gives the `gate` job `timeout-minutes: 45` (green
runs measured at 20m41s on `33567962039` and 18m23s on `33571850280`; twice
the measured duration is a hang) and the two FG-224 proof steps and the new
FG-231 step `timeout-minutes: 10` each (measured 38 s, 51 s, and under five
minutes), so a bound that itself fails to fire is cut at the step rather than
the job.

## Proof of failure

`scripts/prove-fg231-proof-bounds.sh` plants five stalls in byte-mutated
copies of the proof, each under an outer 180 s timeout that is the proof
failing rather than a bound firing, and requires each to exit nonzero on its
own with the expected refusal on stderr, no `fogell-fg224-proof-*` container
left behind, and no controller process from this tree still running. Every
plant asserts that it changed exactly the line it targets. The arms:

1. **`native-stop-ignored`** — `stop_controller`'s `kill -TERM` becomes
   `kill -0`. Expected: `native controller after SIGTERM (pid N) did not exit
   within 15000 ms and was killed`.
2. **`http-silent-server`** — the poisoned-build status GET is pointed at a
   Python socket that accepts and never answers. Expected: the ERR diagnostic
   naming the `poison_terminal=$(curl ...)` assignment with exit 28.
3. **`run-host-restart-hang`** — the same-child Run.Host restart becomes
   `sh -c 'exec sleep 1000'`. Expected: the diagnostic naming `bounded`'s
   `timeout` line, exit 124, budget expired, called from the restart line.
4. **`container-stop-hangs`** (with `FOGELL_FG224_CONTROLLER_IMAGE`) — the
   PID1 identity is compared against a name the controller cannot have, so the
   launch refuses with the container up, and a `docker` shim whose `stop`
   sleeps forever. Expected: the identity refusal, then `controller container
   client (pid N) did not exit within 15000 ms and was killed`, and the
   container removed by name.
5. **`container-run-delayed`** (with the image) — a `docker` shim whose `run`
   sleeps 15 s before creating the container, longer than the 10 s identity
   budget; nothing in the proof is mutated. Expected: `container PID1 was
   unreadable ... (container absent; ...)`, then the same named reap, with the
   controller that came up during the reap removed by name. This is hosted job
   `100045425020`'s own sequence under the first reading above.

The proof runs in the hosted gate after the PID1 step, with the same
PostgreSQL service and image.

Measured on HeMan (fogell-fg060a on 55445, Release build of `23dcc469` plus
this change), the hardened proof passes in both modes with no leftover
container (timings in the publication record), and `scripts/prove-fg231-proof-bounds.sh`
passes with the image on three consecutive runs of the exact committed bytes
(00:30Z to 00:37Z on 2026-09-02, sha256 of both scripts recorded in the run
log), each in 138-139 s:

| arm | refused after | named refusal |
|---|---|---|
| native-stop-ignored | 16-17 s | `native controller after SIGTERM (pid N) did not exit within 15000 ms and was killed` |
| http-silent-server | 11 s | `line 651: \`poison_terminal=$(curl ...)\` exited 28` |
| run-host-restart-hang | 38-39 s | `line 69: \`timeout -k 5 "$1" "${@:2}"\` exited 124 (budget expired) in bounded called from line 917` |
| container-stop-hangs | 46 s | identity refusal with `container running`, then `controller container client (pid N) did not exit within 15000 ms and was killed` |
| container-run-delayed | 25-26 s | `container PID1 was unreadable ... (container absent; ...)`, then the same named reap |

Arm 4's 46 s is 10 s of identity budget, 30 s for the hanging `docker stop`
to exhaust its budget, and the 15 s reap; arm 5's 25 s is the identity budget
plus the reap. Both leave no container: the client is killed and the container
that came up is removed by name.

## Acceptance

- `scripts/prove-runnable-controller.sh` exits 0 in both modes on HeMan and
  contains no `curl` without `--max-time`, no `wait` outside `wait_bounded`,
  and no docker CLI call outside `bounded` other than the two backgrounded
  `docker run` launches, which `wait_bounded` reaps;
- `scripts/prove-fg231-proof-bounds.sh` exits 0 with the image on three
  consecutive HeMan runs, each arm refusing within its budget, and exits
  nonzero with a named arm when any single bound is removed;
- against the original script the same plants hang to an outer timeout;
- `.github/workflows/gate.yml` parses with `timeout-minutes: 45` on the job
  and `10` on the three controller proof steps;
- the exact-head hosted gate passes with the FG-231 step green, and the
  exact head obtains Copilot and Codex coverage.

## Residuals and non-claims

- **Which reading held on the runner is UNPROVEN.** The step log records the
  refusal and the orphan pair, not the client's state. The identity refusal
  now prints that state, so a recurrence names its cause.
- **The hardened proof has not yet run on a hosted runner**; the per-arm
  budgets were sized on HeMan, where a cold pull cannot be measured.
- **The harness itself failed the board's ambient-context rule once.** Three
  of its first eight runs reported arm 1 as a full pass. Every one of those
  runs had `FOGELL_FG224_CONTROLLER_IMAGE` set in the harness's environment,
  the native arms inherited it, and the mutant ran in container mode, where
  the planted `kill -TERM` line is dead code. `run_arm` now unsets the
  variable and each arm names its mode. Found by the three-run rule, not by
  reading.
- **`gh run rerun` is not a recovery for a hung pull_request gate.** The
  re-run of the hung pull_request job (`33567964629`, attempt 2) failed the
  workflow's stale-reference guard (`pre-push commit $BEFORE does not
  resolve`) because a re-run loses the event's base; a fresh push is the
  recovery. Reported by the FG-121 session on 2026-09-01, not re-measured
  here.
- The bounds make a hang a refusal; they do not make the proof faster or
  change what it proves. A genuinely slow runner now fails the 10 s identity
  budget with a named state instead of hanging, which is the intended
  trade.
