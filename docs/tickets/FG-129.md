## The limit, as filed

A Jenkins build refused at COMPILE time emits no `[Pipeline]` annotations,
and the trace classifier was deliberately gated on real structure, so a
compile-shaped refusal on the reference engine reduced to `Started by user
unknown or anonymous` against Fogell's empty output and could not seal a
PROVEN receipt even when result and workspace agreed. Every compile-shaped
refusal the engine implemented was therefore recorded "UNPROVEN by receipt
(FG-129)".

## What landed, unaccounted

Signed commit `d27616c5` ("FG-129 seal compile-refusal equivalence",
2026-08-24) made refusal a comparison AXIS before output shaping:

- `Jenkins.classifyExecutionDisposition` classifies a Jenkins build as
  `RefusedBeforeExecution` from a failure with zero `[Pipeline]` annotations
  and an ordered exact console envelope (the FG-129 test list pins the
  envelope rule and refuses spoofs), and an SCM-defined refusal is
  recognised without a Pipeline-start marker.
- `Compare.traces` compares dispositions first: a one-sided refusal is a
  divergence; when BOTH sides refused, neither executed user code, so
  compiler narration, timestamp coverage and diagnostic wording are outside
  runtime semantics and only disposition, terminal result and the workspace
  hash are compared and sealed (`sealed-output: omitted`; the receipt's
  contract block says so).
- Case and receipt `compile-refusal-invalid-eight` (FG-126a's measured `\8`
  spelling) sealed the first compile refusal PROVEN tier 1, and the test list
  `FG-129 compile refusals are comparable without becoming execution` pins
  the classifier and the comparison.
