Status: **DONE**. The original implementation commit `8007f5090e03bc3954c713d781a4fa39a851b420`
entered `main` inside PR #148, but that PR is historical ingress rather than
closure evidence: its exact head lacks Copilot coverage, and FG-072 had no
standalone seal. This closure independently hardens the current boundary with a
transitive exact-schema audit of every type reachable from `Value`, hostile nested-host-object
fixtures, and real-host generic free-call/member-call denials. The current-tree
HeMan gate passes 921/921 tests and every blocking lane. The standalone receipt

required to receive exact-head review coverage and hosted gates before merge.

## Security claim

Fogell evaluates untrusted scripted Groovy only through its closed interpreter
value model. A free call is admitted only when it is a sanctioned registered
step, a function defined by the script, or a pure builtin; method dispatch is
limited to pure builtins. Every other call fails with the typed `Denied` fault.
The explicit `knownEscapes` set gives reflection, file, process, network,
class-loading, evaluation, thread, and unsafe attempts the more specific
diagnostic rather than the generic unknown-call reason.

`scripts/prove-sandbox-denials.sh` derives the production inventory from
`Sandbox.fs` and requires its named vectors to cover all 30 names exactly as a
set. Two additional vectors stay outside that inventory and exercise the generic
deny-by-default free-call and member-call fallbacks; putting those made-up names
in `knownEscapes` would turn a structural boundary into a deny-list claim. Every
vector traverses the real parser, interpreter, and the exact current-worktree
`tools/Fogell.Run.Host/bin/Release/net10.0/Fogell.Run.Host`; there is no ambient
host-binary override, and a direct call to `admitCall` is not accepted as
end-to-end proof. Constructors, named and generic free calls, ordinary and
generic member calls, and a null-safe call on a null receiver are represented.
For each spelling the lane requires:

- a journaled `Denied` step reason;
- the exact attempted capability name;
- a named capability-boundary explanation;
- exactly one journaled `build-finished` record whose value is `failure`; and
- absence of the successor step's workspace marker.

The positive control exercises a registered `echo`, a registered `sh`, a
script-defined helper, and the pure `trim` builtin. This prevents a blanket
refusal from satisfying the denial half.

The null-safe vector is load-bearing. Previously, a null receiver returned
`VNull` before `Sandbox.admitMethod` ran, so `target?.getClass()` completed and
the successor step executed. Method admission now occurs before the null-safe
short-circuit; arguments remain lazy, so an admitted builtin on a null receiver
still evaluates no argument effects. The lane failed on the pre-fix host binary
and passed only after the corrected interpreter was rebuilt.

## Transitive carrier proof

The sandbox is structural only while the type graph reachable from `Value` contains no
unreviewed CLR carrier or arbitrary host-object reference. This does not claim that
scalar data such as strings cannot name paths, commands, or bearer tokens. The old test froze the union case names and rejected a field
typed directly as `System.Object`; it would still pass if an existing case's
record, tuple, AST node, ref, list, option, or map gained a nested host object.

The replacement audit recursively walks the concrete type graph rooted at
`Value`. Reviewed scalar and F# container shapes are transparent; every reachable
F# union and record contributes a deterministic, exact checked-in schema; cycles
through `Value`, `Env`, closures, and the Groovy AST terminate at the first
definition. Any other CLR leaf is a finding with its full discovery path. A
schema change is therefore an explicit security-review change even when the
outer `Value` case name stays the same.

The proof-of-proof preserves the existing `VScmMap`-shaped outer carrier and
nests a host object below record and map edges. One fixture carries `obj`; another
carries `System.IO.FileInfo`. Both must be rejected at their exact transitive
paths. The previous direct-field-only test would accept both.

## Proof of the proof

The lane first accepts one real denial result, then copies it into eleven
known-bad scratch states. It must reject two execution-status mutations:

1. **timeout-status** — the captured host status is replaced by GNU `timeout`'s
   exit status `124`; and
2. **signal-status** — the captured host status is replaced by `143`, the
   conventional status for termination by signal 15.

It must also reject nine record/workspace mutations:

3. **non-failure-terminal** — the unique terminal record is changed from
   `failure` to `success`, with no second terminal record;
4. **extra-terminal** — a `success` terminal record is appended while the
   original `failure` terminal remains;
5. **generic-failure** — its typed `Denied` classification is replaced by a
   generic failure while its other denial fields remain;
6. **unnamed** — the attempted capability is replaced by `redacted`;
7. **no-boundary-reason** — the reason is replaced by generic policy wording;
   and
8. **reason-free-crosswire** — a named escape's exact boundary reason is replaced
   by the generic free-call reason;
9. **reason-member-crosswire** — the same named reason is replaced by the generic
   member-call reason, whose wording also contains "not reachable";
10. **split-record** — type, attempted name, and reason are distributed across two
    sandbox records so whole-journal greps would assemble a false pass; and
11. **no-halt** — an `escaped.txt` successor marker is planted in the workspace.

The terminal judge reads the first terminal value independently from the count.
That makes the two terminal mutations load-bearing in opposite directions:
removing value enforcement admits the unique `success`, while removing uniqueness
admits the appended `success` after the retained leading `failure`.

The lane records each host command's status separately and validates both paths
through one predicate. GNU `timeout --kill-after=5 60` makes the wall-clock bound
hard even if the host ignores the initial termination signal. The validator
refuses timeout and signal termination explicitly for denial and allowed-control
runs, but does not prescribe one ordinary nonzero exit code for a failed build;
the durable terminal record is authoritative for that claim.

The scratch directory is removed on exit. The lane is wired into
`scripts/build-and-test.sh` after the section-refusal proof and runs without
network or Jenkins credentials.

## Boundary and non-goals

FG-072 proves the interpreter admission and halt boundary only.

- Registered steps are sanctioned capabilities. Their implementations and any
  OS command launched through `sh` or `bat` are outside this proof.
- Agent-account filesystem permissions, process containment, VM isolation, and
  no-egress network enforcement are deployment/runtime controls, not properties
  of `Sandbox.admitCall` or `Sandbox.admitMethod`.
- Secret delivery, redaction, and leak detection remain FG-070/FG-071 controls.
- Syntax the Groovy or Pipeline parser rejects never reaches the sandbox and is
  not counted as a sandbox denial.
- Evaluation tick, materialisation, recursion-depth, and other resource budgets
  remain FG-013 controls. They bound admitted computation rather than deciding
  which host capabilities exist.
- The lane is Fogell security-policy evidence. It makes no Jenkins compatibility
  claim and produces no differential receipt.
