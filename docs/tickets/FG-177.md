results, and JUnit's three measured integer count properties are implemented.
The retained-history SCM maps and the rest of JUnit's object surface remain
fail-closed; work stays split by observable Jenkins contract rather than by
whichever dispatch arm happens to expose it.

The corpus incidence scanner counts unqualified calls plus the explicit Jenkins

## 1. Per-step call schema and unknown binding

Describe accepted positional and named shapes, types/defaults, and the measured
unknown-key binding mode per step.  This is not a universal deny rule: `sh`,
`archiveArtifacts`, `junit`, `checkout`, `deleteDir`, `git`, `stash`, `timeout`
and `retry` warn and continue, while `echo`, `unstable`, `unstash`, `dir` and
`withEnv` bind the map to their constructor parameter and fail coercion.  This
slice is not changed by the genuine-null implementation.

The existing `WalkerRules.soleRequiredParameter` name overstates its contract:
the table supplies the primary parameter name used for positional-to-named
promotion, not a proven minimum-arity rule. Jenkins accepts both `echo()` and a
body-only `retry() { ... }`. Fogell already matches the former in
`script-echo-no-message`, so treating `message` as required would reintroduce a
false refusal. Before slice 1, Fogell refused the latter because the hosted
retry signature demanded `count`, making body-only retry a measured false
refusal. The implemented descriptor models maximum arity, primary-name
promotion, and minimum requiredness as three separate per-step properties.

Slice 1 is now implemented by the exhaustive `WalkerRules.stepDescriptors`
table and its sole `validateHostedCall` boundary. Each of the 14 vocabulary
rows owns maximum positional arity, primary-name promotion, minimum
requiredness, accepted named keys, measured unknown-key binding policy, and
any typed shape check. The validator classifies raw named keys before primary
promotion, so `echo(message: 'x', fogellProbeUnknown: true)` remains a
constructor-map throw rather than becoming a valid positional echo with the
unknown silently discarded. Measured warning rows return structured warning
data with the Jenkins binding class; constructor-map and missing-required
failures use a distinct scripted-Groovy binding fault that `try/catch` may
absorb, while Fogell modelling refusals remain uncatchable.

The binding fault carries its measured runtime class. Constructor-map unknowns
are `IllegalArgumentException`. For a missing required primary, retained Jenkins
evidence records `IllegalArgumentException` for `sh`, `archiveArtifacts`,
`stash`, `unstable`, `unstash`, and `withEnv`, and `NullPointerException` for
`junit`, `checkout`, and `dir`. Catch matching and the value bound to a catch
variable both use that class; a narrow `IllegalArgumentException` catch therefore
cannot intercept the latter three.

The validation boundary is also downstream of the branch-halt guard. For a
`FreeCall`, the interpreter first applies the authoritative sandbox resolution:
a script-defined helper wins over a registered hosted step. Reachability is
then branch-wide, not step-name-based. It is checked before every call argument
and again after a hosted `Perform`; a fail-loud hosted halt unwinds Groovy
evaluation without inventing a catchable fault. Measured runtime exceptions,
including a missing `unstash`, retain their catchable Jenkins fault instead.
Consequently a later helper
named `sh`, `echo`, or another hosted step is neither invoked with discarded
arguments nor allowed to evaluate missing-property or effectful arguments.
Later hosted calls likewise cannot validate, warn, normalize, throw a binding
fault, clear or replace the original diagnostic, or run an effect. This ordering
is part of the call contract rather than a dispatch optimization: Jenkins never
evaluates those later call sites. Method and safe-method targets use the
separate builtin admission path and are covered by the same branch-wide halt.

A hosted halt is contained at the single body boundary shared by the four
admitted scripted wrappers: `dir`, `timeout`, `retry`, and `withEnv`. The wrapper
therefore regains control after its child stops. This is essential for `retry`,
whose attempt owns a fresh failure flag and throwaway status sink: it must inspect
the failed attempt, print `Retrying`, and either run the next attempt or publish
the final failure before the outer script unwinds. The other three wrappers keep
their parent's failure reference while changing directory, deadline, or
environment, so the same boundary preserves their context and propagates the
already-recorded failure once. `node` is not an admitted scripted wrapper.
Stage bodies, stage/pipeline post blocks, sequential children, and parallel
branches start their own walker/script invocation and publish their fresh
`BranchCtx` through the existing stage/post/branch join; they do not sit between
one interpreter thunk and its hosted wrapper. The restart lane covers recovered
and exhausted retry attempts, nested wrapper context, the final attempt's durable
diagnostic, no post-halt warnings/effects, and terminal-journal no-duplication.
The tier-1 `fg177-retry-child-halt-recovers` receipt proves the first-attempt
non-shell halt, nested wrappers, second-attempt recovery, outer continuation,
ordered output, and workspace against pinned Jenkins 2.568.1.

`finally` is the one deliberate reachability exception during that unwind.
Pinned Jenkins executes cleanup helpers and hosted calls even after the try body
has failed, then suppresses ordinary continuation again. Nested cleanup runs
inner then outer. Normal cleanup preserves the original failure; a cleanup fault
or `return` replaces it under Groovy's ordinary control-flow precedence. The
interpreter marks only that dynamic extent as `FinallyUnwind`, and the walker
admits a halted context only for calls carrying that phase. It does not weaken
the ordinary pre-argument guard. Missing `unstash` is surfaced as the measured
catchable `AbortException` instead of irreversibly sinking failure before Groovy
can apply fault/return precedence. The tier-1 `fg177-finally-unwind` receipt
proves retry recovery, helper and hosted cleanup, cleanup-fault replacement,
finally-return replacement, nested ordering, preserved original failure,
suppressed post-halt continuation, ordered output, and workspace. The restart
lane proves exhausted attempts each run cleanup once and terminal replay
duplicates no cleanup effect.

A cleanup call can itself halt while it is using that inherited unwind
permission. Pinned Jenkins stops every successor in the same cleanup block,
still runs a nested `finally` for the newer halt, permits a catchable shell
fault to recover inside cleanup, and lets a nested `finally` return replace both
pending halts. Fogell therefore defers an engine-level call refusal as a
catch-opaque control-flow signal rather than irreversibly sinking failure at the
validation boundary. Only a signal which escapes the current body is returned
to retry or the top-level walker owner and made durable; ordinary Groovy catch
cannot absorb it. The four tier-1 receipts
`fg177-cleanup-new-halt`, `fg177-cleanup-new-halt-nested-finally`,
`fg177-cleanup-catch-recovery`, and `fg177-cleanup-new-halt-return`
prove successor suppression and workspace, nested cleanup ordering, catch
recovery on both retry attempts followed by the original terminal failure, and
return precedence against pinned Jenkins 2.568.1. The restart lane's
`retry-diagnostic` scenario separately proves that this deferred refusal crosses
the wrapper boundary twice, journals exactly one final-attempt reason containing
the original positional-refusal detail, cannot be replaced by unreachable
diagnostics, and performs no successor effect.

The retained corpus incidence TSV regenerates byte-identically. Three focused
tier-1 receipts hold warning-and-continue, catchable constructor-map throw, and
the split minimum contract (`sh()` throws; `echo()` and body-only `retry()`
continue): `fg177-step-schema-warn-continue`,
`fg177-step-schema-constructor-throw`, and
`fg177-step-schema-requiredness`. A fourth receipt,
`fg177-step-schema-halted-unreachable`, proves a failed call prevents later
argument faults/effects, a shadowing script helper, warning-class,
constructor-map, and ordinary effect calls from becoming observable.
`fg177-step-schema-dir-binding-class` proves a
narrow `NullPointerException` catch for the quiet `dir()` path. The restart lane
pins the same positive and negative narrow-catch behavior for both `dir()` and
`junit()`; JUnit's plugin-owned pre-catch narration makes it unsuitable for a
tier-1 ordered-output receipt without weakening the comparator.

The same unwind ownership applies when a cleanup step marks the observed child
Failed/status and returns normally instead of throwing. A pinned 2.568.1 matrix
over `archiveArtifacts`, `junit`, `git`, `stash`, empty `unstable`, `dir`,
`timeout`, `retry`, and `withEnv` showed that Jenkins suppresses the successor
cleanup call while Fogell previously ran it; non-empty `unstable`, which reports
`UNSTABLE` rather than a terminal failure/abort, continues on both engines. The
host now observes every call through fresh status/Failed cells. During inherited
finally permission, only a terminal status introduced by that exact call becomes
a new catch-opaque unwind owner; a successful cleanup which merely observes the
older failed context is not misclassified. The tier-1 receipts
`fg177-cleanup-status-halt`, `fg177-cleanup-status-nested-finally`,
`fg177-cleanup-status-retry`, and
`fg177-cleanup-status-unstable-continues` prove direct successor suppression and
workspace, nested-finally ownership, both retry attempts, and the nonterminal
Unstable control. The descriptor test exhausts
all 14 hosted rows: only the separately measured `sh` and missing-`unstash`
AbortException paths remain catchable, while every other fresh terminal status
uses the deferred owner. The escaping status is committed once with its precise
failure/abort class and masked diagnostic, preserving durable retry/replay state
without duplicating step narration.

## 2. Proven genuine-null returns — implemented

Model a distinct `GenuineNull` return contract for plain `sh`, `echo`,
`archiveArtifacts`, `deleteDir`, `stash`, `unstable` and `unstash`.  A value use
is admitted only when the hosted callback actually yields `VNull`.  `sh` remains
flag-dependent: literal `returnStdout: true` and `returnStatus: true` keep their
typed contracts, an absent or literal-false flag is genuine null, and a dynamic
or non-boolean flag remains refused by the existing fail-closed rules.

Before slice 1, this was **not independently executable**. `StepValueUse.find`
could not distinguish a valid `echo('x')` from
`echo(message: 'x', fogellProbeUnknown: true)`, and the old schema-less path
normalised the primary while silently dropping the constructor-map unknown.
The completed descriptor/validator now runs before dispatch and return
publication, so lifting the value gate cannot bypass that measured binding
fault. No call schema was copied into `StepValueUse`.

`StepDescriptor.ReturnValue` is exhaustive over all fourteen rows. The seven
rows above carry `GenuineNull`; JUnit carries an explicit unsupported
`TestResultSummary`, git/checkout an unsupported SCM map, and the four wrappers
carried an unsupported body result at the slice-2 boundary. Slices 3 and 5
replace only those contracts with `BodyResult` and `JUnitSummary`. The same `returnContract`
feeds the static value-use decision and runtime publication. `HostedResult` is
an unset option until a modelled producer publishes, so `VNull` cannot double
as the initial value for an unimplemented producer. Direct unit-returning walker
arms publish centrally only after validation and nonterminal completion.

Static shell flags distinguish absent, literal false, literal true and
undecidable expressions. The first two select genuine null, literal true keeps
the existing typed stdout/status contracts, and dynamic/non-boolean spellings
remain refused rather than guessed. Binding exception classes, catchability,
status delivery, finally ownership and retry behavior are unchanged.

Tier-1 receipts `fg177-genuine-null-basic`,
`fg177-genuine-null-stateful`, and `fg177-genuine-null-binding` prove the seven
successful null rows, zero-argument echo, stateful archive/stash/delete/unstash,
warning-and-continue, constructor-map and required binding faults, and a failed
shell never becoming null. All three are PROVEN including workspace. The pinned
228-file named-argument TSV is byte-identical. An exact merged-parser incidence
audit found eighteen hosted value uses across eight corpus files, all
`sh(returnStdout: true)`, so this slice changes corpus admission by zero files.

## 3. Wrapper body-result propagation

**Implemented.** `dir`, `timeout`, `retry` and `withEnv` now return the body's
typed result. The established host seam remains a `unit` body thunk: the
interpreter captures each invocation's explicit `return` or implicit trailing
value in a fresh per-call cell, restores the enclosing `LastValue`, and exposes
only the final host-selected successful invocation. The cell is cleared before
every invocation, so a host that absorbs a later fault cannot recycle an earlier
success. A wrapper host that returns without invoking its supplied body refuses
instead of inventing null.

The walker owns whether and how often the thunk runs and returns only an
unobservable transport null for `BodyResult`; the interpreter replaces that
transport value with the captured typed value. SCM-map value uses stay refused;
JUnit's count projection is the separate slice below. Tier-1 receipt
`fg177-wrapper-body-result` is PROVEN including workspace
and covers all four wrappers, explicit and implicit returns, integer/list
preservation, and a failed-first/successful-second `retry` whose final successful
attempt supplies the result.

## 4. SCM maps require retained-history measurement

The current fresh-job/build-1 receipts establish only these minimum observed
key sets:

- `git`: `GIT_BRANCH`, `GIT_COMMIT`, `GIT_LOCAL_BRANCH`, `GIT_URL`;
- `checkout scm`: `GIT_BRANCH`, `GIT_COMMIT`, `GIT_URL`.

They do not establish a complete map across retained job history. Before a
closed model can land, a retained multi-build Jenkins measurement must record
the sorted key sets and values from every build for both steps, explicitly
checking `GIT_PREVIOUS_COMMIT`, `GIT_PREVIOUS_SUCCESSFUL_COMMIT`, and any other
history-dependent keys. The existing differential `runMany` lane can execute
the committed two-build `git` measurement plan, but SCM-defined sequences are
deliberately rejected by the harness, so `checkout scm` needs either that seam
extended or a dedicated retained Jenkins job. No values are inferred here.

A partial map is still inadmissible: a missing history key can make a valid
script take the wrong branch. This slice remains refused until the retained
measurement supports one closed model, and is separate from null returns.

## 5. JUnit closed count projection — implemented, residual object surface open

Pinned Jenkins 2.568.1 with JUnit plugin `1416.vd753e036de5e` returns
`hudson.tasks.junit.TestResultSummary`, not null. The exact installed jar exposes
five semantic getters. Fogell now models only the three integer counts already
transported by its executor: `totalCount`, `failCount`, and `skipCount`.

This is a nominal immutable `VJUnitSummary`, never a map. Exact property reads
return typed integers; unknown properties and every unmeasured operation remain
catch-opaque refusals. That boundary explicitly covers getter calls, `passCount`,
`duration`, rendering, indexing, mutation, equality/identity, truthiness,
reflection, spread access, and direct or collection-wrapped hosted-step
arguments. A missing executor total never becomes zero or null: the hosted call
refuses because its modelled producer published no value.

Receipt `fg177-junit-summary-counts` is tier-1 PROVEN, including workspace. Its
four-test report has one pass, one failure, one error and one skip; both engines
finish UNSTABLE and write `4,2,1` only after the three property reads match.
The retained bundle
`evidence/20260822T035345Z-fg177-junit-summary` brackets the run with identical
oracle, container, JUnit-jar digest, and public-class-surface captures.

This does not close the object. `passCount` is derivable but not separately
transported, while `duration` has a public float getter and Fogell has no decimal
runtime value. Both stay refused rather than acquiring guessed types. The
accepted-but-unimplemented `skipMarkingBuildUnstable` behavior is also adjacent
work, not claimed by this receipt. FG-177 remains PARTIAL with this residual and
the retained-history SCM-map slice open.

## Non-goals of the genuine-null slice

It does not change unknown-key warnings or coercion, wrapper body returns, SCM
maps, JUnit members outside the three-count projection, step
failure/catchability, or the existing shell flag semantics.
