# FG-177 — hosted-step descriptor contract

Status: **PARTIAL**.  Positional upper bounds and primary-parameter name
normalisation already exist in `WalkerRules`, but lower-bound requiredness is
explicitly reopened; the remaining work is split by observable Jenkins
contract rather than by whichever dispatch arm happens to expose it.

The mandatory measurement cases registered on 2026-08-18 against Jenkins
2.568.1 are retained under `evidence/20260818-fg-177-measurement`. The receipts
and logs were regenerated on 2026-08-19 after verifying the pinned oracle and
are bound to that run by `runs/probes/probe-run-manifest.tsv` and
`runs/archive-schema/archive-schema-run-manifest.tsv`. It decides the following
five slices.

The measurement is attributable to one closed oracle identity, not merely a
version string. `jenkins-core.txt`, the sorted installed-plugin manifest
`jenkins-plugins.tsv`, and `jenkins-controller-image.txt` pin the controller
core, every installed plugin's version/active/enabled state, and the immutable
container image ID and digest. `ORACLE-PROVENANCE.md` records the read-only
capture command and exact identity. Both evidence runners verify the live root
and plugin API `X-Jenkins` headers, the complete plugin manifest, and the live
container image before creating an output directory, building the CLI,
synchronizing SCM, or publishing a receipt/exit marker. Redirects,
authentication failures, missing or duplicate version headers, transport
errors, malformed plugin data, and any pinned-metadata drift refuse the run.
`ORACLE-PROVENANCE.md` documents the exact recapture order and the atomic
manifest fields that bind timestamps, oracle metadata, logs, cases, receipts,
and the intentional CLI status `1`.
Each runner owns one self-contained directory under `runs/`. A fresh empty
sibling stage must contain the exact nonempty receipt set and a completed CLI
status before a manifest is built; one atomic directory exchange then publishes
the complete bundle. Partial, empty, extra, interrupted, or infrastructure-error
runs leave the previous receipts and manifest together and byte-identical.

The corpus incidence scanner counts unqualified calls plus the explicit Jenkins
DSL receiver spellings `this.<step>` and `steps.<step>`; it does not treat an
arbitrary object's method as a Pipeline step. The pinned 228-file corpus has no
qualified call in either admitted receiver spelling. Tightening the non-call
boundary removed seven false `git` calls across three files: `git.clean`,
`git.pushGitHubPagesBranch`, and the property read `git.commitAuthorEmail`.
Accordingly, `git` incidence is 26 calls in 26 files rather than 33 in 29;
named-key counts and samples are unchanged.

A direct Groovy 2.4.21 parser probe also rejects the alleged command-syntax
form `println /echo(message: 'fake')/`; Groovy parses the slash as division and
reports the trailing delimiter as invalid syntax. The valid slashy argument is
parenthesized, as in `println(/echo(message: 'fake')/)`, which the scanner
already blanks while preserving calls inside interpolation. Ordinary division
after an identifier, property, safe-navigation expression, or call result
remains executable code. The exact probe source and output are retained in
`groovy-command-slashy-syntax.groovy` and
`groovy-command-slashy-syntax.txt`; no scanner broadening is justified by the
invalid command forms.

## 1. Per-step call schema and unknown binding

Describe accepted positional and named shapes, types/defaults, and the measured
unknown-key binding mode per step.  This is not a universal deny rule: `sh`,
`archiveArtifacts`, `junit`, `checkout`, `deleteDir`, `git`, `stash`, `timeout`
and `retry` warn and continue, while `echo`, `unstable`, `unstash`, `dir` and
`withEnv` bind the map to their constructor parameter and fail coercion.  This
slice is not changed by the genuine-null implementation.

The existing `WalkerRules.soleRequiredParameter` name overstates its contract:
the table supplies the primary parameter name used for positional-to-named
promotion, not a proven minimum-arity rule. Jenkins accepts both `echo()` and a
body-only `retry() { ... }`. Fogell already matches the former in
`script-echo-no-message`, so treating `message` as required would reintroduce a
false refusal. Fogell currently refuses the latter because the hosted retry
signature demands `count`, making body-only retry a measured false refusal.
This evidence PR records, but does not repair, that runtime gap. Slice 1 must
model maximum arity, primary-name promotion, and minimum requiredness as three
separate per-step properties.

## 2. Proven genuine-null returns — blocked on a completed slice 1 schema

Model a distinct `GenuineNull` return contract for plain `sh`, `echo`,
`archiveArtifacts`, `deleteDir`, `stash`, `unstable` and `unstash`.  A value use
is admitted only when the hosted callback actually yields `VNull`.  `sh` remains
flag-dependent: literal `returnStdout: true` and `returnStatus: true` keep their
typed contracts, an absent or literal-false flag is genuine null, and a dynamic
or non-boolean flag remains refused by the existing fail-closed rules.

This is **not independently executable in the current code**. `StepValueUse.find`
asks a callback only `(step name, returnStdout, returnStatus)`, before hosted
dispatch validates the call. It therefore cannot distinguish a valid
`echo('x')` from `echo(message: 'x', fogellProbeUnknown: true)`. Jenkins throws while
binding the latter map to `message`; Fogell's schema-less path currently
normalises `message`, ignores `fogellProbeUnknown`, runs the step and returns `VNull`.
`unstable` and `unstash` have the same measured constructor-map behavior.
Declaring those names `GenuineNull` now would remove the pre-flight refusal and
create a false success.

Allowing only selected positional spellings inside `StepValueUse` is rejected as
a workaround: it would create a second call-schema table in the interpreter
layer, exactly the drift FG-177 exists to remove. Slice 1 must first supply one
descriptor/validator that both pre-flight and dispatch can consult, including
the measured zero-argument `echo` and body-only `retry` minimums. The smaller
warn-and-continue subset is also not landed separately because a step-name-only
contract cannot establish parameter presence or optionality and would change malformed
call placement before the descriptor owns it.

Acceptance after that dependency is satisfied:

- one data source drives both the static `StepValueUse` decision and runtime
  publication;
- focused tests prove all seven null rows and prove `junit`, `git`, `checkout`
  and the four wrappers are still refused as value producers;
- direct Jenkins receipts exercise pure, self-working, zero-argument and
  stateful null-return paths; and
- corpus admission is unchanged except that exactly the measured safe value
  uses cease to be rejected.

## 3. Wrapper body-result propagation

`dir`, `timeout`, `retry` and `withEnv` return the body's typed result.  The
current hosted body thunk returns `unit`, so this requires its own seam change
and retry-specific proof.  It must not be approximated as null in slice 2.

## 4. SCM maps require retained-history measurement

The current fresh-job/build-1 receipts establish only these minimum observed
key sets:

- `git`: `GIT_BRANCH`, `GIT_COMMIT`, `GIT_LOCAL_BRANCH`, `GIT_URL`;
- `checkout scm`: `GIT_BRANCH`, `GIT_COMMIT`, `GIT_URL`.

They do not establish a complete map across retained job history. Before a
closed model can land, a retained multi-build Jenkins measurement must record
the sorted key sets and values from every build for both steps, explicitly
checking `GIT_PREVIOUS_COMMIT`, `GIT_PREVIOUS_SUCCESSFUL_COMMIT`, and any other
history-dependent keys. The existing differential `runMany` lane can execute
the committed two-build `git` measurement plan, but SCM-defined sequences are
deliberately rejected by the harness, so `checkout scm` needs either that seam
extended or a dedicated retained Jenkins job. No values are inferred here.

A partial map is still inadmissible: a missing history key can make a valid
script take the wrong branch. This slice remains refused until the retained
measurement supports one closed model, and is separate from null returns.

## 5. Unsupported JUnit closed object

`junit` returns `hudson.tasks.junit.TestResultSummary`, not null.  Its value use
remains refused unless Fogell adds a closed model for the accessible object
surface and proves it against Jenkins.  Merely naming the Java class is not a
model.

## Non-goals of the genuine-null slice

It does not change unknown-key warnings or coercion, wrapper body returns, SCM
maps, JUnit objects, step failure/catchability, or the existing shell flag
semantics.
