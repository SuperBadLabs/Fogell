# FG-026b — runtime effect-ledger adoption and reconciliation

Status: **PARTIAL** (P0). Built and proven locally on HeMan on 2026-09-04 in
seven commits on `claude/fg-026b-effect-dispatch`; awaiting the exact-head
hosted gate (which now carries the new `controller` job step), dual review and
merge before the row is accounted DONE. FG-026 provides the durable Store
primitive; this ticket puts it in the production runtime.

## Required runtime contract

Every controller-managed external-effect producer must be declared in one
bounded registry and prepare through FG-026 before invocation. It uses one
stable key and exact payload digest across replay/resume within the same attempt,
advances only under the current owner/fence/lease/restore epoch, and confirms
only after destination evidence. A retry child has a new attempt-scoped ledger
identity; cross-attempt destination idempotency is a separate connector contract.
At a bounded production trigger such as lease expiry, restore, or startup,
stale ambiguous prepared/applied work must become tenant-scoped uncertain, reach
an observable operator/API/event surface, and never be automatically invoked
again.

## The honest inventory

Before writing code, every candidate producer in the runnable controller was
listed. The only process that holds attempt authority (owner, fence, lease) is
`Fogell.Controller.Host`; `tools/Fogell.Run.Host` has no Store reference, so
`archiveArtifacts`, `junit`, `stash`/`unstash`, `checkout scm` and `sh` are
child-process filesystem effects the ticket text already excludes. Inside the
host: the Run.Host child launch is a process side effect (scoped out by the
ticket); `ArtifactSnapshots.finalize` moves a staging directory inside the
controller's own state root and has a second caller (the API's legacy
read-repair path) that holds no attempt authority; the outbox rows the Store
writes have no publisher anywhere; and no webhook, notification, e-mail, agent
dispatch or credential-provider connector exists (`rg -i 'HttpClient|Smtp|webhook'
src/` hits only the Jenkins oracle client in `Fogell.Differential`).

**The modelled set of controller-managed external-effect producers was empty.**
The ticket allows "a destination simulator", so the first registered producer is
a real, config-gated connector that the production worker invokes: the file-drop
receipt connector. It is a simulator in the sense that its destination is a
directory, not a network service; it is not a test double — the worker calls it
on every natural terminal when `FOGELL_EFFECT_FILE_DROP_ROOT` is set.

## What was built

- **`Store.ReconcileStaleEffects(org, reason)`** (`src/Fogell.Store/Store.fs`):
  the bounded trigger. Same RepeatableRead classification as
  `MarkStaleEffectsUncertain` (whose contract, including "no operator surface",
  is unchanged and now pinned by a test), plus exactly one `effect.uncertain`
  event (build lineage via attempts -> nodes, payload `{effect_key,
  uncertain_from, reason}`) and one `effect.uncertain` outbox row per newly
  uncertain checkpoint, in the same transaction. Idempotent. `ActivateRestore`
  runs the same classification per organization atomically with the epoch bump
  (reason `restore_epoch_advanced`). The minimal NOBYPASSRLS restore-maintenance
  role therefore needs `SELECT, UPDATE` on `effect_checkpoints`; the Store test
  that enumerates that role's grants was the only place the list lived and is
  updated, and the controller runbook now says so.
- **`EffectProducer`** (`src/Fogell.Controller.Host/EffectRegistry.fs`): the
  closed-world registry, one case (`FileDropReceipt`), `EffectProducer.all`,
  `EffectProducer.name`, and the attempt-scoped key `<producer>:<identity>`.
  `EffectProducerConfig.loadFromEnvironment` parses the two optional variables
  and refuses a kill hook without a destination and a destination that is
  relative, missing, or not disjoint from the state root.
- **`EffectDispatch.run`** (`src/Fogell.Controller.Host/EffectDispatch.fs`): the
  single dispatch path and the only caller of `PrepareEffect`/`AdvanceEffect`
  under `src/`. prepare -> invoke -> record applied -> read destination
  evidence -> record confirmed, with `DispatchHooks` between the windows. A
  refusal at preparation invokes nothing; a confirmed replay is a no-op; an
  applied row only re-reads evidence; any failure after invocation is reported
  `Uncertain` and left for the trigger, never retried. `runRegistered` matches
  exhaustively over `EffectProducer.all` and with no producer enabled returns
  `[]` without a Store call. `killHooks` is the only place a kill can originate.
- **`FileDropReceipt`** (same file): writes `<root>/<org>/<attempt>.receipt`
  (temp file + rename; an existing file is the idempotent destination contract)
  holding canonical JSON `{build, attempt, fence, pipeline_sha256,
  journal_terminal}`; `Confirm` is a byte-exact read. The receipt records the
  executed attempt's journal terminal, not the published build status —
  `PublishTerminal` may still arbitrate a raced cancellation into Aborted.
- **Worker wiring** (`Worker.fs`, `Config.fs`, `Program.fs`): on the natural-exit
  `PublishTerminal` branch, after the artifact snapshot and before
  `PublishTerminal` (lease live, attempt not yet terminal),
  `EffectDispatch.runRegistered` runs every enabled producer;
  `WorkerControl.effectDispatchDisposition` (pure) allows publication only when
  every producer confirmed, otherwise the attempt fails closed into
  `reconciliation_required` with reason `effect_dispatch_unconfirmed`. The scan
  loop body is `scanOrganization` (an internal `ScanOrganization` seam for the
  tests): after `RequeueExpiredLocalAttempts` it runs
  `ReconcileStaleEffects(org, "lease_expired")`. `Program.main` runs
  `reconcileEffectsAtStartup` (reason `controller_startup`) over every
  organization before `app.Run()`; a failure is reported, not a refusal, because
  the periodic pass repeats it. `ControllerConfig` gains one field and one
  additive parse block (kept small because FG-251 is rewriting the file).
- **Operator surface**: `GET /api/v1/organizations/{org}/effects/uncertain`
  (`Router.fs`, `Contracts.fs`), bearer-authorized before parsing, read-only,
  snake_case fields `attempt_id, effect_key, fence, authority_owner,
  restore_epoch, payload_sha256, uncertain_from`.
- **Audit** (`scripts/audit-effect-dispatch.sh`, in the gate's `audits` lane
  after `scripts/prove-effect-dispatch-audit.sh`): five questions the compiler
  cannot ask — one ledger caller; triggers bound to the worker scan and startup
  only; every declared case registered, routed and uniquely named; the
  controller's effect-bearing calls (`HttpClient|SmtpClient|Socket|WebRequest|
  Process.Start|File.Move|File.WriteAll*|.Kill()`) exactly a pinned per-file
  allow-list; the in-process trigger test inside its
  `FG026B_NO_MANUAL_STORE` fence and running the production scan.
- **Process-kill proof** (`scripts/prove-fg026b-effect-dispatch.sh`, new step
  in the hosted `controller` job): see the acceptance table.

## Acceptance, bullet by bullet

Using the file-drop receipt destination simulator, execution is killed in every
prepare/invoke/apply/confirm window twice: in-process (hooks raise a sentinel;
`tests/Fogell.Controller.Api.Tests`, list "FG-026b effect dispatch", 15 tests)
and as a real SIGKILL of the built `Fogell.Controller.Host` apphost
(`scripts/prove-fg026b-effect-dispatch.sh`, run on HeMan against a scratch
PostgreSQL; the four windows die by their own `Process.Kill()` with status 137
and no survivor, the ledger and destination hold exactly that window's state
and receipt count, and the relaunched controller classifies the prepare and
invoke windows through the **startup** pass and the apply window through the
**lease-expiry** pass, each with one event/outbox pair, listed per tenant,
untouched across two further lease periods; the confirm window's row survives
lease loss confirmed and unlisted while the attempt and build still reach
`reconciliation_required`).

- **same-attempt exact confirmed replay is a no-op** — test "a registered
  file-drop receipt runs prepare, invoke, apply and confirm once, and an exact
  same-attempt replay is a no-op" (two replays return `Confirmed true`, the
  invocation counter stays 1, one receipt) and the confirm arm of "an abort in
  each of the four windows ...".
- **payload substitution and stale owner/fence/lease/epoch are refused** — tests
  "payload substitution on the same attempt-scoped key is refused before any
  invocation" (prepared and confirmed rows, plus a flipped receipt byte after
  confirmation) and "stale fence, wrong owner, expired lease and pre-restore
  epoch are each refused before any invocation" (counter 0, no ledger row, no
  receipt for each). The Store-level law is FG-026's ten tests, unchanged.
- **a production trigger, without a manual Store call in the test, classifies
  ambiguous prepared/applied work as tenant-scoped uncertain and emits the
  operator-visible surface rather than auto-replaying it** — test "the
  production lease-expiry trigger classifies an abort in the prepare, invoke and
  apply windows ..." (the fenced region only aborts the real dispatch, ages the
  lease by SQL and runs `LocalWorker.ScanOrganization`; the audit refuses a
  reconciliation call inside the fence), the Store list "FG-026b effect
  reconciliation" (lease-expiry pass, restore pass, idempotency, the
  surface-free primitive), the route test, and the process-kill proof above for
  both the startup and the lease-expiry trigger under the real controller.
- **a closed-world registry/dispatch audit fails if any modelled producer can
  bypass the ledger** — `scripts/prove-effect-dispatch-audit.sh`: twelve planted
  violations refused by name (a direct ledger call in the worker, a second
  `AdvanceEffect` path, a trigger in the API, the worker calling the
  surface-free primitive, an unregistered case, a registered-but-unrouted
  case, a name literal outside the registry, an `HttpClient`, a second file
  write of an allowed kind, a manual Store call inside the fence, a removed
  fence, a fenced test that no longer runs the scan), two clean copies
  accepted. The compile-time half is FS0025 on the exhaustive matches; the
  registry test compares `EffectProducer.all` with the union cases by
  reflection.

## Self-adversarial pass

For each bullet, the input that would make the claim false was tried:

- *A producer bypassing dispatch*: a direct `store.PrepareEffect` planted in
  `Worker.fs` — refused by audit question 1 (proof arm 1). A planted second
  `AdvanceEffect` inside `EffectDispatch.fs` — refused (arm 2).
- *A producer arm removed*: a case added to the DU but not to `all` or the
  dispatch — refused by question 3 (arms 5 and 6); removing the case from the
  `registered` match would not compile (FS0025 is an error).
- *A second organization listing*: the route test's `otherOrg` and the proof's
  foreign organization both receive an empty set; the Store list's foreign
  organization is neither classified nor surfaced.
- *A payload byte flipped*: on the destination after confirmation the
  connector's `Confirm` returns `Ok false` and the ledger replay still never
  re-invokes; a different payload under the same key is refused at
  preparation, before and after confirmation.
- *A replay after confirm*: `Confirmed true`, counter unchanged, in-process
  and (as the confirm window) under the real controller.
- *Re-invocation from applied*: `Ok false` evidence leaves the row applied and
  a second run re-reads evidence only (counter unchanged).
- *The trigger under a non-production owner*: the periodic requeue only reaps
  `local:` owners; the test uses the production owner shape, and the proof
  uses the real one.
- *A kill hook on a service*: refused at startup without a drop root, proven by
  the proof's first window and by the config tests.
- *A judge that cannot fail*: the proof's judges are refused on a controller
  that exits 0, a destination with two receipts, a surface missing its event or
  carrying a duplicate outbox row, and a listing from another organization.

## Scope out (stated, not deferred silently)

- `ArtifactSnapshots.finalize` is not routed: it moves data inside the
  controller's own state root, is idempotent, and its API read-repair caller
  holds no attempt authority. File FG-026c if it should become a producer.
- Child-process step effects (`sh`, `archiveArtifacts`, `checkout`, ...) remain
  under the execution-isolation and no-egress boundaries; Run.Host holds no
  Store authority.
- No outbox publisher, webhook, notification or credential connector exists;
  the file-drop connector is the simulator the ticket allows.
- There is no host-level restore trigger today; restore classification is
  proven at the Store boundary (`ActivateRestore`) and by the startup pass.
- Cross-attempt destination idempotency is each connector's own contract (a
  retry child writes its own receipt).
- No automatic replay, resolution or dismissal of uncertain effects; the API is
  read-only. No uncertainty count on the build status response, no UI.
- A prepared row replayed under the same live authority (same owner, fence,
  lease, epoch — in practice only the same process resuming in-window) is
  driven again through the idempotent connector; once authority is lost the
  trigger classifies it and nothing re-invokes.
