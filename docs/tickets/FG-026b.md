# FG-026b — runtime effect-ledger adoption and reconciliation

Status: **PARTIAL** (P0). Built and proven locally on HeMan on 2026-09-04 in
seven step commits plus one fold commit per review round (see "Review
findings folded" below for the count) on `claude/fg-026b-effect-dispatch`;
awaiting the exact-head
hosted gate (which now carries the new `controller` job step), dual review and
merge before the row is accounted DONE. FG-026 provides the durable Store
primitive; this ticket puts it in the production runtime.

## Required runtime contract

Every controller-managed external-effect producer must be declared in one
bounded registry and prepare through FG-026 before invocation. It uses one
stable key and exact payload digest across replay/resume within the same attempt,
advances only under the current owner/fence/lease/restore epoch, and confirms
only after destination evidence. A retry child has a new attempt-scoped ledger
identity; cross-attempt destination idempotency is a separate connector contract.
At a bounded production trigger such as lease expiry, restore, or startup,
stale ambiguous prepared/applied work must become tenant-scoped uncertain, reach
an observable operator/API/event surface, and never be automatically invoked
again.

## The honest inventory

Before writing code, every candidate producer in the runnable controller was
listed. The only process that holds attempt authority (owner, fence, lease) is
`Fogell.Controller.Host`; `tools/Fogell.Run.Host` has no Store reference, so
`archiveArtifacts`, `junit`, `stash`/`unstash`, `checkout scm` and `sh` are
child-process filesystem effects the ticket text already excludes. Inside the
host: the Run.Host child launch is a process side effect (scoped out by the
ticket); `ArtifactSnapshots.finalize` moves a staging directory inside the
controller's own state root and has a second caller (the API's legacy
read-repair path) that holds no attempt authority; the outbox rows the Store
writes have no publisher anywhere; and no webhook, notification, e-mail, agent
dispatch or credential-provider connector exists (`rg -i 'HttpClient|Smtp|webhook'
src/` hits only the Jenkins oracle client in `Fogell.Differential`).

**The modelled set of controller-managed external-effect producers was empty.**
The ticket allows "a destination simulator", so the first registered producer is
a real, config-gated connector that the production worker invokes: the file-drop
receipt connector. It is a simulator in the sense that its destination is a
directory, not a network service; it is not a test double — the worker calls it
on every natural terminal when `FOGELL_EFFECT_FILE_DROP_ROOT` is set.

## What was built

- **`Store.ReconcileStaleEffects(org, reason)`** (`src/Fogell.Store/Store.fs`):
  the bounded trigger. The same classification rule as
  `MarkStaleEffectsUncertain` (whose FG-026 contract — one RepeatableRead
  snapshot, no operator surface — is unchanged and pinned by a test), run as
  bounded chunks of at most 100 stale candidates per short transaction with
  their attempts taken `FOR UPDATE SKIP LOCKED` (a live attempt is never
  selected or locked), each chunk emitting exactly one `effect.uncertain`
  event (build lineage via attempts -> nodes, payload `{effect_key,
  uncertain_from, reason}`) and one `effect.uncertain` outbox row per newly
  uncertain checkpoint from the same statement. Idempotent. `ActivateRestore`
  runs the same classification per organization atomically with the epoch bump
  (reason `restore_epoch_advanced`). The minimal NOBYPASSRLS restore-maintenance
  role therefore needs `SELECT, UPDATE` on `effect_checkpoints`; the Store test
  that enumerates that role's grants was the only place the list lived and is
  updated, and the controller runbook now says so.
- **`EffectProducer`** (`src/Fogell.Controller.Host/EffectRegistry.fs`): the
  closed-world registry, one case (`FileDropReceipt`), `EffectProducer.all`,
  `EffectProducer.name`, and the attempt-scoped key `<producer>:<identity>`.
  `EffectProducerConfig.loadFromEnvironment` parses the two optional variables
  and refuses a kill hook without a destination and a destination that is
  relative, missing, or not disjoint from the state root.
- **`EffectDispatch.run`** (`src/Fogell.Controller.Host/EffectDispatch.fs`): the
  single dispatch path and the only caller of `PrepareEffect`/`AdvanceEffect`
  under `src/`. prepare -> invoke -> record applied -> read destination
  evidence -> record confirmed, with `DispatchHooks` between the windows. A
  refusal at preparation invokes nothing; a confirmed replay is a no-op; an
  applied row only re-reads evidence; any failure after invocation is reported
  `Uncertain` and left for the trigger, never retried. `runRegistered` matches
  exhaustively over `EffectProducer.all` and with no producer enabled returns
  `[]` without a Store call. `killHooks` is the only place a kill can originate.
- **`FileDropReceipt`** (same file): writes `<root>/<org>/<attempt>.receipt`
  (temp file + rename; an existing file is the idempotent destination contract)
  holding canonical JSON `{build, attempt, fence, pipeline_sha256,
  journal_terminal}`; `Confirm` is a byte-exact read. The root is pinned by
  the operator-created `.fogell-drop-root` marker: `Destination` is checked
  before preparation and inside `Invoke`, only the per-organization
  subdirectory is ever created, and a vanished root is never recreated. All
  destination I/O is descriptor-bound to the pinned root (`open` with
  `O_DIRECTORY|O_NOFOLLOW` once, then `openat`/`mkdirat`/`renameat2`
  relative to it) and evidence is read through a bounded stream after a
  length check on the open descriptor. The receipt records the
  executed attempt's journal terminal, not the published build status —
  `PublishTerminal` may still arbitrate a raced cancellation into Aborted.
  **The destination is byte-checked, not authenticated.** The root is pinned
  by the operator marker and opened `O_NOFOLLOW`, its disjointness from the
  state root is decided by device/inode ancestry, and every entry under it
  is reached through descriptors — but group-writability is not checked and
  the pin is not device identity, so a same-UID pipeline (FG-073's boundary)
  can pre-write `<root>/<org>/<attempt>.receipt`: with the exact bytes the
  destination is byte-identical to what the connector would have written
  (attribution, not truth), and with any other bytes, length or file type
  `Confirm` returns false and forces Uncertain — on its own build only, since
  the key is attempt-scoped. A SIGKILL between the temp file's
  `openat(O_CREAT|O_EXCL)` and its `renameat2` can leave an orphan
  `<attempt>.receipt.<guid>.tmp` beside the receipt (a failed write unlinks
  its own temp; only a kill or a failed unlink leaves one); it is never read,
  never counted (the proof counts `*.receipt`), and not swept.
- **Worker wiring** (`Worker.fs`, `Config.fs`, `Program.fs`): on the natural-exit
  `PublishTerminal` branch, after the artifact snapshot and before
  `PublishTerminal` (lease live, attempt not yet terminal),
  `EffectDispatch.runRegistered` runs every enabled producer;
  `WorkerControl.effectDispatchDisposition` (pure) allows publication only when
  every producer confirmed, otherwise the attempt fails closed into
  `reconciliation_required` with reason `effect_dispatch_unconfirmed`. The scan
  loop body is `scanOrganization` (an internal `ScanOrganization` seam for the
  tests): it ages and requeues lost local leases and claims the next attempt,
  and classifies nothing; the independent `reconciliationLoop` (one
  `PeriodicTimer` tick per lease period, run beside the scan loop by
  `Task.WhenAll`; its pass is the internal `ReconcileOnce` seam) runs
  `ReconcileStaleEffects(org, "lease_expired")` for every organization
  whatever the scan loop is doing, so a long unrelated build cannot delay
  classification. `Program.main` runs
  `reconcileEffectsAtStartup` (reason `controller_startup`) over every
  organization before `app.Run()`; a failure is reported, not a refusal, because
  the periodic pass repeats it. `ControllerConfig` gains one field and one
  additive parse block (kept small because FG-251 is rewriting the file).
- **Operator surface**: `GET /api/v1/organizations/{org}/effects/uncertain`
  (`Router.fs`, `Contracts.fs`), bearer-authorized before parsing, read-only,
  snake_case fields `attempt_id, effect_key, fence, authority_owner,
  restore_epoch, payload_sha256, uncertain_from`, paged by
  `Store.ListUncertainEffectsPage` (`?limit=` 1..1000, default 200; opaque
  organization-bound `next_cursor` over the existing listing order).
- **Audit** (`scripts/audit-effect-dispatch.sh`, in the gate's `audits` lane
  after `scripts/prove-effect-dispatch-audit.sh`): six questions the compiler
  cannot ask — exactly one `PrepareEffect` and one `AdvanceEffect` token in
  `EffectDispatch.fs` and none elsewhere under `src/`; triggers bound to the
  worker scan and startup only; every declared case registered, routed and
  uniquely named; the controller's effect-bearing calls (`HttpClient|SmtpClient|
  Socket|TcpClient|WebRequest|Process.Start|new Process|Environment.Exit|
  File.Move|File.Copy|File.Create|File.Open|File.WriteAll*|FileStream|
  Directory.Move|.Kill()`) exactly a pinned per-file allow-list; the in-process
  trigger test inside its `FG026B_NO_MANUAL_STORE` fence and running the
  production scan; and every reach to a producer's `Invoke`/`Confirm` closure
  (`.Invoke(`, `Invoke =`, `FileDropReceipt.invocation`, `EffectInvocation`)
  confined to `EffectDispatch.fs`. **Limits**: it is a name-based source
  tripwire over `src/` (comments excluded) plus one fenced test region; a helper
  defined outside a scanned pattern and called inside it, a reflection call, or
  a spelling the patterns do not know is not caught. "Closed world" therefore
  means this tripwire plus the compile-time exhaustive match (FS0025) and the
  reflection-based registry test — not a formal proof.
- **Process-kill proof** (`scripts/prove-fg026b-effect-dispatch.sh`, new step
  in the hosted `controller` job): see the acceptance table.

## Acceptance, bullet by bullet

Using the file-drop receipt destination simulator, execution is killed in every
prepare/invoke/apply/confirm window twice: in-process (hooks raise a sentinel;
`tests/Fogell.Controller.Api.Tests`, list "FG-026b effect dispatch", 15 tests)
and as a real SIGKILL of the built `Fogell.Controller.Host` apphost
(`scripts/prove-fg026b-effect-dispatch.sh`, run on HeMan against a scratch
PostgreSQL; the four windows die by their own `Process.Kill()` with status 137
and no survivor, the ledger and destination hold exactly that window's state
and receipt count, and the relaunched controller classifies the prepare and
invoke windows through the **startup** pass and the apply window through the
**lease-expiry** pass, each with one event/outbox pair, listed per tenant,
untouched across two further lease periods; the confirm window's row survives
lease loss confirmed and unlisted while the attempt and build still reach
`reconciliation_required`).

- **same-attempt exact confirmed replay is a no-op** — test "a registered
  file-drop receipt runs prepare, invoke, apply and confirm once, and an exact
  same-attempt replay is a no-op" (two replays return `Confirmed true`, the
  invocation counter stays 1, one receipt) and the confirm arm of "an abort in
  each of the four windows ...".
- **payload substitution and stale owner/fence/lease/epoch are refused** — tests
  "payload substitution on the same attempt-scoped key is refused before any
  invocation" (prepared and confirmed rows, plus a flipped receipt byte after
  confirmation) and "stale fence, wrong owner, expired lease and pre-restore
  epoch are each refused before any invocation" (counter 0, no ledger row, no
  receipt for each). The Store-level law is FG-026's ten tests, unchanged.
- **a production trigger, without a manual Store call in the test, classifies
  ambiguous prepared/applied work as tenant-scoped uncertain and emits the
  operator-visible surface rather than auto-replaying it** — test "the
  production lease-expiry trigger classifies an abort in the prepare, invoke and
  apply windows ..." (the fenced region only aborts the real dispatch, ages the
  lease by SQL and runs `LocalWorker.ScanOrganization`; the audit refuses a
  reconciliation call inside the fence), the Store list "FG-026b effect
  reconciliation" (lease-expiry pass, restore pass, idempotency, the
  surface-free primitive), the route test, and the process-kill proof above for
  both the startup and the lease-expiry trigger under the real controller.
- **a closed-world registry/dispatch audit fails if any modelled producer can
  bypass the ledger** — `scripts/prove-effect-dispatch-audit.sh`: nineteen
  planted violations refused by name (a direct ledger call in the worker, a
  second `AdvanceEffect` path through `store.` and through a differently named
  Store binding, a trigger in the API, the worker calling the surface-free
  primitive, an unregistered case, a registered-but-unrouted case, a name
  literal outside the registry, an `HttpClient`, a second file write of an
  allowed kind, an unlisted `Directory.Move`, a trigger through another Store
  binding in the worker, a producer driven through its
  `Invoke` closure with no ledger row, the same through a spaced
  `invocation.Invoke ()` on a record pattern, a spaced `Invoke   =` copy, an
  `EffectInvocation` assembled in the API, a manual Store call inside the
  fence, a removed fence, a fenced test that no longer runs the scan), two
  clean copies accepted. The compile-time half is FS0025 on the exhaustive matches; the
  registry test compares `EffectProducer.all` with the union cases by
  reflection.

## Self-adversarial pass

For each bullet, the input that would make the claim false was tried:

- *A producer bypassing dispatch*: a direct `store.PrepareEffect` planted in
  `Worker.fs` — refused by audit question 1 (proof arm 1). A planted second
  `AdvanceEffect` inside `EffectDispatch.fs` — refused (arm 2).
- *A producer arm removed*: a case added to the DU but not to `all` or the
  dispatch — refused by question 3 (arms 5 and 6); removing the case from the
  `registered` match would not compile (FS0025 is an error).
- *A second organization listing*: the route test's `otherOrg` and the proof's
  foreign organization both receive an empty set; the Store list's foreign
  organization is neither classified nor surfaced.
- *A payload byte flipped*: on the destination after confirmation the
  connector's `Confirm` returns `Ok false` and the ledger replay still never
  re-invokes; a different payload under the same key is refused at
  preparation, before and after confirmation.
- *A replay after confirm*: `Confirmed true`, counter unchanged, in-process
  and (as the confirm window) under the real controller.
- *Re-invocation from applied*: `Ok false` evidence leaves the row applied and
  a second run re-reads evidence only (counter unchanged).
- *The trigger under a non-production owner*: the periodic requeue only reaps
  `local:` owners; the test uses the production owner shape, and the proof
  uses the real one.
- *A kill hook on a service*: refused at startup without a drop root, proven by
  the proof's first window and by the config tests.
- *A judge that cannot fail*: the proof's judges are refused on a controller
  that exits 0, a destination with two receipts, a surface missing its event or
  carrying a duplicate outbox row, and a listing from another organization.

## Review findings folded

The pre-push verifier (one round) and Codex on PR #424 (head `3c054dd7`,
four inline threads) each found real gaps; every one changed source or
scripts, was re-proven, and is recorded here rather than argued.

- **Verifier**: the dispatch audit missed a producer driven through its public
  `Invoke` closure and a second ledger path through a differently named Store
  binding; question 6 and the token count in question 1 were added, question
  4 widened, four planted arms added. Docs state the audit's limits and that
  the destination is byte-checked, not authenticated.
- **Codex 1 (P1, Worker.fs)**: reconciliation ran only inside the scan loop,
  and `runClaim` holds that loop for a whole build, so a stale row could wait
  for an unrelated build to finish — unbounded. `LocalWorker` now runs an
  independent `reconciliationLoop` (a `PeriodicTimer` on the lease period,
  sequential so single-flight per organization, logged on error, stopped with
  the worker's token) beside the scan loop via `Task.WhenAll`; the scan-loop
  pass is kept because it is cheap and idempotent against it. Test: "the
  reconciliation cadence classifies a stale row within two lease periods
  while the scan loop never runs" starts only the cadence loop and observes
  the classification, one event/outbox pair, no invocation, no write. The
  process-kill proof's apply window passes unchanged.
- **Codex 2 (P2, audit-effect-dispatch.sh)**: question 6 matched only
  `.Invoke(` and `Invoke =`. It now matches `\bInvoke\s*\(`, `\.Invoke\b`,
  `\bInvoke\s*=`, `\bDestination\s*=`, `FileDropReceipt.(invocation|pinned)`
  and `EffectInvocation`; two planted arms (`invocation.Invoke ()` on a record
  pattern, `Invoke   =` in a copy) join the proof (eighteen refusals).
- **Codex 3 (P1, EffectDispatch.fs)**: `Directory.CreateDirectory` on the
  per-organization path would recreate a vanished root (an unmounted volume)
  on whatever is underneath, and the ledger would reach confirmed against a
  receipt on the wrong filesystem. The root is now pinned by an
  operator-created marker file `.fogell-drop-root`: startup refuses a root
  without it; `EffectInvocation` gained `Destination`, checked by
  `EffectDispatch.run` before preparation (Refused, no ledger row) and again
  inside `Invoke` before and after the write (Uncertain, nothing recreated);
  only the per-organization subdirectory is ever created; `Confirm` reads no
  evidence from an unpinned root. Test: "a destination that is no longer the
  pinned root refuses before preparation and is never recreated after it"
  (marker removed before the effect → Refused with no row; root deleted
  between prepare and invoke → Uncertain, row prepared, root absent; remounted
  → confirms on the pinned root; unpinned again → `Confirm` is false). The
  identity check is the marker plus existence, not device/inode: a same-UID
  writer that recreates the marker on a replacement directory is the FG-073
  boundary already stated above.
- **Codex 4 (P2, Router.fs)**: the listing returned every row.
  `Store.ListUncertainEffectsPage(org, cursor, limit)` pages by keyset over
  the existing order `(prepared_at, attempt_id, effect_key)` — no migration —
  with an opaque base64 cursor that carries the organization and is refused
  for any other; `?limit=` defaults to 200, 1..1000, refused otherwise
  (`invalid_limit`), `?cursor=` refused when malformed or foreign
  (`invalid_cursor`); the response gains `next_cursor` (null on the last
  page). Tests: Store page boundaries (2+1, exact fit, limit 1, cross-org
  cursor, garbage cursor, limit 0/-1/1001/1000) and the route (two stranded
  rows paged one per page without skip or repeat, cross-org cursor 400 with no
  key leaked, malformed cursor 400, bad limits 400).

- **Codex 5 (P2, EffectDispatch.fs `Confirm`, second round)**: `Confirm` read
  the predictable receipt path with `File.ReadAllBytes`, so a same-UID
  pre-write of a huge file allocated unbounded memory while a build
  finalised. `Confirm` now opens the receipt through the root descriptor,
  checks `FileStream.Length` against the payload length first (mismatch →
  `Ok false`, nothing read), then reads exactly that many bytes through a
  bounded stream; a short read or a byte past the length is `Ok false`. Test:
  a 3 GiB sparse pre-written receipt → `Confirm` is `Ok false` with under
  64 MiB allocated, the dispatch outcome is Uncertain "evidence absent"
  (never Confirmed, never an exception), the file is untouched; equal length
  with different bytes is refused; the exact bytes confirm.
- **Codex 6 (P2, EffectDispatch.fs `write`, second round)**: after the pin
  check, `Directory.CreateDirectory` re-traversed the configured path, so a
  mount that vanished between pin and write got its organization directory
  recreated on the underlying filesystem and the stray receipt landed there.
  The connector is now descriptor-bound: the configured path string is
  resolved once per operation with `open(O_DIRECTORY|O_NOFOLLOW)` (flag bits
  from `LinuxOpenFlags`, the FG-238 table); the marker is verified with
  `openat` relative to that descriptor; the organization directory is
  `mkdirat` (non-recursive, EEXIST idempotent) and opened with `openat`; the
  temp file is created with `openat(O_CREAT|O_EXCL)` and published with
  `renameat2(RENAME_NOREPLACE)` in the same directory descriptor (an
  EEXIST loser unlinks its temp file); the marker is re-verified through the
  root descriptor after the rename; evidence is read through the same
  descriptors. The five `DllImport`s live beside the kill hook and are pinned
  by the audit's allow-list (question 4 now also pins every `DllImport`
  under the controller). Test: the root is deleted after the pin (test seam
  `invocationWith`) → Uncertain, and afterwards neither the configured path,
  its organization directory nor any receipt exists; a symlink standing in
  for the root → Refused before preparation with nothing written through
  the link. The process-kill proof is unchanged and green.

- **Codex 7 (P1, EffectDispatch.fs:177, round 4)**: the read-side `openat` of
  the marker and the receipt lacked `O_NONBLOCK`, so a FIFO planted at either
  path by a same-UID pipeline parked the worker forever. The descriptor layer
  now lives in `EffectRegistry.fs` (`DestinationDescriptor`, shared with
  startup); every read-side open is `O_RDONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC`
  and is followed by `statx(AT_EMPTY_PATH)` requiring `S_IFREG` with one link
  before any byte is read; anything else is "not pinned" (Refused) for the
  marker and `Ok false` (Uncertain) for the receipt. Test: a FIFO at the
  receipt path → `Confirm` false and Uncertain within a second, the FIFO left
  in place; a FIFO, a directory, a symlink and a hard link at the marker path
  → pin refused by name within a second, nothing invoked.
- **Codex 8 (P1, EffectDispatch.fs:270, round 4)**: `Flush(true)` made the
  temp file's bytes durable but not the `renameat2` entry or the new
  organization directory. `write` now fsyncs the root descriptor after
  `mkdirat` and the organization directory descriptor after the rename,
  before returning; an fsync failure is an error (Uncertain). Test: the trace
  seam observes exactly `root-fsynced, temp-fsynced, renamed,
  organization-fsynced` in that order, and a confirmed replay performs no
  destination I/O.
- **Codex 9 (P2, EffectRegistry.fs:115, round 4)**: startup proved write/exec
  on the root and existence of the marker only; a `0300` root or `0200`
  marker passed and failed every build. `validateFileDropRoot` now performs
  the runtime opens: root `O_DIRECTORY|O_NOFOLLOW` for reading, marker via
  `openat` with the runtime read flags, `statx` regular-file with one link,
  and a bounded read of at most 4096 bytes; each failure refuses startup by
  name. Test: `0300` root → "is not readable as the pinned directory";
  `0200` marker → "readable regular"; a 4097-byte marker → "larger than";
  a FIFO marker → "not a regular file" within a second (permission arms skip
  under uid 0).

- **Codex 10 (P2, EffectRegistry.fs:360, round 5)**: the "drop root not
  inside `FOGELL_STATE_ROOT`" check was a lexical `StartsWith` on
  `GetFullPath`, so `/srv/alias -> /srv/state` with root `/srv/alias/drop`
  passed. Disjointness is now decided physically with both directories open:
  `DestinationDescriptor.isWithin` walks upward with
  `openat(fd, "..", O_DIRECTORY|O_NOFOLLOW)` comparing `(device, inode)` from
  `statx` until the filesystem root (whose parent is itself), in both
  directions, bounded at 4096 levels; the lexical check stays as the cheap
  first refusal. Test: a symlinked ancestor into the state root → "physically
  inside"; the drop root containing an aliased state root → "physically
  contains"; a genuine sibling passes.
- **Codex 11 (P2, Store.fs:1448, round 5)**: a well-formed base64 cursor whose
  decoded key held NUL, invalid UTF-8 or an out-of-range length only failed
  inside PostgreSQL as a 500. `decode` now uses a strict UTF-8 decoder,
  `TryParse` for the organization, timestamp ticks (range-checked) and attempt
  id, and holds the key to `validateEffectInput` (the rule `PrepareEffect`
  and the 0007 check constraint enforce) plus a NUL refusal, all before any
  connection; every failure is "cursor is malformed" → route `invalid_cursor`
  400. Tests: Store — ten tampered shapes against an unreachable store (NUL,
  oversized, empty, whitespace key; non-GUID attempt and organization;
  garbage and out-of-range timestamp; invalid UTF-8; missing field) refused
  without a round trip while a genuine cursor still works; route — NUL key,
  oversized key, non-GUID attempt, garbage timestamp → 400 `invalid_cursor`.

- **Codex 12 (P2, Store.fs:1481, round 6)**: a keyset over `prepared_at`
  skipped a row that became uncertain behind an issued cursor while the
  reconciliation cadence ran, because a row can be classified long after it
  was prepared. `ListUncertainEffects` and `ListUncertainEffectsPage` now
  order and page by `(uncertain_at, prepared_at, attempt_id, effect_key)`:
  `uncertain_at` is monotone for rows entering the set and NOT NULL for
  every uncertain row by the 0003 guard (so no COALESCE), and the
  classification pass now stamps it with `statement_timestamp()` rather than
  `clock_timestamp()` so every row of one pass shares one instant and
  `prepared_at` breaks the tie — which is what keeps FG-026's pinned "stable
  list order" test (prepared before applied, classified together) true; the
  first local full gate on this fold caught that test flipping under a
  per-row `clock_timestamp()`. The cursor (version `fg026b-2`) encodes the
  four keys, the page row carries `UncertainAt`, and the wire row gains
  `uncertain_at` (ISO 8601 UTC). The one other Store assertion that read two
  same-pass rows in prepared order now asserts the set. Test: rows A, B, C
  prepared in that order; B and C classified;
  page 1 (limit 1) → B and a cursor; A classified behind the cursor;
  following the cursor reaches C then A (a `prepared_at` keyset would have
  left A behind), and the full listing is in classification order.
- **Codex 13 (P2, EffectRegistry.fs:321, round 6) — declined with a stated
  limit**: a bind mount that aliases a subdirectory of `FOGELL_STATE_ROOT`
  defeats the device/inode ancestry walk. No mount-table parsing was added.
  The disjointness check is an operator-configuration guard decided by
  device/inode ancestry; a bind-mounted alias of a state-root subdirectory is
  invisible to it and is the operator's own configuration. The destination is
  byte-checked and unauthenticated by design (FG-073), so this changes
  attribution, not truth.

- **Codex 14 (P2, Store.fs:1512, round 7)**: the only partial index (0003,
  `effect_checkpoints_uncertain` on `(organization_id, prepared_at,
  attempt_id, effect_key)`) did not match the new keyset, so a small page
  sorted an organization's whole uncertain history. Migration
  `0012_effect_checkpoints_uncertain_order.sql` creates
  `effect_checkpoints_uncertain_order` on `(organization_id, uncertain_at,
  prepared_at, attempt_id, effect_key) WHERE state = 'uncertain'` and drops
  the 0003 index in the same migration because nothing uses it any more
  (`rg -n effect_checkpoints_uncertain src` hits only its own definition; the
  classification pass filters `state IN ('prepared', 'applied')`, which the
  partial predicate never covers, and both listings now order by
  `uncertain_at` first). No new table or sequence, so `RuntimeCapabilities`
  is unchanged; the runbook lists no migrations, so nothing to add there.
  `EXPLAIN (COSTS OFF)` of `ListUncertainEffectsPage`'s query on the scratch
  database (schema at 0012) with a cursor:
  ```text
  Limit
    ->  Index Scan using effect_checkpoints_uncertain_order on effect_checkpoints
          Index Cond: ((organization_id = '…'::uuid) AND (ROW(uncertain_at, prepared_at, attempt_id, effect_key) > ROW('…'::timestamptz, '…'::timestamptz, '…'::uuid, 'k'::text)))
  ```
  and without a cursor `Limit -> Index Only Scan using
  effect_checkpoints_uncertain_order (Index Cond: organization_id = …)` — no
  Sort node in either. Those plans were taken with `enable_seqscan = off`:

## Scope out (stated, not deferred silently)

- `ArtifactSnapshots.finalize` is not routed: it moves data inside the
  controller's own state root, is idempotent, and its API read-repair caller
  holds no attempt authority. File FG-026c if it should become a producer.
- Child-process step effects (`sh`, `archiveArtifacts`, `checkout`, ...) remain
  under the execution-isolation and no-egress boundaries; Run.Host holds no
  Store authority.
- No outbox publisher, webhook, notification or credential connector exists;
  the file-drop connector is the simulator the ticket allows.
- There is no host-level restore trigger today; restore classification is
  proven at the Store boundary (`ActivateRestore`) and by the startup pass.
- Cross-attempt destination idempotency is each connector's own contract (a
  retry child writes its own receipt).
- No automatic replay, resolution or dismissal of uncertain effects; the API is
  read-only. No uncertainty count on the build status response, no UI.
- A prepared row replayed under the same live authority (same owner, fence,
  lease, epoch — in practice only the same process resuming in-window) is
  driven again through the idempotent connector; once authority is lost the
  trigger classifies it and nothing re-invokes.
