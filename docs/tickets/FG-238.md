# FG-238 — O_DIRECTORY and O_NOFOLLOW were hardcoded to the x86-64 values, so on arm64 the descriptor policy failed closed and never asked for no-follow

Status: **PARTIAL** (P2). Source head `5a27fb93976b403da4632210c031fd92ee9bf9d7`
merged through PR #364 as `f049c4b8c1b70efdf45bc94e5492913cb06b6c38` on
2026-09-03 after the exact-head hosted gate and Copilot/Codex coverage. The fix
is derived from the kernel's headers and proven on x86-64; what remains is the
arm64 run named under "What DONE requires". Filed 2026-09-02 from the
grok QA report's Manyu (Docker Desktop, LinuxKit arm64) finding: stash and
artifact GET returned 503.

## Defect

`src/Fogell.Execution/Native.fs` and `src/Fogell.Controller.Api/Router.fs`
each declared

```fsharp
let private OpenDirectory = 0x10000
let private OpenNoFollow = 0x20000
```

Those are `include/uapi/asm-generic/fcntl.h` values (0o200000, 0o400000),
which x86, x86-64, riscv, s390x and loongarch use. `arch/arm64/include/uapi/asm/fcntl.h`
overrides them (arm64 kept arm32's numbering; arm and powerpc carry the same):

| flag        | asm-generic       | arm64            |
|-------------|-------------------|------------------|
| O_DIRECTORY | 0o200000 (0x10000)| 0o40000 (0x4000) |
| O_NOFOLLOW  | 0o400000 (0x20000)| 0o100000 (0x8000)|
| O_DIRECT    | 0o40000           | 0o200000         |
| O_LARGEFILE | 0o100000          | 0o400000         |

Read from `/usr/src/linux-hwe-7.0-headers-7.0.0-30` on HeMan. On arm64 the
two hardcoded bits are therefore `O_DIRECT|O_LARGEFILE`. Opening a directory
with `O_DIRECT` is EINVAL, so every entry point of the FG-228 stash policy and
the artifact GET path failed at its first directory open: stash 503, artifact
GET 503, exactly what Manyu showed. It failed closed — no traversal was
possible, because no stash or unstash path reaches a leaf open before a
directory open has already failed (`openFileWithoutLinks` itself opens only
the leaf, but every caller selects through the workspace descriptor first) —
but it failed for the wrong reason, and had any path reached a
leaf-only `O_NOFOLLOW` open the kernel would have been asked for
`O_LARGEFILE` and followed the link. The guard was absent on that
architecture, not merely broken; that is why this is a ticket and why it is P2
rather than P1: the intended server (HeMan, Luigi, Mario, the hosted gate) is
x86-64, where the FG-228 evidence stands unchanged.

## What closed it on this branch

- `src/Fogell.Domain/LinuxOpenFlags.fs`: one table per architecture lineage
  (`asmGeneric`, `armLineage`), `forArchitecture` mapping every
  `System.Runtime.InteropServices.Architecture` .NET names to one of them, and
  an `Error` for anything untabulated (`Wasm`, or a future value). A wrong bit
  pattern is silent until it is a traversal, so an unknown architecture is a
  refusal, never a guess.
- `Native.fs`: the two literals are gone. The four public descriptor-policy
  entry points (`openDirectoryIfPresentWithoutLinks`,
  `openChildDirectoryWithoutLinks`, `openFileWithoutLinks`,
  `createWorkspaceFileWithoutLinks`) resolve the table once through
  `requireOpenFlags` and pass it to the bodies; an untabulated architecture
  returns `descriptor policy unavailable: …` through the existing `Result`
  channel.
- `Router.fs`: `tryOpenArtifact` matches the table alongside the path
  segments and answers `ArtifactPlatformUnsupported` when there is none, after
  the invalid-path check so a bad path still reads as a bad path.
- `Fogell.Domain.Tests`, list `FG-238`: seven tests pin both tables to the
  header values, prove the generic bits are `O_DIRECT|O_LARGEFILE` on arm64,
  map every named architecture, refuse `Wasm`, and require the running
  process to be tabulated. The mutant that puts the generic values in the arm
  row fails exactly two of them.
- `scripts/prove-fg228-stash-symlinks.sh`: its child-directory mutant now
  targets `openChildDirectoryWithoutLinksUsing` and removes one
  `||| table.NoFollow` guard, and it still kills the mutant, so the FG-228 proof
  binds the renamed opener rather than passing vacuously.
- `Fogell.Execution.Tests`, list `FG-238` (Linux only): the running
  architecture is tabulated, a plain directory opens under the resolved
  policy, a linked directory is still refused. On arm64 with the old literals
  the second test fails EINVAL; the FG-228 suite fails the same way, but this
  is the test that says why.

## What DONE requires

Run `Fogell.Execution.Tests` lists `FG-228` and `FG-238` on an arm64 Linux
host (Manyu's Docker Desktop is enough) at the exact head and record the pass
in this ticket. Until that run exists the fix is derived, not measured, and
the row stays PARTIAL.

## Not this ticket

- `O_NONBLOCK`, `O_CREAT`, `O_TRUNC`, `O_CLOEXEC` keep their literals: no
  architecture .NET runs on overrides them (alpha, sparc, mips and parisc do,
  and .NET does not run there).
- The x86-64 FG-228 evidence is not re-sealed; nothing in its path changed
  value on x86-64.
