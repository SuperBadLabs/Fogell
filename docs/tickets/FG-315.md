# FG-315 — Establish safe unattended maintenance quiescence

**Wave:** W3 · **Priority:** P0 · **State:** Doing · **Unblocks:** FG-308, FG-310

The paired backup helper requires stopped database and state writers. The
current controller has no admission pause or drain operation. Stopping its
service on a timer can interrupt an active attempt and leave an uncertain
external effect; a configurable shell hook that exits zero cannot by itself
prove that all controller, worker, retention, Run.Host and detached descendants
are extinct. Therefore FG-308 cannot be scheduled safely with the current
host contract.

Define and implement a supported single-host maintenance boundary that closes
new admission, stops new worker claims, lets running attempts become terminal
or explicitly reconciliation-required, and then stops all state/database
writers. Verify the database state and the service process domain independently
before authorizing `paired-backup.py --writers-quiesced`. Preserve uncertain
attempts and evidence; do not clear dirty storage-pool records or replay an
external effect to make the check pass. Specify a safe resume and a timeout
path that leaves backup unstarted with an operator alert.

**Done when:** a disposable-host test with active and detached work proves the
backup cannot begin until the admission and writer conditions are satisfied;
timeout/interruption leaves an explicit failed maintenance record; resume
returns admission only after verification; and the runbook names exact service,
database, process-domain, and state-root checks. Record raw process, database,
API and backup evidence. Keep the October 23 W3 deadline unchanged and report
the gate as missed if this prerequisite is not qualified in time.
