# FG-165 — Deterministic containment-test precondition

Status: **DONE 2026-08-27**

## Problem

The `BEAT JENKINS` success-containment test repeatedly failed on hosted runners
with `the daemon never started, so this test would prove nothing`, then passed on
the identical source SHA. The test was honest about its missing precondition, but
its fixture let the foreground shell exit immediately after forking `nohup`.
Fogell could therefore reap the successful process group before a delayed child
wrote `daemon.pid`.

That false red blocked unrelated changes and trained gate readers to distinguish
"the known flake" from a real regression. A required gate cannot carry that
ambiguity.

## Closure

`daemonScriptAfter` keeps the foreground shell alive until the background child
has written a nonempty pid file, with at most 300 ten-millisecond probes and a
distinct exit code on failure. All ordinary daemon fixtures use that helper. The
typed delay and shell-quoted positional pid path keep the proof independent of
workspace punctuation.

The closure regression adds a 250 ms delay before the child records its pid. It
then proves both halves of the contract: the child established a real pid before
the foreground success path completed, and Fogell subsequently reaped that exact
pid. Removing the bounded handshake makes the focused test fail with the original
precondition error, so the wait is load-bearing rather than incidental runner
slowness.

The adjacent FG-197 output-causality fixture also no longer uses a 150 ms sleep.
It now crosses the reader/signal boundary through three observable handshakes:
the user `Terminated` callback has started, interruption has been selected, and
the shell's TERM trap has run. This closes the fresh same-SHA failure observed on
hosted runs `32996633611` (red) and `32996641247` (green) without changing
production process semantics. It does not close FG-197's same-host latency
measurement requirement.

## Acceptance evidence

- The delayed-daemon regression passed 50 consecutive focused runs.
- A mutant deleting the parent handshake failed deterministically with
  `the delayed daemon was reaped before establishing the test precondition`.
- The handshake-based pre-signal regression passed 100 consecutive focused runs.
- The complete Execution suite passed 101/101 on HeMan outside the test runner's
  private PID namespace. Inside that namespace, the unrelated pre-setsid guard
  correctly observed process group 1, which violates a host-oriented fixture
  assumption but is not a product failure.

The unmodified authoritative HeMan gate passed with all 922 project tests, the
focused FG-207 durability checks, every blocking audit/proof, the live 228-file
FG-094 compatibility regression comparison, restart lane, approval lane, and
terminal `OK`.

## Boundary

This ticket removes nondeterminism from containment and output-order test
coordination. It does not weaken a fail-closed assertion into a skip, change the
runtime cleanup algorithm, claim VM-grade containment, or satisfy FG-197's
Jenkins-versus-Fogell performance benchmark.
