# FG-255 — Twenty FG-236 mutants were judged against a doubly-mutated program

Status: **IN PROGRESS** (P1). Found while measuring the hosted gate for FG-256; the
performance work is blocked on this, because it would otherwise have sharded a proof
whose mutants are not independent.

## Defect

`scripts/prove-fg236-stream-masking.sh` is FG-236's blocking mutation proof: 44 mutants,
each a `sed -i` against a scratch copy of the worktree, followed by a rebuild and a
filtered Expecto run that must fail with a named message. Isolation between mutants was
maintained by hand — each mutant restored its own file from a `.clean` snapshot before the
next one was applied.

One of those restores named the wrong file. At line 246 the `live-policy` mutant edits
`WalkerStep.fs`:

```bash
sed -i 's/^ *MaskingSecrets = Some runCtx\.BoundSecrets$/  MaskingSecrets = None/' "$walker_step"
kill_differential_mutant live-policy 'the late-registered split form is redacted'
```

Line 252 then restores **`walker_ctx`**. The next restore of `walker_step` is at line 443,
197 lines later. Every other file in the proof is restored immediately after its own
mutant; this is the sole exception.

**Twenty mutants were therefore evaluated against a program carrying two mutations rather
than their own one** — `publication-race` through `failed-reader-drain`, each running with
a residual `MaskingSecrets = None` in `WalkerStep.fs`, plus `admission-factory`, which
edits a *second* line of the same already-mutated file and so was an unintended compound.

## Why it stayed green

`kill_mutant` and `kill_differential_mutant` require only that the mutant compiles, that
the suite exits non-zero, and that the expected string appears **anywhere** in the
captured output:

```bash
printf '%s\n' "$output" | rg -F "$expected" >/dev/null \
  || { ...; echo "FG-236 proof: $label mutant failed elsewhere" >&2; exit 1; }
```

With two mutations live, both produce failures and both print. So the residual mutation
could satisfy a later mutant's assertion on its own: **a mutant whose own edit was inert
would still have been recorded as killed.** That is precisely the false-green a mutation
harness exists to exclude, and it is why the defect survived review — the proof passed.

This makes the published claim in `docs/tickets/FG-236.md:217` and
`docs/EXECUTION_BOARD.md:916` ("all 44 compiling semantic mutants") weaker than stated for
twenty of them, independently of whether they still pass once isolated.

## Fix

Isolation is now structural rather than clerical:

- **All seven pristine snapshots are taken together, before the first mutation.** Two
  (`executor`, `process_group`) used to be taken mid-script, immediately before their
  file's first mutant. That was correct in itself but meant no point existed at which
  every pristine copy was available, so a total reset was impossible and isolation had to
  be hand-maintained.
- **`reset_tree` runs at the end of both kill helpers**, so a mutation cannot outlive the
  mutant that made it. It is content-compared (`cmp -s` before `cp`): rewriting an
  already-pristine file bumps its mtime and forces MSBuild to recompile that file's whole
  project chain for a change that is not there. `cp -p` would be wrong in the other
  direction — preserving the pristine mtime would leave the previous mutant's compiled
  output looking up to date, and the next mutant would be tested against the previous
  mutant's binary.
- **`assert_isolated` runs at the start of both kill helpers** and refuses when more than
  one file differs from pristine. Every one of the 44 mutants edits exactly one file
  (verified statically across the whole script), so this is the check that would have
  caught the original defect at the very next mutant instead of never.

## Scope

The defect is confined to this proof. Its three siblings share the `bash -ic` /
scratch-tree idiom but not the failure: `prove-fg235-multiline-secrets.sh` has two
mutants, each isolated; `prove-fg228-stash-symlinks.sh` applies three `sed`s as one
intentional compound mutant; `prove-fg251-token-file.sh` factored a `restore_config()`
helper rather than restoring inline. The hand-restore idiom only broke down at 44 mutants.

**All 44 mutants are still killed once isolated, including the twenty that were
previously judged against a residual mutation.** The published conclusion was therefore
correct; the evidence behind it was not, for twenty of the forty-four. No live hole in
FG-236's masking guarantees follows from this ticket, and the FG-236 claim needs no
retraction — but it needed this run to be true rather than assumed.

`assert_isolated` passed 44 times, which is the positive control for the fix: every
mutant now demonstrably starts from a pristine tree. Before the fix the same assertion
would have refused at `publication-race`, the twentieth mutant.

### The checker shown to fail

A checker nobody has watched fail is a claim, and this one exists precisely because the
condition it detects previously produced no symptom. Removing **only** the added
`reset_tree` call from `kill_differential_mutant` — leaving the one in `kill_mutant`, so
the tree is reset for every Execution mutant and for none of the Differential ones —
recreates exactly the original missing-restore condition. Run on that copy:

```
FG-236 proof: publication-race runs with 2 mutated files (WalkerStep.fs WalkerCtx.fs); a restore is missing
```

It refused at `publication-race`, the nineteenth mutant and the first one the original
defect contaminated, naming both files. Seventeen `kill_mutant` arms and `live-policy`
itself passed before it, which is the discrimination that matters: the assertion does not
fire on the mutants that were always isolated, and fires on the first one that was not.
It refuses before the build, so the run stops in ~4 minutes rather than completing.

### Not a performance claim — the timing difference is UNATTRIBUTED

Same host, same isolated-cache recipe, one run each:

| script | total |
|---|---|
| `HEAD` (before the fix) | 870.45 s |
| with the fix | 580.33 s |

**This is not offered as a speedup, and the difference is not attributed.** Three reasons
it cannot be, as measured:

- **n=1 on each side, on a shared machine.** HeMan was running several other agent
  sessions during both runs. Nothing pinned cores or excluded concurrent builds.
- **No mechanism accounts for it.** The fix adds work (seven `cmp`s per mutant) and
  removes none: the per-mutant `cp "$scratch/X.clean" "$X"` restores are still present and
  still unconditional, so the mtime churn they cause is unchanged. A 33% reduction with no
  mechanism behind it is more likely load than effect.
- **Neither number bears on the gate.** The hosted proof costs 1495 s on a 4-core
  `ubuntu-latest`; HeMan has far more cores, so no HeMan figure transfers to CI.

Recorded here only so a later reader does not mistake the fixed run's 580 s for a
regression or an improvement. The cost work is FG-256, which must measure its own
before/after with repeats on one host, or on CI where the 1495 s was measured.
