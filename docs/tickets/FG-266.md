# FG-266 — Structured execution and test diagnostics

Status: DONE. Milestone: M2. Depends on: M1 observations.
Completion scope: local implementation and measured acceptance (2026-09-23); publication remains separate.

Problem: text logs force each coding agent to rediscover failure structure.

Scope: define and persist versioned step/test diagnostics (stable identity,
category, exit/result, source position where actually known, bounded relevant
output and artifact references). Preserve masking and fencing at ingestion.
Report infrastructure failures separately from workload failures. Unknown
locations remain unknown; do not invent a diagnosis from log text.

Acceptance: deliberate shell/test/infrastructure failures produce distinct
machine-readable evidence before or at terminal publication; oversized and
secret-bearing diagnostics respect shared budgets/masking; restart does not
duplicate identity; stale attempts cannot publish; an agent identifies the
planted failing test without scanning full logs. Re-run the M1 campaign and
measure time to first actionable diagnostic.

Design gate: enumerate existing runner events and JUnit data before adding a
new durable representation; specify upgrade and rollback with any migration.
