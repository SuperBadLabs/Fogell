# Design pipeline-environment expression evaluation

Priority: **P1**

Status: **DONE 2026-09-07**. FG-259 measured a reachable semantic difference before
allowlisting its corpus candidate: Jenkins evaluated a top-level zero-argument
helper used as an unquoted pipeline `environment` RHS, while Fogell retained the
call text. This ticket owns the missing capability. It does not itself authorize
that corpus file or claim compatibility; FG-261 owns that separate decision.

## Measured boundary

The exact helper reads `env.GIT_BRANCH` and `env.BUILD_ID`, replaces `/` with
`.`, and concatenates the values. Two three-attempt controls on Jenkins 2.568.1
showed that it runs during pipeline environment setup and sees the pre-block
build environment: a late `withEnv` overlay cannot change the result, and
sibling `GIT_BRANCH`/`BUILD_ID` declarations are not visible to the helper.
Jenkins produced `null.1`; Fogell produced literal `getdockertag()`.

The current IR records only environment text plus literal/nonliteral
provenance. That cannot distinguish an unquoted Groovy expression from a
double-quoted GString. Environment resolution is also recomputed by consumers,
while Jenkins evaluates each RHS once per scope. Preamble functions currently
enter the Groovy interpreter only for hosted `script {}` bodies.

## Required design

Before implementation, specify and test:

- distinct literal, GString and expression provenance at pipeline and stage
  environment scopes without changing existing quote semantics;
- deterministic source-order, once-per-scope evaluation against the environment
  visible before that Declarative block, including Jenkins-provided values;
- top-level helper registration by name and arity for this phase;
- an effect-free environment evaluator: hosted steps, closures with effects,
  assignments outside the owned scope, non-scalar results and unsupported calls
  must fail closed before workspace effects;
- typed diagnostics and precedence for parse, lookup, arity, evaluation and
  coercion failures; and
- caching/lifetime rules for stage entry, retries, parallel branches and post
  conditions so a value is neither reevaluated nor leaked across scopes.

Acceptance requires direct Jenkins controls for missing and supplied ambient
branch values, slash replacement, build ID selection, eager timing, sibling
declaration invisibility and registry preservation. Focused tests and hostile
mutants must kill expression-as-GString, constant-return, lazy evaluation,
double evaluation, sibling/overlay leakage, step execution and unsupported
result coercion. Only then may a successor re-open the exact FG-259 candidate,
add its allowlist row, and run the fenced corpus lane.

## Implemented boundary

`EnvironmentBinding` now carries one of `EnvironmentLiteral`,
`EnvironmentGString`, or `EnvironmentExpression` at pipeline and stage scope.
The parser preserves compact and semicolon-delimited RHS boundaries. Literal
and quoted values retain the previous quote semantics, including the
left-to-right quoted resolver and empty text for an absent quoted name.

Expression preflight follows only helpers reachable from expression RHS values.
It admits a deliberately total scalar subset: literals, GStrings, nullable
direct `env.NAME` reads only through GString coercion, concatenation with a
guaranteed string operand, exact-arity helper calls, and nonempty literal,
non-expanding `String.replace`. Containers, assignments, closures, control
flow, hosted steps, recursion, unknown calls or methods, ambiguous signatures,
unsafe coercions, and non-scalar returns refuse before Fogell changes a
workspace. Helper depth, analysis work, derived-value amplification, and
constant text all have explicit bounds. Failures are structured records with
typed `Parse`, `Lookup`, `Arity`, `Evaluation`, and `Coercion` classes; bindings
are checked in source order, so the first failing RHS owns the diagnostic.

Expression RHS values in a scope read one immutable pre-block snapshot; legacy
quoted GStrings retain Jenkins' measured left-to-right sibling resolver.
Pipeline values resolve once per build. Stage values use a thread-safe `Lazy`
cache keyed by source position and name, inherit their enclosing stage scopes,
and are shared by condition, step, retry, parallel and post consumers; a new
build receives a new cache. Tests invoke concurrent and repeat consumers
through an instrumented evaluator, prove nested inheritance, distinguish two
stages, and prove the next build evaluates again.

## Two-engine controls

Three direct controls are PROVEN Tier 1 on Jenkins 2.568.1 and Fogell:

- `environment-helper-missing`: the candidate-exact helper and declarations,
  followed by a late overlay, print
  `tag=null.1 registry=varunpalekar1/php-test branch=late/poison id=99`;
- `environment-helper-sibling`: sibling branch/build-ID declarations remain
  invisible to the unquoted expression while a quoted copy sees the earlier
  sibling through Declarative's left-to-right resolver; the tag stays `null.1`;
  and
- `environment-helper-scm`: the SCM wrapper supplies
  `origin/case/environment-helper-scm` and build ID `1`, producing
  `origin.case.environment-helper-scm.1` and preserving the registry.

These receipts directly cover missing and supplied ambient branches, slash
replacement, build-ID selection, eager timing, sibling invisibility, and
registry preservation. Focused tests additionally pin quote compatibility,
effect refusal before filesystem changes, failure precedence, reachable-helper
selection, and once-per-scope lifetime. FG-261 may therefore reconsider the
exact digest-bound FG-259 candidate through the fenced corpus lane.
