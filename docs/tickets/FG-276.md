# Outbox relay, `build.finished` webhook, and `mail` as a fenced effect

Priority: **P2**

Verb: **notify** on build completion (webhook, mail).

Status: **TODO**. Filed 2026-09-10 by the Track 4 re-cut (`adr/0009`). FG-053c
is SUPERSEDED by this row: triggers are recorded, never fired, per the ADR.

## Demand

The `mail` step, `emailext` and `triggers { }` rows of [FG-263](FG-263.md)'s
table (a substring count of 25 for `mail` was withdrawn the same day). Most
`mail` calls sit inside `post { failure }`, so the unlock is conditional on the
failure path being reached; `emailext` is refused by name below and unlocks
nothing. A single-build differential cannot observe a trigger. The webhook is
operator value, not corpus value, and is ranked as such. The 2026-09-10 code
read found six insert sites into `outbox` in `Store.fs`: `publishLockedTerminal`
(`build.terminal`), `AdmitBuild` (`build.admitted`), and `ActivateRestore`,
`ClaimNextExecution`, `RequeueExpiredLocalAttempts` and `RequireReconciliation`
(all `build.reconciliation_required`), plus the retry trigger in migrations
0004 and 0011; the table is read by nothing but a count.

## Design

- The `build.terminal` row `publishLockedTerminal` already writes in the
  terminal transaction is the message; no new topic is added. The relay
  consumes it.
- New `OutboxRelay` hosted service in `Fogell.Controller.Host`, a sibling of
  `LocalWorker` iterating `organization_work_roots` the same way, delivering
  unpublished rows oldest-first and setting `published_at`. Sink v1:
  `FOGELL_WEBHOOK_URL` plus `FOGELL_WEBHOOK_SECRET_FILE` (the FG-251 token-file
  reader), HMAC-SHA256 over the body in `Fogell-Signature`, `Fogell-Delivery-Id`
  = outbox id, at-least-once, idempotent at the receiver. Under the fence the
  URL must be loopback; the relay refuses otherwise.
- `mail` becomes a fenced external effect: `PrepareEffect("mail:<stage>:<idx>")`,
  SMTP to `FOGELL_SMTP_URL`, `AdvanceEffect`. Receipted against a loopback
  SMTP sink written in F# under `tools/`; with no sink configured both engines
  fail the step identically, which is itself receiptable. `emailext` and
  `slackSend` refuse by name.
- `triggers { }`: persisted as a project property row (kind plus raw source),
  never fired; the option descriptor records it as a job property.

## Acceptance

A tier-1 receipt for a corpus file whose `post { failure { mail … } }` is
reached, with a loopback SMTP sink on both engines and the message bytes
compared; the relay proven at-least-once by a crash-lane case (kill between
delivery and `published_at`, observe exactly one redelivery with the same
delivery id); a hand-written case proving `emailext` refuses by name.

## Jenkins probe first

Measure on luigi: the exact SMTP envelope and headers the pinned mailer plugin
sends for `mail to:, subject:, body:`; the console line on send; and the
failure text with no SMTP host configured.
