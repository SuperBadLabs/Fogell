# FG-239 — A stage-level `timeout` with an unusable unit fails the build
without rejecting the model, so the pipeline `post` still runs

Status: **PARTIAL — implemented and tested with FG-240 in one change;
exact-head hosted gate and review coverage are outstanding** (P2). Filed
2026-09-03 from the FG-123 round-4 pre-push verifier's note, reproduced on
both engines before filing.

## Measured

Jenkins 2.568.1 (a transient job on the pinned lab, 2026-09-03, deleted
after the run), with

```groovy
pipeline {
    agent any
    stages {
        stage('one') {
            options { timeout(time: 1, unit: 'NOPE') }
            steps { sh 'touch stage-marker.txt' }
        }
    }
    post { always { sh 'touch post-marker.txt'; sh 'ls' } }
}
```

refuses the MODEL: `WorkflowScript: 5: Expecting "class
java.util.concurrent.TimeUnit" for parameter "unit" but got "NOPE" of type
class java.lang.String instead @ line 5, column 46.`, `Finished: FAILURE`,
and nothing runs — no `[Pipeline] Start`, no stage, no `post`, no marker.

Fogell at `origin/main` (`24262d76`), the same Jenkinsfile through
`Fogell.Run.Host`: `completed: failure`, then `+ touch post-marker.txt`, and
`post-marker.txt` exists in the workspace. On a local SCM-defined pipeline
(the FG-123 `FogellSide.runScm` harness) the trace's disposition is
`ExecutedOrRuntime`, not `RefusedBeforeExecution`: the checkout runs and
narrates, then the `post` runs, and the workspace holds `Jenkinsfile`,
`post-marker.txt` and `.git`.

So Fogell performs an effect Jenkins never performs, under a Jenkinsfile
Jenkins refuses to compile, and reports the build as executed rather than
refused. A plain (non-SCM) differential case would DIVERGE on disposition
and on the workspace hash; it is deliberately not added to
`differential/cases/`, as FG-126's probe was not, because it diverges by
design until fixed.

## Why

`runStage` in `src/Fogell.Differential/WalkerOrchestration.fs` asks
`deadlineFromOptions stage.Options inherited` and, on an error, emits
`ERROR: stage '…' declares an unusable timeout option: …`, sets
`ctx.Failed` and sinks `Failure` — but does not mark the model rejected. The
pipeline-level branch in `Fogell.fs` sets `compileRejected` for the same
error ("FG-121 fixed precisely this for the timestamps and ansiColor
refusals and this one was left behind — the same defect, in the same block,
one branch down", its comment says), and the pipeline `post` guard tests
`compileRejected`; the stage-level branch was left behind a second time. The
stage-level check also runs only when the walk reaches the stage, after any
SCM checkout, where Jenkins refuses before anything runs.

## What would close it

Validate every stage's `options { timeout(...) }` unit (and `time`) beside
the other compile-shaped option checks in `Fogell.fs`, before the SCM block,
so a bad stage unit is a refusal with `compileRejected` set and no checkout,
stage or `post` effect — the FG-121 / FG-123 placement — while the stage's
own deadline computation stays where it is. Then: a test that the stage
shape refuses with empty output and an empty workspace on both the plain and
SCM paths (FG-123's harness), and a plain differential case sealed as a
matching refusal on both engines (result FAILURE, empty workspace; the
wording is not compared).

## Implemented boundary

In `src/Fogell.Differential/Fogell.fs`, beside the other compile-shaped
option checks (the stage `retry` count, `unstable`, `skipStagesAfterUnstable`,
`parallelsAlwaysFailFast`, `timestamps`) and before the SCM block, every
`timeout` option at pipeline level and on every flattened stage (nested and
parallel children included) is parsed with `WalkerRules.timeoutMs` — the
same rule the deadline computation uses, so the two cannot disagree — and
the first error refuses the model: `ERROR: pipeline declares an unusable
timeout option: …` or `ERROR: stage '<name>' declares an unusable timeout
option: …`, with `compileRejected` set, so no checkout, stage or `post`
runs and the disposition is `RefusedBeforeExecution`. The deadline
computation (`deadlineFromOptions`) keeps its place after the checkout,
where its `Timeout set to expire` banner is measured to print, and a
rejected model computes no deadline so the error is not emitted twice; the
walk's own stage-level refusal remains as a defence it can no longer reach
for an unusable argument.

Tests (`FG-239 FG-240 timeout unit refusals`, 6/6; Differential 349/349): a
stage-level unusable unit and a non-numeric time refuse with empty output,
an empty workspace and no `post` marker; a nested stage's unit is found; the
pipeline-level unit still refuses on a plain pipeline; both levels refuse
BEFORE the checkout on a local SCM pipeline (FG-123's harness: empty output,
no `.git`, no Jenkinsfile); and valid units at both levels still run and
announce their budgets exactly once.

Proof of failure: with the early refusal blinded (its match arm made a
no-op) and the tree rebuilt, exactly four of the six tests fail — the
stage-level shapes, the nested stage, and both SCM-path cases — while the
plain pipeline-level case still passes (the late deadline branch still
refuses it there, as before this ticket) and the valid-units control passes.
The clean tree was restored and rebuilt afterwards.

No differential case is added: a compile-shaped refusal seals no receipt
(FG-129), so the "plain differential case sealed as a matching refusal"
named above is not obtainable and the tests carry the claim.
