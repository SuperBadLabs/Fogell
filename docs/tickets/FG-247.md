## `ljpengelen_jenkinsfile`, read to the end

127 lines. Top-level assignments of `additionalBuildArgs` and
`dokkuHostname` conditioned on `env.BRANCH_NAME` (preamble), `agent none`,
`options { ansiColor("xterm") }`, `triggers { cron(...) }`, five stages.
The FIRST stage, `Test back end`, declares
`agent { dockerfile { additionalBuildArgs ...; filename
"back-end/dockerfiles/ci/Dockerfile"; label "webapps" } }` and one step,
`sh "cd back-end && bin/ci"`. Two facts decide it:

- **Fogell ignores the stage agent.** `AgentDockerfile` is parsed for
  admission; only `AgentUnmodelled` is refused by the differential's
  execution preflight (`src/Fogell.Differential/Fogell.fs`), and nothing in
  `Fogell.Execution` reads the agent kind. `Fogell.Run.Host` on the file
  prints `completed: failure`, `+ cd back-end`,
  `${WORKSPACE}@tmp/durable-<id>/script.sh.copy: 1: cd: can't cd to
  back-end`, then four `Stage "…" skipped due to earlier failure(s)` lines.
- **Jenkins never reaches the `cd`.** The lab has one node, `Built-In
  Node`, labelled `built-in` only. A hand-written probe job (not the corpus
  file; `agent none`, one stage with the same `dockerfile { … label
  "webapps" }` agent and `sh "echo fg247-probe"`) was created, built and
  read after 12 s: console `Started by user unknown or anonymous`,
  `[Pipeline] Start of Pipeline`, `[Pipeline] stage`, `[Pipeline] { (Test
  back end)`, `[Pipeline] node`; `building:true, result:null`; queue item
  `part of fg247-probe-label #1` with `why: ‘Jenkins’ doesn’t have label
  ‘webapps’`. The queue item was cancelled, the build stopped and the job
  deleted (queue empty, job 404). The differential harness polls a build for
  five minutes and then reports `jenkins build did not reach a terminal
  state`; it does not cancel the queued item.

So the file diverges by construction — Fogell runs a stage Jenkins cannot
allocate — and the divergence is not this file's: it is the engine
executing under an agent it does not model. It was NOT put on the allowlist
and NOT run through the lane, because a lane run would have executed the
Fogell side against a Jenkins side that never starts, left a queued build
on the oracle, and produced no receipt either way. The engine question it
raises — should execution refuse (or model) a `label`/`docker`/`dockerfile`
agent rather than run under it — is filed here as the ticket's one open
item, not fixed: the eight `label`-agent files and five docker-agent files
in the table above are the pool it gates.

## What these prove and do not

Each receipt proves: the declarative walk through a literal `environment`
to the first stage; `echo`; the `-x` trace of a one-line body; dash's
`not found` naming `$0` as `script.sh.copy` through the merged stream; a
non-zero exit failing the step, the stage and the build; and three or four
later stages — every one under a `when` — SKIPPED with Jenkins' own
sentence in Jenkins' own order. They do NOT prove anything about the
pipelines' intended builds (`gradlew`, `docker.build`, `kubernetesDeploy`
and the `input` all live in a repository and a cluster neither engine has),
and they do not exercise `when { branch }` evaluation, because Declarative
skips a stage after an earlier failure before its `when` is read. The
allowlist rows say "a failure receipt on an empty workspace" for that
reason, and the board row says the same.
