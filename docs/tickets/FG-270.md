# FG-270 — Persistent Luigi deployment and bounded adversarial pilot

Status: DONE. Milestone: M4. Depends on: FG-269.

Owner: primary agent (deployment and integration), proof subagent (bounded fault
driver), client/source subagent (independent plan/evidence review). The user
requested deployment on Luigi and a sustained adversarial campaign. The
[versioned runbook](../runbooks/luigi-campaign.md) owns the predeclared boundaries.

Problem: local acceptance does not establish that a persistent deployment works
on Luigi, tolerates declared operational faults or leaves existing services
untouched.

Scope: provision an owned persistent rootless controller/worker plus separate
PostgreSQL container; bind the authenticated API to `127.0.0.1:46206`; run 100
real Domain correction loops, bounded load/fault controls and paired recovery;
leave the measured service available with operator handoff instructions.

Version qualification is explicit: complete 100 baseline loops on v1, retain
its strict adversarial failures, gate and install the narrow typed-cap diagnostic
correction as immutable v2, refresh campaign identities, and preserve the measured v2 controller-crash
diagnostic failure. Gate and install the expired-lease diagnostic correction as
v3; pass its full adversarial matrix and paired recovery, then run 30 separate
v3 qualification loops. Recovery precedes
further retention so the original loop-100 corrected artifact remains available.
Measurements from earlier versions are not attributed to the final release.

Acceptance:

- Declare exact images/binaries/source/tool/cache identities, SDK `10.0.301`,
  effective CPU/memory/process limits, writable mounts, storage reserve, workload,
  timing thresholds and finite fault matrix before measurement.
- Preserve `ctrl`, `ag1`, `jenkins-bench`, `mcloving-faceoff2` and `jenkins-lab`:
  exact full IDs and `StartedAt` unchanged before/after; no mutation targets
  outside recorded owned service identities and paths.
- Verify 100 complete correction loops, 200 distinct real Domain admissions,
  all 41 tests per run, bound identities/artifacts/typed failures and corrected
  success. Report uncensored p50/p95 and all unexpected results. Meet the profile's
  240-second loop p95, 120-second build and 5,400-second campaign limits.
- Qualify deployed v3 with its own 30 complete correction loops/60 builds and
  six retention phases under the same thresholds. Report its p50/p95 separately;
  do not pool versions or convert a captured v1 adversarial failure into a pass.
- Complete twenty bounded retention phases and record physical filesystem/DB
  observations alongside logical accounting. A disk guard is not a hard quota;
  no shared-host exhaustion test or unsupported quota claim.
- Pass the declared finite invalid-input, authentication, idempotency, load,
  cancellation and owned-controller interruption controls. Preserve uncertain
  effects for reconciliation; never fabricate success or replay automatically.
- On v3 require named timeout/output-cap/artifact-limit failures, no published
  rejected artifact and bounded ENOSPC in the verified 256 MiB container scratch
  tmpfs followed by healthy controls. No host/state disk fill.
- Pass paired restore within 120 seconds from the defined restore boundary,
  complete row/sequence/schema and state comparison, corrupted-backup controls,
  stale-authority rejection, original artifact access and a fresh correction pair.
  Attribute the retained artifact to v1 and the fresh restored pair to v3.
  Reconcile the source probe only after that proof succeeds, using the existing
  fenced Store operation, then restore the original persistent service.
- Independently verify final evidence and leave one healthy persistent service
  with endpoint/token-file usage, exact identities, restart procedure, state and
  evidence locations. Retain failed attempts and any partial/censored campaigns.

Evidence: [Luigi campaign report](../../evidence/20260923-luigi/README.md) and
[passing offline aggregate](../../evidence/20260923-luigi/summary.json), independently
reverified by the proof agent. V1 completed 100 loops; final v3 completed 30 loops,
all 21 fault scenarios and paired recovery in 40.18 seconds. V3 actionable-diagnostic
p95 was 13.60 seconds and correction-loop p95 28.58 seconds. The full release gate
passed 1,387 tests and all required proofs. Typed resource-limit and expired-lease
reconciliation gaps found during the campaign were fixed; both failed intermediate
campaigns and the setup failure remain visible in the evidence. The persistent
service is healthy, both services enabled, and all five protected containers retain
their original identities and start times. This ticket does
not expand Jenkins compatibility, certify untrusted workload isolation or claim
unmeasured reboot/power-loss durability.
