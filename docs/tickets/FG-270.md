# Credentials under the controller: RLS table, routes, least-privilege file in argv

Priority: **P1**

Verb: **bind** a credential in a controller-run build.

Status: **TODO**. Filed 2026-09-10 by the Track 4 re-cut (`adr/0009`).

## Demand

The `withCredentials(` row of [FG-263](FG-263.md)'s table. The three binding kinds
(`string`, `usernamePassword`, `file`) are implemented and receipted in the
differential lane, where the store comes from `FOGELL_CREDENTIALS[_FILE]`. The
2026-09-10 code read found that the controller's worker
(`src/Fogell.Controller.Host/Worker.fs`, the launch arm) calls
`Environment.Clear()` and never sets either variable, so under the controller
`FogellSide.credentialStore()` is always empty and every `withCredentials`
fails closed on "credential id not found". The capability exists; the
controller path does not reach it.

## Design

- Migration `0013_credentials.sql`: `(organization_id, id, kind, material bytea, file_name, created_at)`,
  `kind IN ('text','userpass','file')`, forced RLS, immutable rows (replace is
  delete + insert in one transaction so no build sees a half-rotated value).
  Encryption at rest is a separate ticket; the threat model already states the
  local worker and builds are one mutually trusting domain, and this ticket
  says so rather than bolting on a cipher without a key-management story.
- Routes: `PUT …/organizations/{org}/credentials/{id}` (JSON
  `{kind, value_base64, file_name?}`), `DELETE`, `GET …/credentials` returning
  ids and kinds only, never material.
- At claim time the worker statically extracts referenced ids from the parsed
  pipeline (`Credentials.parseRequests` over `withCredentials` steps plus
  `credentialsId:` on `git`/`checkout`; complete for the executed surface
  because `withCredentials` inside `script { }` is refused), selects only
  those rows, writes them in the existing `credentialStoreFromSpec` wire
  format to `<stateRoot>/_secrets/<attempt>-<fence>.credentials` at mode 0600,
  passes `--credentials <path>` in argv, and deletes the file with the same
  discipline as the event file after terminal publication.
- `runPersisted` gains a `credentials` argument; the environment read in
  `Fogell.fs` stays only for `tools/Fogell.Differential.Cli`.

## Acceptance

A `withCredentials` corpus file obtains a tier-1 receipt THROUGH
`Fogell.Controller.Host` (submit route, credentials table) rather than through
the CLI; `scripts/prove-control-env-isolation.sh` still passes; the
credentials file is proven absent after terminal publication and after a
SIGKILL of the worker mid-build; a build referencing an id the organisation
does not hold refuses by name before any effect.

## Jenkins probe first

None new; the binding semantics are already receipted. Re-run the existing
credential cases through the controller path.
