# FG-224 — Runnable, restart-discovered controller

Status: **PARTIAL**. The implementation and local acceptance are complete; a
fresh exact-head hosted gate, exact-head Copilot/Codex review coverage,
publication, and merge remain owner-controlled.

## Problem

Fogell had durable admission, scheduling, execution, logs, and an HTTP router,
but no production process connected them. The API discarded the accepted
Jenkinsfile bytes, the runner was reachable only as a standalone tool, and a
terminal attempt did not atomically become the build status returned by the API.
The result was an engine that could be tested component by component but could
not accept and complete a build as one service.

## Closed vertical slice

`Fogell.Controller.Host` now performs migration and database-role validation
before binding, serves health and authenticated API routes, and runs one bounded
local Linux worker. Admission stores the exact source bytes, a SHA-256 digest,
and a versioned fingerprint binding source plus controller-owned placement.
Concurrent replays of one idempotency key converge on that immutable definition;
source or placement substitution is refused.

Before durable admission, the HTTP boundary runs the same deterministic
execution preflight as `Fogell.Run.Host`. A pipeline that parses but exceeds
Fogell's execution capability returns a stable 422 refusal without allocating a
build number or binding the caller's idempotency key.

The local worker discovers organization UUID roots after restart, claims one
whole-pipeline execution unit, materializes the exact durable source, and starts
`Fogell.Run.Host` in its own process group with a cleared environment. The child
sets a Linux parent-death signal, writes machine log frames outside the workspace,
and retains its existing journal as terminal authority. Build processes receive
a private HOME derived from stable job/build identity, so restart converges on
the same directory while distinct builds cannot share mutable HOME state. The
raw configured state root must be fully qualified before it is normalized, so a
relative path cannot silently bind durability to the controller's current
directory. Startup also performs a create-new, write, durable-flush, and cleanup
probe inside that root before readiness; an existing root that the service
identity cannot write is refused without replacing user data. Run-host admission
asks the Linux kernel whether the effective service identity may execute the
configured file, rather than accepting an execute bit from an inapplicable owner,
group, or other permission class. Every engine-created
inner `setsid` step group is identity-bound by Linux pid plus process start ticks
and registered before user code is released. A Run.Host-liveness EOF watchdog
and the controller's combined outer/registered-inner cleanup reap descendants,
including after the inner leader exits, without authorizing a signal to a reused
pid. The controller renews its fenced lease and polls cancellation. After an
unforced natural child exit it atomically rolls attempt, node, build, terminal
event, and outbox to one result. Starting
execution refreshes the lease in the same transaction;
queued cancellation cannot launch a child, and cancellation races with terminal
publication are serialized to one durable outcome. Diagnostic drains and event
frame tails are bounded even when descendants retain inherited file descriptors.
Expired never-started offers may be reclaimed, while expired started work enters
reconciliation instead of risking duplicate effects. A forced stop after child
launch also enters reconciliation even after every registered process group is
proved extinct: process extinction cannot prove whether an external effect or
journal write completed. Only an unforced natural `Run.Host` exit may publish its
journal terminal result.

Progressive output is masked, leak-screened, assigned FIFO order under the
walker's output lock, and delivered by one publisher outside that lock. Slow or
reentrant callbacks cannot freeze concurrent emitters. The first callback
failure is typed, sticky, and never retried; `Run.Host` withholds terminal journal
truth so the controller requires reconciliation instead of converting transport
failure into build semantics. Attempt-local frame sequences remain the
idempotency key for publication, while PostgreSQL atomically allocates a separate
build-wide sequence for the public log cursor. Retries and parallel attempts may
therefore both publish local sequence zero without a page limit splitting the
tie or `next_sequence` skipping either chunk. Publishers lock the canonical
lineage before the duplicate check, so concurrent replay of one local frame is
a true database no-op and cannot burn a build cursor. Publication locks attempt,
node, and build rows in that order before accepting the requested build, closing
a concurrent mutable-node lineage substitution window.

Forced tenant RLS remains the data boundary. The only global runtime relation is
`organization_work_roots`, containing UUIDs and no tenant slug or record; every
claim after discovery still opens a transaction-local tenant scope. A queued
legacy multi-node build, missing/corrupt durable definition, or conflicting
state-root materialization cannot poison later tenant work. Invalid durable
claims are quarantined inside FIFO arbitration; a materialization failure after
an offer uses that offer's owner and fence to move the same attempt, node, and
build to `reconciliation_required` before the worker scans again. Later work
therefore remains claimable instead of waiting behind a repeatedly requeued
poisoned admission.

A forward-only repair migration also backfills work roots missed when a
preexisting organization crossed migration 0006 under a normal NOBYPASSRLS
schema owner. It temporarily lowers FORCE RLS only inside the migration
transaction, inserts every missing UUID idempotently, and restores ENABLE plus
FORCE before commit; the checksum-pinned historical migration remains unchanged.

## Acceptance

`scripts/prove-runnable-controller.sh` uses a fresh PostgreSQL database and a real
`NOSUPERUSER NOBYPASSRLS` runtime role. It proves weak-token refusal before bind,
least-privilege startup, durable queued admission discovered by a restarted
controller process, real whole-pipeline execution, progressive output through
the HTTP API before terminal state, exact-once output after terminal state,
decoded-body overflow refusal for an actual chunked request, atomic terminal
roll-up, exact idempotent replay, source-substitution conflict, request placement
denial, and a repeated parseable-but-execution-unsupported submission that
creates no build and leaves its idempotency key available to a supported source.
It also proves durable build-number metadata, terminal cancellation conflict,
immutable definition enforcement, terminal-only event-file cleanup, and a
graceful-shutdown transition carrying the exact reconciliation reason through
the event, outbox, and retained byte-exact recovery file. Configured
token/password text is absent from host logs. Unsafe worker poll/lease
combinations are refused at startup. The hosted gate runs this proof against its
PostgreSQL service.

Exact-tree HeMan acceptance on fresh databases:

- Controller API: 28/28 passed;
- Differential: 265/265 passed;
- Execution: 100/100 passed; and
- runnable-controller proof: PASS.

The operator contract is in `docs/runbooks/controller-host.md`. The authoritative
locked repository gate also passes all 884 main-suite tests and every blocking

recorded at publication rather than predicted here.

## Boundary

This closes a single-process, capacity-one Linux controller. Remote agents,
mTLS agent protocol, HA leader election, packaging, queue saturation policy, and
automatic replay of an effect interrupted mid-step remain outside the ticket.
An interrupted journal without a terminal record still enters reconciliation;
the controller never treats process exit or stdout as proof of build success.
