# FG-224 — Runnable, restart-discovered controller

Status: **PARTIAL**. The implementation and local acceptance are complete; a
fresh exact-head hosted gate, exact-head Copilot/Codex review coverage,
publication, and merge remain owner-controlled.

## Problem

Fogell had durable admission, scheduling, execution, logs, and an HTTP router,
but no production process connected them. The API discarded the accepted
Jenkinsfile bytes, the runner was reachable only as a standalone tool, and a
terminal attempt did not atomically become the build status returned by the API.
The result was an engine that could be tested component by component but could
not accept and complete a build as one service.

## Closed vertical slice

`Fogell.Controller.Host` now performs migration and database-role validation
before binding, serves health and authenticated API routes, and runs one bounded
local Linux worker. Admission stores the exact source bytes, a SHA-256 digest,
and a versioned fingerprint binding source plus controller-owned placement.
Concurrent replays of one idempotency key converge on that immutable definition;
source or placement substitution is refused.

Before decoding, parsing, or applying the current release's execution rules, the
HTTP boundary probes an existing immutable admission using the raw source bytes
and controller-owned placement. An exact replay of even legacy malformed bytes
therefore preserves the original 200 response, while changed malformed bytes for
the bound key return the durable 409 conflict rather than a parser classification.
A probe miss creates nothing and leaves `AdmitBuild` as the one-key race arbiter.
Only a fresh request then runs strict UTF-8 decoding, parsing, and the same
deterministic persisted-execution preflight as `Fogell.Run.Host`. In addition to
the generic execution boundary, the preflight rejects duplicate flattened stage
names and stage names containing journal record delimiters before allocating a
build number or binding an idempotency key. A pipeline that parses but exceeds
Fogell's execution capability returns a stable 422 refusal without allocating a
build number or binding the caller's idempotency key.

The local worker discovers organization UUID roots after restart, claims one
whole-pipeline execution unit, materializes the exact durable source, and starts
`Fogell.Run.Host` in its own process group with a cleared environment. The child
sets a Linux parent-death signal, writes machine log frames outside the workspace,
and retains its existing journal as terminal authority. Build processes receive
a private HOME derived from stable job/build identity, so restart converges on
the same directory while distinct builds cannot share mutable HOME state. The
raw configured state root must be fully qualified before it is normalized, so a
relative path cannot silently bind durability to the controller's current
directory. Startup also performs a create-new, write, durable-flush, and cleanup
probe inside that root before readiness; an existing root that the service
identity cannot write is refused without replacing user data. Run-host admission
asks the Linux kernel whether the effective service identity may execute the
configured file, rather than accepting an execute bit from an inapplicable owner,
group, or other permission class. Every engine-created
inner `setsid` step group is identity-bound by Linux pid plus process start ticks
and registered before user code is released. The controller also captures the
outer Run.Host launcher's birth identity immediately after start. Leader and
process-group signals require that identity still to match and the observed group
to belong to it; if the identity is absent or changed while the numeric group is
populated, cleanup fails closed instead of signalling a possible PID/PGID reuse.
A Run.Host-liveness EOF watchdog and the controller's combined
outer/registered-inner cleanup reap descendants, including after the inner leader
exits. The controller renews its fenced lease and polls cancellation. After an
unforced natural child exit it atomically rolls attempt, node, build, terminal
event, and outbox to one result. Starting
execution refreshes the lease in the same transaction;
queued cancellation cannot launch a child, and cancellation races with terminal
publication are serialized to one durable outcome. Diagnostic drains and event
frame tails are bounded even when descendants retain inherited file descriptors.
Expired never-started offers may be reclaimed, while expired started work enters
reconciliation instead of risking duplicate effects. A forced stop after child
launch also enters reconciliation even after every registered process group is
proved extinct: process extinction cannot prove whether an external effect or
journal write completed. Only an unforced natural `Run.Host` exit may publish its
journal terminal result.

State-root availability remains a runtime condition, not a startup memory. The
readiness route evaluates database reachability, runtime capabilities, launcher
availability, and then the state-root probe lazily in that order. The full
create-new, write, durable-flush, unlink, and verified-cleanup probe is protected
by a lock and cached for at most one second, bounding durable I/O under concurrent
health traffic while detecting a missing or newly unwritable root continuously.
The worker uses its own instance of the same cache before claiming. After an
offer it always forces a fresh probe before materialization; a failed fresh probe
fenced-requeues the still-unstarted attempt instead of recreating a missing root
or quarantining known storage unavailability as a corrupt definition. A cached
success can therefore permit at most an offer; materialization still requires a
fresh point-in-time probe.

Progressive output is masked, leak-screened, assigned FIFO order under the
walker's output lock, and delivered by one publisher outside that lock. Slow or
reentrant callbacks cannot freeze concurrent emitters. The first callback
failure is typed, sticky, and never retried; `Run.Host` withholds terminal journal
truth so the controller requires reconciliation instead of converting transport
failure into build semantics. Attempt-local frame sequences remain the
idempotency key for publication, while PostgreSQL atomically allocates a separate
build-wide sequence for the public log cursor. Retries and parallel attempts may
therefore both publish local sequence zero without a page limit splitting the
tie or `next_sequence` skipping either chunk. Publishers lock the canonical
lineage before the duplicate check, so concurrent replay of one local frame is
a true database no-op and cannot burn a build cursor. Publication locks attempt,
node, and build rows in that order before accepting the requested build, closing
a concurrent mutable-node lineage substitution window.

Forced tenant RLS remains the data boundary. The only global runtime relation is
`organization_work_roots`, containing UUIDs and no tenant slug or record; every
claim after discovery still opens a transaction-local tenant scope. A queued
legacy multi-node build, missing/corrupt durable definition, or conflicting
state-root materialization cannot poison later tenant work. Invalid durable
claims are quarantined inside FIFO arbitration; a materialization failure after
an offer uses that offer's owner and fence to move the same attempt, node, and
build to `reconciliation_required` before the worker scans again. Later work
therefore remains claimable instead of waiting behind a repeatedly requeued
poisoned admission. Definition quarantine moves attempt → node → build and
publishes exactly one `attempt.reconciliation_required` event plus one
`build.reconciliation_required` outbox row in the same transaction. Both
records carry the definition-specific reason, so public notification cannot
commit without the state transition it explains.

A forward-only repair migration also backfills work roots missed when a
preexisting organization crossed migration 0006 under a normal NOBYPASSRLS
schema owner. It temporarily lowers FORCE RLS only inside the migration
transaction, inserts every missing UUID idempotently, and restores ENABLE plus
FORCE before commit; the checksum-pinned historical migration remains unchanged.

Fleet restore now keeps forced RLS enabled while iterating the global UUID root
registry with a transaction-local tenant context. The epoch bump, attempt → node
→ build reconciliation roll-up, and one reasoned event/outbox pair per moved
attempt commit atomically, including under a real NOBYPASSRLS maintenance role.
Fresh attempt creation shares the epoch lock in Store, while forward-only
migration 0010 enforces the same rule for every direct SQL creator: an attempt
whose restore epoch is stale is rejected by PostgreSQL before insertion. Both
sides of the insert/restore race are deterministic—an insert that commits first
is reconciled by restore; an insert that waits is born in the new epoch.

## Review 23 closure

- Codex finding `3866556745` is closed by identity-binding outer Run.Host cleanup
  to the captured Linux process start time and by a regression proving that a
  reused PID/PGID receives neither TERM nor KILL; ambiguous group presence returns
  `StatusUncertain`.
- Codex finding `3866556752` is closed by resolving the durable raw-byte
  idempotency binding before UTF-8 decoding and parsing. Exact malformed legacy
  bytes replay as 200, changed malformed or invalid bytes conflict as 409, fresh
  invalid input retains its 400/422 classification, and a concurrent mixed-source
  race still creates exactly one build.

## Review 24 closure

- Codex finding `3866743417` is closed by giving invalid-definition FIFO
  quarantine atomic publication parity with every other reconciliation path.
  Missing definitions, legacy multi-node definitions, and digest mismatches each
  move attempt → node → build to `reconciliation_required` and emit exactly one
  reasoned event/outbox pair in the same transaction; concurrent and later
  claimers neither duplicate the pair nor leave the poison at the head of FIFO.
- The adjacent lease-expiry audit is also closed. Expired `accepted`, `running`,
  `finalizing`, and `cancelling` attempts atomically roll attempt → node → build
  to reconciliation and emit exactly one event/outbox pair carrying
  `lease_expired`. An expired pre-launch `offered` attempt is safely returned to
  `queued` and emits neither record; repeated scans publish nothing further.

## Review 25 closure

- Codex finding `3866957698` is closed by making the active child poll wait
  cancellation-aware without letting cancellation escape as a generic worker
  failure. Shutdown interrupts even a configured 60-second poll promptly, sets
  the existing interrupted disposition, performs the ordinary identity-bound
  cleanup, and durably records `controller_shutdown` reconciliation.
- Codex finding `3866957703` is closed by extending state-root readiness beyond
  startup. `/health/ready` checks database, capabilities, launchers, and state
  root lazily in order; the lock-protected monotonic cache limits the full
  create/write/flush/unlink probe to once per second and recovers on the next
  cadence boundary. The worker uses cached readiness before claiming and a
  forced fresh probe after every offer but before materialization. Fresh failure
  fenced-requeues that unstarted offer, so cached readiness cannot authorize
  execution after the root disappears or becomes unwritable.

## Review 26 closure

- Codex finding `3867130539` is closed by giving both post-offer dependency-loss
  paths the same immediate fenced recovery. The worker checks launchers first and
  only performs the fresh state-root probe when they are available; either
  launcher loss or state-root loss calls `RequeueOwnedAttempt` once before
  logging. The still-unstarted attempt, node, and build return to `queued`
  atomically, the lease owner and expiry are cleared, and no event or outbox row
  is published. The current owner, fence, unexpired lease, and restore epoch must
  still match through the attempt → node → build lock order; the replacement
  claim advances the fence, and a concurrent cancellation request remains set for
  that replacement to observe. Neither path materializes work, begins execution,
  or enters reconciliation.

## Review 27 closure

- Codex finding `3867267809` is closed by requiring a live lease and the current
  restore epoch, in addition to the exact owner and fence, at the
  `RequireReconciliation` attempt-row transition. An expired offered claim
  cannot publish a worker-selected reason and loses atomically to safe lease
  recovery, which returns the attempt, node, and build to `queued` without an
  event or outbox row. A pre-restore claim likewise publishes nothing and leaves
  restore recovery to own the durable disposition. A live current-epoch running
  owner retains the existing atomic reasoned event/outbox reconciliation path.
- Codex finding `3867267816` is closed by treating whitespace-only values as
  missing for every required controller setting. In particular, a whitespace-only
  `FOGELL_LOCAL_TRUST_POOL` now returns the stable required-setting error before
  startup rather than producing a controller whose Store rejects every admission.

## Review 28 closure

- Codex finding `3867404726` is closed by making the post-`BeginExecution`,
  pre-`Process.Start` boundary explicit. All fallible sequence, event-state,
  process-start configuration, and unstarted `Process` setup is prepared before
  launch is attempted. If that setup fails, the worker disposes any partially
  owned process object, invokes one fenced `RequeueOwnedAttempt` before logging,
  and returns the attempt, node, and build to `queued` without reconciliation,
  event, or outbox publication. Once `Process.Start` is attempted, false or
  exceptional launch outcomes retain the conservative reasoned
  `launcher_failed` reconciliation path.

## Review 29 closure

- Codex finding `3867560435` is closed at the final-refresh cancellation race.
  After natural leader exit, verified process extinction, and a complete
  terminal event drain, a cancellation first observed by that final refresh is
  delegated to `PublishTerminal`. The Store arbitrates the build row: a
  cancellation that committed first publishes one `aborted` terminal
  event/outbox pair, while publication that committed first remains terminal.
  Shutdown, lease loss, or an incomplete drain still require reconciliation;
  none is reclassified as a safe terminal publication.

These are local exact-tree closure claims only. Exact-head hosted gates, fresh

## Acceptance

`scripts/prove-runnable-controller.sh` uses a fresh PostgreSQL database and a real
`NOSUPERUSER NOBYPASSRLS` runtime role. It proves weak-token refusal before bind,
least-privilege startup, durable queued admission discovered by a restarted
controller process, real whole-pipeline execution, progressive output through
the HTTP API before terminal state, exact-once output after terminal state,
decoded-body overflow refusal for an actual chunked request, atomic terminal
roll-up, exact idempotent replay, source-substitution conflict, request placement
denial, and a repeated parseable-but-execution-unsupported submission that
creates no build and leaves its idempotency key available to a supported source.
It also proves durable build-number metadata, terminal cancellation conflict,
immutable definition enforcement, terminal-only event-file cleanup, and a
graceful-shutdown transition carrying the exact reconciliation reason through
the event, outbox, and retained byte-exact recovery file. Configured
token/password text is absent from host logs. Unsafe worker poll/lease
combinations are refused at startup. The hosted gate runs this proof against its
PostgreSQL service.

## Boundary

This closes a single-process, capacity-one Linux controller. Remote agents,
mTLS agent protocol, HA leader election, packaging, queue saturation policy, and
automatic replay of an effect interrupted mid-step remain outside the ticket.
An interrupted journal without a terminal record still enters reconciliation;
the controller never treats process exit or stdout as proof of build success.
