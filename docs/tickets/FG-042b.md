# FG-042b — Retrieve archived build artifacts byte-exactly

Status: **DONE**

## Problem

`archiveArtifacts` already copied matched files out of the mutable workspace, but
the controller exposed no way to retrieve those durable bytes. A successful archive
therefore ended at the filesystem boundary and the parent FG-042 remained partial.

## Delivered contract

An authenticated caller can retrieve a known archived relative path at:

```text
GET /api/v1/organizations/{organizationId}/projects/{projectId}/builds/{buildId}/artifacts/{path}
```

Authorization happens before identifier parsing. The controller then uses the store's
build snapshot to prove that the build belongs to the organization and project in the
URL and has reached a terminal status before consulting artifact storage. Guessed
cross-project paths therefore do not bypass the database tenancy boundary, and a
running or reconciliation-required build cannot expose output that may still change.

The artifact path must contain nonempty relative segments and cannot contain `.` or
`..`. On Linux, retrieval resolves the build's durable artifact root, opens the target
read-only with `O_NOFOLLOW`, and verifies the physical path of that already-opened
descriptor remains beneath the build root. The response is copied from that descriptor,
so a pathname swap after validation cannot redirect the response. Missing files,
directories, and symlink escapes return no artifact bytes.

A successful response has `application/octet-stream`, the descriptor's exact byte
length, `X-Content-Type-Options: nosniff`, and an attachment filename. The URL is stable
for the durable build UUID and archived relative path.

## Acceptance evidence

- The Controller API suite archives a payload containing NUL, `0xff`, CR, and LF through
  the production `Publish.archive` and `ArtifactStore`, downloads it twice, and compares
  the exact bytes. The same test covers content headers, missing paths, cross-project
  ownership, pre-terminal refusal, unauthenticated access, and a final-symlink escape.
- A separate boundary test rejects empty, absolute, dot-segment, traversal,
  double-separator, and NUL-bearing paths while accepting a nested relative path.
- `scripts/prove-runnable-controller.sh` drives the real database, controller, worker,
  Run.Host, shell, and `archiveArtifacts`. It publishes bytes `00 ff 41 0d 0a 42`,
  retrieves those exact six bytes over HTTP, checks the binary headers, and proves an
  unauthenticated request returns 401 without disclosing the payload.

These tests close FG-042's remaining retrieval dependency as well as FG-042b.

## Explicit boundaries

- This is known-path download. It does not add artifact listing, metadata, range
  requests, upload, promotion, retention policy, content addressing, or reproducibility.
- Retrieval is for completed archived output. No snapshot guarantee is made while a
  same-UID process concurrently modifies an artifact in place.
- Descriptor-bound path validation prevents traversal and symlink escape; it is not
  same-UID filesystem, hard-link, mount, namespace, or host-administrator isolation.
  Those remain part of the execution-containment boundary recorded under FG-222.
- The route is Linux-specific, matching the controller's existing process and storage
  assumptions. It returns an explicit `artifact_platform_unsupported` refusal rather
  than weakening the descriptor check or misreporting a permanent mismatch as a
  temporary storage outage on another operating system.
