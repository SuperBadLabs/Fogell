# FG-216 — case-sensitive JUnit report patterns

Status: **DONE** on 2026-08-23. The authoritative gate passes on the final
ticket tree; exact-head CI and review are the remaining repository merge
controls, not ticket implementation work.

## Bounded claim

On the pinned Linux Jenkins/JUnit boundary, `junit testResults:` matches literal
path characters case-sensitively, including literals beside `*` as measured
here. A
case-only mismatch is not opened or parsed and follows the existing no-report
or `allowEmptyResults` behavior. Normalization, comma tokenization, supported
wildcard syntax, deduplication, and global sorting are unchanged.

This ticket changes only JUnit report selection. Archive/stash glob behavior,
Ant default excludes, symlink traversal, platform-specific path separators,
`skipOldReports`, richer Ant syntax, and unmeasured wildcard edge behavior
remain outside the claim.

## Implementation

`Publish.expandGlobWithCase` now owns the existing glob translation with an
explicit matching mode. The public/shared `expandGlob` entry point preserves
its prior case-insensitive behavior. `parseJUnitWithAbort` alone uses the new
case-sensitive entry point. No request, walker, XML traversal, count, duration,
or result-channel code changes.

Focused coverage pins exact-case selection, default and allowed case-only
misses, literal case beside a wildcard, exclusion of a differently cased
failing report, and the unchanged shared archive/stash entry point. Execution
passes 52/52.
