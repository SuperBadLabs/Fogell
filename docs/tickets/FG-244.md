# The no-egress fence — built 2026-09-04

Status: **DONE** (P1). Filed and closed in one pass on 2026-09-04, on the
owner's instruction to build the fence, as the first paid-for entry in
FG-242's capability inventory. Publication identities are appended below
once the merge exists.

## What was missing

The operating contract says imported Jenkinsfiles may be executed only
"allowlisted by executed surface, on a no-egress network, in a disposable
workspace". FG-200 probed on 2026-08-17 that the middle clause was not true
of the lab: `jenkins-lab` resolved DNS and fetched an external HTTPS URL
(HTTP 200), and the Fogell side ran on HeMan with full egress. Every corpus
file with an `sh` step therefore waited on the fence, and FG-242 measured
that pool at 21 files, two of them with shell bodies that need no tool.

## What was built

Two scripts, no engine change, no change to the oracle container.

**`scripts/no-egress-fence.sh`** — the fence, one side at a time.

- **Jenkins side** (`jenkins apply|verify|quiesce|remove|status`). `jenkins-lab`
  is a rootless podman 4.9.3 container on luigi with `slirp4netns`
  networking. Its network namespace is owned by our user namespace, so
  `nsenter -t <pid> -U --preserve-credentials -n` enters it as our own user
  — no root, no `--cap-add`, no recreation of the oracle — and `nft` loads a
  ruleset that filters exactly that container:

  ```
  table inet fogell_fence {
    chain output {
      type filter hook output priority 0; policy drop;
      oif "lo" accept
      tcp flags ack accept
      counter reject
    }
  }
  ```

  Stateless on purpose: a packet with ACK set belongs to a flow that already
  exists (Jenkins answering HeMan on its published port, or a reply), a SYN
  without ACK is a new outbound connection, UDP (DNS) and everything else
  is rejected outright. REJECT, not DROP, so a step that tries the network
  fails in milliseconds and identically on every run instead of hanging an
  executor. The ruleset lives in the namespace and EVAPORATES when the
  container restarts, which is why it is applied and proven per run and
  `status` reports what is there rather than what was configured.

- **Fogell side** (`fogell run -- <command>`). HeMan silently ignores
  `IPAddressDeny=` on user units and forbids unprivileged user namespaces
  (`unshare -rn`: "write failed /proc/self/uid_map: Operation not
  permitted"), both measured before choosing this design. The fence is a
  root nftables rule keyed to the cgroup of a transient systemd user scope
  (`systemd-run --user --scope --slice=fogell-fence.slice`) that the command
  runs in. `nft` binds `socket cgroupv2` to the cgroup's identity AT LOAD
  TIME and refuses a path that does not exist, so the rule is loaded from
  INSIDE the live scope, proven there, and deleted on exit. Before the rule
  is deleted every process still in the scope is killed, so nothing a step
  backgrounded outlives the fence; a rule left for a dead scope (its cgroup
  directory gone) is swept on the next run, a live one is never touched, and
  only this user's tables are considered at all — the table name carries the
  UID, because another user's live scope lives under another cgroup root and
  would otherwise read as stale (Codex on PR #389). The oracle and ssh
  addresses are taken numeric or from `/etc/hosts` only: a DNS lookup there
  would be egress before the fence exists (Copilot on PR #389).
  Inside the scope the reachable set is the oracle port and the collector's
  ssh port on the Jenkins host, plus loopback minus systemd-resolved's stub
  listeners (`127.0.0.53` AND `127.0.0.54`), so DNS does not resolve inside
  the scope; the oracle host resolves from `/etc/hosts`. The rule matches by
  cgroup: it fences the command and every process it spawns — the
  differential CLI, Fogell in-process, and every `/bin/sh` a step starts.

  **What the Fogell side is and is not.** It is a network fence for the
  executed surface that turns an accidental or ordinary network call into
  an immediate refusal. It is NOT a boundary against a hostile file. The
  fenced processes run as the operator's own UID on HeMan, and the
  verifier measured four ways that UID hops off the fence: `ssh luigi
  'curl https://…'` through the collector's allowed port (HTTP 200);
  `systemd-run --user … curl` (the user manager spawns outside the cgroup,
  HTTP 200); passwordless `sudo nft delete table …`; and any listener on
  loopback (measured: a local metrics port answered). None of these is a
  property of the fence: they are properties of running Fogell as the
  operator, which FG-073 records as "no hostile-workload containment", and
  the allowlist-by-reading rule is the control that addresses them. The
  JENKINS side is the network boundary — a namespace, in which the verifier
  found no same-UID hatch.

**`scripts/run-corpus-differential.sh`** — the corpus lane. It refuses, in
order: a file outside the pinned corpus; a corpus whose manifest does not
verify; a missing CLI build; a second lane of this user on this host (a
lock, because a second lane's exit trap would remove the first lane's
Jenkins fence — measured); a busy oracle; a lane LEASE it cannot take — a
`flock` on the Jenkins host whose holder is `cat` reading an ssh session's
stdin, fed by `tail --pid=<lane pid>`, so the lease is atomic across users
and hosts and is released when the lane's pid is gone however it went
(measured: lock free after a normal exit and after `kill -KILL` of the
lane, holder and feeder both gone; a first version held with `sleep
infinity`, which ignores stdin and outlived the client — the verifier
measured it stuck); a Jenkins fence that cannot be applied or proven; a
Fogell fence that cannot be proven. Its exit trap is installed BEFORE the
fence is applied, so a partial apply is never left behind. On exit,
whatever happened, it QUIESCES the container — kills every process that is
not init, the Jenkins JVM or the exec itself. The JVM is the process whose
cmdline names `jenkins.war` with the EARLIEST start time: it started with
the container, before any build could spawn an impostor named `java` or
carrying `#jenkins.war` in its arguments; `/proc/<pid>/stat` is parsed
after the closing parenthesis of the comm field, because a comm with a
space shifts every whitespace-split field (measured: `cp /bin/sleep
/tmp/java`, `sh -c 'sleep 60 #jenkins.war'` and a copy of `sh` named
`a b` running the same were all killed while pid 2 lived; the name-only,
first-match and naive-`$22` versions were Codex's and the verifier's
findings in turn). A clean run normally quiesces 0 or 1 process — a
durable-task wrapper can linger a moment after the build. So a step's
backgrounded process does not get egress after the run (measured escape,
fixed) — and removes the Jenkins fence, reporting a deletion that FAILS
rather than swallowing it, short of ssh itself failing; the runbook covers
a leftover.

## What the verifier measured

The pre-push verifier attacked both fences from inside before this landed.

- **Held, Jenkins side.** IPv6 to a public and a link-local address, UDP to
  `1.1.1.1` and to the slirp resolver, `/dev/tcp/1.1.1.1/80`, the slirp
  gateway `10.0.2.2` on the oracle, ssh and 8080 ports, the tailscale and
  LAN addresses of the host itself — all refused; loopback 200; inbound
  200. `tcp flags ack accept` is not exploitable from the container: uid
  1000 with an empty capability set has no raw sockets, slirp delivers no
  unsolicited inbound (no simultaneous open), and ICMP and every other
  protocol hit the reject; the `inet` table covers IPv6.
- **Held, Fogell side.** Child and grandchild processes, `setsid`, python
  TCP and UDP sockets, `dig` over UDP and TCP, `nc`, `ping` (EPERM), other
  ports on luigi, other hosts on the LAN and tailscale — all refused.
  `ip daddr` in the `inet` table is IPv4-only, which is fail-closed: IPv6
  to anything, the oracle included, is rejected.
- **Escaped, then fixed.** A second `fogell run` swept the first run's
  table (the sweep now deletes only tables whose scope cgroup is gone). A
  `nohup … &` process outlived the fence on both sides and fetched an
  external URL after teardown (the scope is now killed before its rule is
  deleted; the container is quiesced before its fence is removed; both
  re-measured: the survivor's output file is absent). Names resolved
  through systemd-resolved's second stub at `127.0.0.54` (now rejected
  with `.53`; `resolvectl query` over D-Bus still answers, which is the
  stated limit below). `verify` treated a probe that produced no output as
  a refusal (now a failure).
- **Escaped, stated, not fixable here.** The four same-UID hops above.
- **The oracle was killed once, by me, while fixing this.** The verifier
  had shown the naive `$22` parse choosing a space-named impostor over
  pid 2. My patch script aborted on a text mismatch without writing, I did
  not check that the fix had landed, and I ran the impostor test against
  the unpatched quiesce: it kept the impostor and SIGKILLed the Jenkins
  JVM at 09:53:55Z; `jenkins-lab` exited 137 and was restarted at
  09:54:08Z (up in 12 s, volume-backed home intact, 8 executors, 28 jobs,
  154 plugins; the peer session was told). The corrected selection was
  then dry-run inside the container with the kill disabled — `CHOSEN
  jvm=2 … matches=3` — before the live quiesce ran again. The rule this
  earned: grep for a patch before running anything that kills, and test a
  kill's selection with the kill disabled first.
- **Found by review on PR #389, fixed before merge.** A build's own `java`
  would have survived the quiesce (the JVM is now found by `jenkins.war`
  and an impostor named `java` was measured killed while the JVM lived);
  another user's live Fogell table would have been swept (per-UID names);
  two lanes from different users or hosts could both pass the busy check
  and share the one Jenkins fence (the lease; measured refusing a lane
  while held, and — after the verifier found the first holder outlived
  its client — measured released on the lane's death, SIGKILL included);
  the lane trap was installed after apply (now before, with
  quiesce conditional on a fence having been applied); a failed
  `nft delete` read as removed (now reported); the container name reached
  a remote shell unquoted (now `printf %q`); hostnames were resolved
  before the fence existed (now `/etc/hosts` or numeric only); and the
  runbook's recovery removed the fence without quiescing (now quiesce
  first).

## The allowlist, stated

The executed surface is `sh` running `echo`, once with a redirection into
the workspace. In the container the shell can reach loopback only; in the
scope its own sockets reach loopback and the oracle host only; DNS is
refused on both; every other destination is rejected before a connection
exists, subject to the same-UID hops stated above. The workspace is
disposable on both sides.

## Limits, stated

- The Jenkins ruleset is per-namespace and per-uptime. Nothing persists it;
  the lane proves it every time, and a run that skips the lane is a run
  without a fence.
- The Fogell side is a same-UID fence: it refuses accidental and ordinary
  egress from the executed surface and does not contain a hostile file
  (the four hops above). The Jenkins side is the boundary. A run on the
  Fogell side needs passwordless `sudo` for `nft` on HeMan, and that same
  sudo is one of the hops.
- The fence is defence in depth, not the allowlist. A corpus file is still
  read before it runs; the fence makes a wrong reading fail fast instead of
  reaching the network.
- Name resolution: refused over UDP inside the container; refused at both
  stub listeners inside the scope, so `getent` and `curl` fail, while
  `resolvectl query` over D-Bus still answers — a name can be learned, a
  connection cannot be made by the fenced socket itself, and DNS-shaped
  exfiltration through the resolver daemon is not closed on the Fogell side.
- Loopback inside the scope is open, and loopback on HeMan carries every
  local listener (databases, a metrics forwarder); the fence does not
  narrow it.
- Teardown races: a process that daemonises in the instant between the
  quiesce and the fence removal would survive; the window is one ssh
  round-trip and was not observed.
- A lane killed with SIGKILL runs no trap: its lease is released (the
  feeder dies with the pid) but the Jenkins fence it applied stays until
  the runbook's recovery (`jenkins quiesce`, then `jenkins remove`) — the
  lab is left FENCED rather than open, which is the safe direction.
- What the fence does NOT unlock is in FG-242's inventory, which stays the
  one place that list lives: implicit shared libraries (58 files), SCM,
  credential and plugin steps, unmodelled core steps, answered `input`, and
  the sixteen `sh`-bearing files whose bodies need `mvn`, `gradlew`, `npm`,
  `make`, `pip`, `docker`, `java`, `git` or a cloud CLI pinned on both sides
  before a fenced run means anything.
