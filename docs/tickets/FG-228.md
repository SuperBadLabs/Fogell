# FG-228 — Stash symlink boundary

Status: **TODO**.

## Problem

The current stash implementation recursively enumerates the workspace and copies
selected paths into controller storage. FG-044b proves Ant default-exclude selection,
but neither that receipt nor its local suite defines what happens when a selected
file or directory is a symbolic link, especially when the target is outside the
workspace.

Without a measured policy, default-exclude parity must not be cited as a general
workspace-containment guarantee.

## Acceptance

Measure pinned Jenkins behavior for all of the following under both default excludes
and `useDefaultExcludes: false`:

- an in-workspace file symlink;
- an in-workspace directory symlink;
- a file symlink whose target is outside the workspace; and
- a directory symlink whose target is outside the workspace.

Then implement either the measured behavior or a named stricter refusal. The public
stash/unstash path must prove that no external sentinel bytes are copied when the
selected policy forbids them, that an ordinary file still round-trips, and that a
known-bad traversal/following mutation fails the proof. Platform-specific behavior
outside the pinned Linux boundary remains a stated nonclaim.
