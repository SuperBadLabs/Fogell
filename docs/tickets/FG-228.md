# FG-228 — Stash symlink boundary

Status: **PARTIAL — implementation and evidence complete; publication pending**.

## Problem

The pre-FG-228 stash implementation recursively enumerated the workspace and copied
selected paths into controller storage. FG-044b proves Ant default-exclude selection,
but neither that receipt nor its local suite defined what happens when a selected
file or directory is a symbolic link, especially when the target is outside the
workspace.

Without a measured policy, default-exclude parity must not be cited as a general
workspace-containment guarantee.

## Pinned Jenkins measurement

Two probes ran on Jenkins 2.568.1 under both the default Ant excludes and
`useDefaultExcludes: false`. The flag does not change the result for these
ordinary logical names:

- Jenkins restores selected file links as symbolic links with their original
  link text. The internal file link is dangling because its unselected target
  is absent; the external file link still resolves and reads the external
  sentinel while that target exists.
- Jenkins follows selected directory links and archives matching descendants as
  ordinary files, whether the target directory is inside or outside the workspace.

The external-directory result is incompatible with a workspace-containment
claim: the restored `out-dir-link/value.txt` contains the external sentinel.
The two three-attempt post-fix receipts retain that exact Jenkins side in
[`evidence/20260901T023015Z-fg-228-stash-symlink-boundary`](../../evidence/20260901T023015Z-fg-228-stash-symlink-boundary).
They are deliberately `DIVERGED`, not tier-1 compatibility receipts, because
Fogell chooses the stricter boundary below.

## Delivered policy

Fogell refuses the whole stash when an included file is a symbolic link or is
reachable only through a linked directory. The rule applies before and after Ant
default-exclude opt-out. A no-follow enumerator opens the root and every child
directory through live `O_DIRECTORY|O_NOFOLLOW` descriptors, then enumerates
through `/proc/self/fd`; a pathname substitution therefore refuses instead of
entering a directory-link target. Unselected, fully excluded, and
default-excluded links remain inert.

Every ordinary selected file is then opened on Linux with `O_NOFOLLOW`. Fogell
resolves the already-open descriptor through `/proc/self/fd`, requires it to name
the exact lexical path under the exact physical workspace root, rejects
directories and non-seekable inputs, and copies from that descriptor. A pathname swap after the
check therefore cannot redirect the copied bytes. Copies are assembled in a
fresh controller-side staging directory; a refusal removes the staging directory
and preserves any prior same-name stash.

Replacement is rollback-aware but is not claimed crash-atomic or safe for
concurrent same-name publishers. The move of the complete staging tree to the
canonical target is the commit point; failure to remove the obsolete backup is
best-effort cleanup and does not misreport a committed save as failed.

`unstash` applies the same no-follow source scan and descriptor read to
controller storage. Workspace output is created relative to opened directory
descriptors: every ancestor and the final leaf use `O_NOFOLLOW`, so neither a
corrupted stored link nor a pre-planted destination link can redirect restored
bytes. The stored Unix permission bits are applied through the opened output
descriptor after copying, preserving executable and special mode bits without
reopening the destination path.

The public walker reports `stash refuses selected path … symbolic link`, marks
the step/build failed, and does not run the stage successor. This is intentionally
stricter than Jenkins' directory-link behavior.

## Acceptance evidence

- Execution tests cover in-workspace and external file/directory links with
  defaults on and off. They require the refusal, no internal or external sentinel
  in controller storage, and byte-exact preservation of a seeded ordinary stash.
- The public Differential test first round-trips an ordinary file through
  `stash`/`deleteDir`/`unstash`, then reaches all four link shapes, requires a
  named terminal refusal, no successor, preserved post behavior, unchanged
  external sentinels, and no link-target bytes in the controller stash tree.
- The blocking `prove-fg228-stash-symlinks.sh` gate first passes the production
  suite, then compiles a mutant that enters directory links and replaces the
  descriptor boundary with a pathname-following `File.OpenRead`. The same
  external-sentinel test kills that known-bad mechanism for the named reason.
- The focused FG-228 suites pass 10/10 Execution tests and 2/2 Differential tests
  on HeMan. Exact-tree full-gate, hosted review, and merge identities remain the
  publication step; this ticket must not be marked DONE before they exist.

## Boundary

This is a pinned Linux stash-read boundary. Stash and unstash fail closed when
these descriptor semantics are unavailable off Linux; cross-platform path/link
parity is not claimed. It does not make arbitrary shell filesystem access safe, isolate a
same-UID process from controller state, prevent hard-link or mount substitution,
or extend the policy to archive/JUnit selectors. JUnit's separately measured
compatibility scanner may follow links under its own bounded FG-221 contract.
