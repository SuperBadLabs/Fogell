# FG-246 — The map-form `parallel(...)` step with closure branches is refused as `malformed_syntax` inside a Declarative `steps { }` block; Jenkins runs it

Status: **TODO** (P2). Filed 2026-09-04 from the grok QA combined report's
7,500-file "worldly" run (266 `tpl_parallel` files the generator expected to
admit were refused), measured on Jenkins 2.568.1 and on this engine before
filing; not implemented.

## Measured, 2026-09-04

Two transient jobs on the pinned lab (`qa-probe-par-steps-20260904T212857Z`,
`qa-probe-par-script-20260904T212900Z`, both deleted after their console was
read; container start instant unchanged before and after). The pipeline is the
worldly template verbatim: a Declarative stage whose `steps { }` calls

```groovy
parallel(
'b0': { echo 'WORLD_PAR_04149_B0'; sh 'echo par-04149-0' },
'b1': { ... },
'b2': { ... }
)
```

once bare inside `steps { }` and once wrapped in `script { }`.

| engine | bare in `steps { }` | inside `steps { script { } }` |
|---|---|---|
| Jenkins 2.568.1 | **SUCCESS**. `[Pipeline] parallel`, then `[Pipeline] { (Branch: b0)` / `(Branch: b1)` / `(Branch: b2)`, the three `echo` lines, then the three `sh` xtrace pairs; no `[b0]` prefix on any branch output line; no warning | **SUCCESS**, identical apart from the `[Pipeline] script` / `[Pipeline] // script` framing |
| Fogell at `ac3e934e` | parse refusal `malformed_syntax` — "a parenthesised argument body that does not parse is refused, never downgraded to one positional value" — positioned at the LAST branch closure's closing brace | not measured separately: the same parser reads the `script { }` body |

Spellings tried on this engine, every one refused with the same message:
quoted keys (`'b0': { }`), unquoted keys (`b0: { }`), a single entry, double-quoted
keys with a trailing comma before `)`, and multi-line closure bodies with `sh`.

Corpus (228 pinned files): eight carry `parallel(`. Six are scripted
`node { }` files and wait on a scripted walker, not on this ticket. Of the two
Declarative ones, `jjasghar_jenkinsfile_cookbook_pipeline` is tier 3 today with
exactly this refusal (`@72:13`, the closing `)` of a quoted-key map with a
trailing comma) — a one-file admission lever — while
`Romeh_spring-boot-sample-app` is ADMITTED parse-only although its `steps { }`
calls `parallel(IntegrationTest: { script { ... } }, ...)`. The parser's
boundary is therefore not "the map form" but something narrower about the
closure bodies; the first job of this ticket is to pin that boundary with
tests before changing it.

## Why it matters

- ADR 0001's admission class: a shape Jenkins runs is refused here. The
  refusal is honest (refuse-not-diverge), so no receipt lies, but 266 of the
  7,500 generated worldly files and one pinned corpus file are admission
  losses that a parser change would recover.
- Refusal precision (the FG-114 class): the reason names a parser fallback
  ("parenthesised argument body that does not parse"), not the shape. A reader
  cannot tell an unsupported feature from a typo.
- ADR 0005's `[branchName]`-prefix note describes the scripted map form's
  console; this measurement shows the same map form inside Declarative
  `steps { }` prints NO prefix on Jenkins either, only the
  `{ (Branch: name)` framing, so an implementation must not add one.

## Acceptance

1. The parser's exact refusal boundary for `parallel(` argument bodies is
   pinned by tests (which closure-body shapes parse today, which do not).
2. Map-form `parallel(` with closure branches is accepted inside `steps { }`
   and inside `steps { script { } }`, and the walker runs the branches with
   Jenkins' framing; receipts `parallel-map-form-steps` and
   `parallel-map-form-script` sealed tier 1 against the lab.
3. `jjasghar_jenkinsfile_cookbook_pipeline` re-scored: admitted, or its next
   refusal named on this ticket.
4. Any spelling that stays unsupported is refused with a reason that names
   the shape, not `malformed_syntax`.

## Not in scope

The six scripted `node { }` corpus files (scripted walker); `failFast` on the
map form (`parallel(failFast: true, ...)`), to be measured when (2) lands;
the worldly generator's own labelling.
