# FG-208 — malformed JUnit XML is a synthetic failed test

Status: **DONE** on 2026-08-22.

## Measured divergence

Fogell treated any XML parse exception as an unreadable report: the `junit`
step failed, published no `TestResultSummary`, and stopped its successor. Pinned
Jenkins 2.568.1 with JUnit plugin `1416.vd753e036de5e` does something narrower
and observable. A matched lowercase-`.xml` file containing literal `not-xml`
becomes one synthetic failed test named `[failed-to-read]`; the step continues,
returns `1,1,0,0`, exposes `passCount` as `java.lang.Integer`, and marks the
build UNSTABLE. An unretained read-only oracle audit observed the shape three
times; the retained tier-1 case below is the published proof.
A zero-byte report takes an earlier `[empty]` arm independent of extension: a
retained case with empty `.txt` and uppercase `.XML` inputs returns `2,2,0,0`,
continues, exposes Integer `passCount`, and finishes UNSTABLE.

The retained aggregation case separately proves that one consistent passing
report plus one malformed `.xml` returns `2,1,0,1`, continues, and finishes
UNSTABLE. The unretained read-only audit also observed two malformed files,
marking suppression, and the case-sensitive extension gate for non-empty
uppercase `.XML` and non-XML inputs; those observations are disclosed as
unretained rather than promoted to receipt claims. Focused Fogell tests and the
captured bytecode pin their implementation boundary.

The pinned plugin bytecode explains that extension boundary:
`TestResult.parsePossiblyEmpty` checks file length first and creates `[empty]`
without inspecting the suffix. Java's length probe also returns zero for a path
which vanished after glob expansion, so that edge takes the same synthetic arm
without an open attempt. `TestResult.parse(File, ...)` catches dom4j
`DocumentException` only when the path ends exactly `.xml`, constructs a
synthetic suite and failed case, and continues its file loop. A nonzero report
which cannot be opened remains terminal.

## Implementation

`Publish.parseJUnitWithAbort` now probes length before opening; a zero-byte or
vanished matched file adds one total and one failure. It handles
`System.Xml.XmlException` from a non-empty lowercase-`.xml` the same way.
Successfully parsed sibling totals remain accumulated. Every other exception
retains the existing `Unreadable` path, and interruption still wins before and
after the scan.

Execution regressions pin the ordinary and fully suppressed result channels,
extension-independent empty and vanished reports, per-file multiplicity,
valid-plus-malformed aggregation, exact case-sensitive extension gating, I/O
faults after a nonzero probe, checked-width accumulation, and both interruption
boundaries.
Differential runtime tests pin returned counts, continuation, and the
Integer-not-Long `passCount` provenance.

Three tier-1 cases are retained:

- `fg208-junit-malformed-xml` — `1,1,0,0,Integer`, continuation, UNSTABLE.
- `fg208-junit-malformed-mixed` — `2,1,0,1`, continuation, UNSTABLE.
- `fg208-junit-empty-any-extension` — `2,2,0,0,Integer`, continuation, UNSTABLE.

The immutable bundle
`evidence/20260822T111812Z-fg208-junit-malformed-xml` binds the inputs,
receipts, oracle/container identity, JUnit jar digest, and before/after private
bytecode for `TestResultSummary`, `TestResult`, `SuiteResult`, and `CaseResult`.

## Residual boundary

This is not a general JUnit XML parser rewrite. The oracle also proved that
Jenkins derives counts from testcase children rather than trusting suite
aggregate attributes; Fogell still trusts those attributes, including missing,
nonnumeric, negative, or inconsistent values. Well-formed documents containing
no recognized result also remain separate work. JUnit duration, object/UI
surface, numeric-width arithmetic, and other options remain under FG-177's
explicit residual.
