# Bounded scripted walker: `node`, `stage` and map-form `parallel` over the hosted interpreter

Priority: **P1**

Verb: **run** a scripted `node { }` Jenkinsfile.

Status: **TODO**. Filed 2026-09-10 by the Track 4 re-cut; the decision is
recorded in `adr/0009`. First Track 4 row by demand.

## Demand

The `scripted-ok` row of [FG-263](FG-263.md)'s table, which is the scorer's
own verdict in `corpus/BASELINE-DECLARATIVE-SCORE.tsv`. The `scripted-err`
row is NOT counted for this ticket: those files fail
`Fogell.Groovy.Parser.Parser.parse` itself, and a walker over
`Interpreter.runHosted` needs the parsed `Script`, so they wait on parser
work that this ticket does not include (Codex, PR #446). FG-245 measured that the walker
refuses every one at 1:1 with `no_pipeline_block`; FG-247's survey counted 122
such files among the admitted rows at its reading. This is the largest single
class in the corpus and it is refused by a `looksDeclarative` regex in
`src/Fogell.Pipeline.Parser/Parser.fs` before anything runs.

## Design

- `Parser.parseWithLimitsAndStagesBodyStart` routes a source with no
  `pipeline { }` block to a new `ScriptedWalker` in the walker project (after
  FG-262) instead of refusing. The whole file becomes one hosted body run by
  `Interpreter.runHosted` with a scripted vocabulary.
- `node` (bare, `node('label')`, `node { }`), `stage('name') { }`, the
  pre-block `stage 'name'` spelling (a stage boundary that runs until the next
  `stage` or the end of the `node` body, which is how the alternate acceptance
  file is written), and the map-form
  `parallel(a: {...}, b: {...}, failFast: bool)` are hosted wrappers
  added to `WalkerRules.scriptWrappersWithHostedBody`. `node('label')` goes
  through the FG-272 placement seam; until then only the `built-in` label and
  the bare form are admitted. `stage` supplies the journal's stage name;
  steps inside are keyed by `(stage, stepIndex)` exactly as Declarative steps
  are, and top-level steps outside any `stage` (of either spelling) refuse
  (`scripted_step_outside_stage`) so the durability key is never ambiguous.
  The hosted vocabulary already holds `git`, `checkout scm`, `sh` and `echo`,
  which is every step the two acceptance files use.
- Everything else scripted — `properties`, `checkout scm` without a defined
  SCM, `currentBuild` before FG-268, `env.X =` before FG-267, classes, `load`,
  `catchError`, `ws`, `lock` — refuses by name before any effect, through the
  FG-264 static pass extended to hosted bodies where a name is statically
  visible.
- The corpus scorer's `scripted-ok` verdict becomes "parses"; the walker's own
  static pass decides "executes", and FG-263's tokens report both.

## Acceptance

One scripted corpus file whose steps are already modelled runs on both engines
under both proven no-egress fences and its receipt is PROVEN tier-1 in the
ledger. The candidate is `tknerr_jenkins-pipes-helloworld` (`scripted-ok`;
`node { try { stage('…') { checkout scm / sh / echo } } finally { stage … } }`,
every step in the hosted vocabulary; its `sh "git clean -fdx"` and
`./test_hello.sh` fail on an empty workspace, the same class as the twelve
FG-245/FG-247 receipts). The alternate is `TTFHW_jenkins_pipeline_shell_scripts`
(`scripted-ok`; the pre-block `stage 'name'` spelling plus `git url:` under
the fence). FG-242 had named `camiloribeiro_cdeasy`; that file is
`scripted-err` in the committed baseline (parse failure at 1:6) and cannot be
the acceptance file for a walker over the existing parser, so that nomination
is retracted here. A 2026-09-11 sweep of the 109 `scripted-ok` files found no
file whose `sh` bodies are all `sleep`/`echo`; these two are the only ones
whose step vocabulary is entirely modelled today, once the 58 one-line
`buildPlugin()` files are excluded. Every unmodelled scripted construct refuses
by name before any step effect, proven by a hand-written case per refusal. Not
DONE on the hand-written suite: the receipt must name a corpus file.

## Jenkins probe first

Measure on luigi: the console shape of `stage` in scripted mode (the
`[Pipeline] { (name)` annotations and whether the receipt canonicaliser
already strips them), map-form `parallel` branch narration and ordering, and
what a step outside any `stage` prints, so the comparison contract is fixed
before the walker is written.
