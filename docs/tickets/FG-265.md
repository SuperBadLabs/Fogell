# FG-265 — Real failure/fix feedback proof

Status: DONE. Owner: proof subagent.
Milestone: M1. Depends on: FG-263, FG-264.
Completion scope: local implementation and acceptance.

Problem: a stage-speed benchmark does not establish a usable correction loop.

Scope: disposable trusted failure and corrected fixtures plus a bounded harness
using the real controller and F# client. Reuse isolated controller provisioning
where practical. Record monotonic client observations and fixture/build identity.
No Jenkins oracle or imported corpus execution is needed.

Acceptance:
- A known failure is observed as non-success with its expected output; a new
  corrected submission reaches success with distinct durable build identity.
- Record admission, first nonempty feedback, terminal observation, controller and
  client identity when known, fixture hashes, polling settings and limits.
- A known-bad control proves the checker rejects false success; run timing
  dependent controls three times. Bound every wait and preserve useful failures.
- Exercise a real controller in an isolated deployment, clean up owned resources,
  and retain a concise receipt. If the environment prevents it, report the exact
  missing proof rather than claiming M1 completion.

Implementation:
- `scripts/prove-feedback-loop.py` submits trusted failure/corrected fixtures
  through the F# client to an explicitly configured disposable controller.
- `docs/runbooks/feedback-loop-proof.md` documents invocation, limits, timing
  semantics, evidence interpretation and deployment-owner cleanup.

Evidence:
- `python3 scripts/prove-feedback-loop.py --self-test` passes ten deterministic
  known-bad receipt controls and three repetitions each of actual subprocess
  deadline and aggregate output guards. This synthetic checker exercise is not
  real-controller proof.
- Three real isolated-controller campaigns passed with six distinct submissions,
  nonempty progressive feedback before completion, expected failure/output, then
  corrected success. Ten known-bad mutations rejected per campaign; all three
  saved receipts reverified. See [retained evidence](../../evidence/20260922-feedback-loop/README.md).
- An earlier sandbox transport failure is retained explicitly as a setup failure.
- [Cleanup receipt](../../evidence/20260922-feedback-loop/cleanup.json) confirms
  controller exit, removal of the exact disposable database container, and
  removal of the private token/state directory. Shared images remain untouched.
- A post-campaign process-group cleanup correction is documented in the evidence
  directory with the original measured harness retained. The final checker and
  repeated process guards passed and all three receipts reverified.
- [Combined validation](../../evidence/20260922-feedback-loop/validation.json)
  records the configuration stop and resumed checks; it does not claim an
  uninterrupted full pre-publication gate.
