## Jenkins measurement and implementation boundary

Six disposable Jenkins probes on the pinned controller established the call
boundary before implementation. One positional string prints the value and
returns genuine Groovy `null`; zero arguments prints a blank line and also
returns null; two positional arguments fail. Jenkins accepts `message:` by
treating the named arguments as a map and printing `{message=...}`, but that
broader map surface is deliberately refused here. Jenkins also stringifies
integer and null values; FG-258 conservatively admits only zero arguments or
one evaluated string.

`println` is now a hosted script step with a descriptor-owned maximum arity of
one, zero-or-single-string schema, genuine-null return contract, and explicit
named-map refusal. It shares `echo`'s secret masking and newline-aware output
path. A direct Declarative `println` outside `script { }` is rejected before
argument rendering or effects, rather than falling through a generic walker
path that could discard its arguments.

Focused tests pin the descriptor partition, string and zero-argument returns,
exact output occurrence, masking in streamed and buffered output, named-map,
two-argument, list, integer, null and boolean refusals, and the direct-call
no-render/no-effect guard. The final focused suites passed Differential
`379/379` and Execution `162/162` when run in their required process-owning
lanes.

Six isolated mutants were killed by the Differential suite: removing hosted
vocabulary, admitting the named map, raising maximum arity to two, changing
the return contract, deleting the direct Declarative guard, and removing the
executor dispatch. The last boundary-hardening pass also made the direct
argument carry an assignment side effect so an accidental render is observed.
