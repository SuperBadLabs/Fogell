## Reachable surface

Before `pipeline { }`, lines 1–3 define the zero-argument helper
`getdockertag()`. It interpolates `env.GIT_BRANCH`, replaces every `/` with
`.`, appends `.`, and interpolates `env.BUILD_ID`. The pipeline then reaches:

- `agent any` at line 5;
- pipeline environment evaluation at lines 6–9: literal
  `DOCKER_REGISTRY = "varunpalekar1/php-test"` and
  `DOCKER_TAG = getdockertag()`;
- stage `Build`, its `script { }` block, and
  `echo "install compose.json"` at line 14;
- `sh 'composer install --prefer-source'` at line 15.

There are two hidden blockers, not one. First, this route is bounded only if
`composer` is absent under the exact execution `PATH` on both engines. Tool
absence is a negative capability claim and cannot be inferred from one host or
from an old image. Second, the helper call is part of pipeline environment
evaluation before the first stage. The candidate does not read `DOCKER_TAG`
before `composer` fails, so identical terminal output could conceal a missing,
late or wrong `getdockertag()` evaluation. A receipt-shaped result alone cannot
prove that surface.

## Required measurements and controls

Before any allowlist edit, both sides must be bound to the same source digest
and run under the existing one-file corpus lane: fresh random controller and
home, disposable empty workspaces, exact Jenkins image/core/plugin closure,
fixed `PATH` and locale, `/bin/sh -> dash`, private exact-source CLI, and all
four local-access/Jenkins-host/Jenkins-egress/Fogell-egress fences proven before
the target and cleanly removed afterward.

The negative Composer capability requires, on each selected execution runtime:

1. record the exact runtime tuple and `PATH`, and prove `command -v composer`
   is absent immediately before and after the target;
2. run three direct `sh -xe script.sh.copy` probes containing exactly
   `composer install --prefer-source` in fresh empty directories;
3. require the same `+ composer install --prefer-source` trace, the same
   `script.sh.copy: 1: composer: not found` diagnostic and exit 127 on every
   probe; and
4. bind the executable search environment used by the probes to the one used
   by the job, rather than treating host-wide absence as proof of job-local
   absence.

The helper/environment surface needs a separate observable control made from
the exact top-level helper and environment declarations. On both engines it
must print the resulting `DOCKER_TAG` before any failing step for at least (a)
the no-SCM/missing-`GIT_BRANCH` environment used by the corpus lane and (b) an
explicit branch containing `/`, with a fixed observable `BUILD_ID`. It must
also establish that the helper is evaluated during environment setup and that
the literal registry value is unchanged. Only after those controls match may
the exact candidate run alone. Its required candidate outcome is terminal
`failure`, the same nine normalized lines above, the empty canonical workspace,
and no reached later surface on both engines.

## Required hostile proof

The evidence controls are not trusted until independent known-bad arms fail.
At minimum, the prospective lane must reject each of these changes separately:

- one candidate byte changed while retaining the allowlist stem, and a manifest
  or source-digest check bypassed;
- `composer` injected on only one side after the precheck, a pre/post absence
  check omitted, or the target run given a different `PATH` from its probe;
- a fake absence probe that never invokes `command -v`, or a direct probe with
  the wrong exit code, `$0` identity or diagnostic accepted;
- `getdockertag()` not invoked, invoked after the first step, returning a
  constant, retaining `/`, omitting or substituting `BUILD_ID`, or reading an
  ambient host `GIT_BRANCH` instead of the job environment;
- the candidate accepted from the nine output lines while the observable helper
  control is missing or disagrees;
- each of the four fence predicates independently disabled, a non-empty initial
  workspace, a created file, or any later step marked reached.

Positive controls must also survive: an intentionally supplied `composer`
must be found (so the absence checker is not hard-coded), the helper control
must distinguish two branch/build-id tuples, loopback/oracle collection must
remain available while no-egress is installed, and an unchanged exact candidate
must pass every identity guard up to execution. Any time-bearing or polling
arm runs three times.
