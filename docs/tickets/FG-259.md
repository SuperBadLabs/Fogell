## Reachable surface

`getdockertag()`. It interpolates `env.GIT_BRANCH`, replaces every `/` with
`.`, appends `.`, and interpolates `env.BUILD_ID`. The pipeline then reaches:

- `agent any` at line 5;
- pipeline environment evaluation at lines 6–9: literal
  `DOCKER_REGISTRY = "varunpalekar1/php-test"` and
  `DOCKER_TAG = getdockertag()`;
- stage `Build`, its `script { }` block, and
  `echo "install compose.json"` at line 14;
- `sh 'composer install --prefer-source'` at line 15.

There are two hidden blockers, not one. First, this route is bounded only if
`composer` is absent under the exact execution `PATH` on both engines. Tool
absence is a negative capability claim and cannot be inferred from one host or
from an old image. Second, the helper call is part of pipeline environment
evaluation before the first stage. The candidate does not read `DOCKER_TAG`
before `composer` fails, so identical terminal output could conceal a missing,
late or wrong `getdockertag()` evaluation. A receipt-shaped result alone cannot
prove that surface.

## Required measurements and controls

The direct controls must precede the allowlist. Only after they agree may a
reviewed allowlist row bind the exact candidate digest and runtime pin. The
existing one-file corpus lane then supplies the fresh random controller and
home, disposable empty workspaces, exact Jenkins image/core/plugin closure,
fixed `PATH` and locale, `/bin/sh -> dash`, private exact-source CLI, and all
four local-access/Jenkins-host/Jenkins-egress/Fogell-egress fences before the
target, with clean removal afterward. FG-259 stopped before that permission
step because the helper controls disagreed.

The negative Composer capability requires, on each selected execution runtime:

1. record the exact runtime tuple and `PATH`, and prove `command -v composer`
   is absent immediately before and after the target;
2. run three direct `sh -xe script.sh.copy` probes containing exactly
   `composer install --prefer-source` in fresh empty directories;
3. require the same `+ composer install --prefer-source` trace, the same
   `script.sh.copy: 1: composer: not found` diagnostic and exit 127 on every
   probe; and
4. bind the executable search environment used by the probes to the one used
   by the job, rather than treating host-wide absence as proof of job-local
   absence; and
5. re-resolve the typed requirement inside every Fogell retained build,
   immediately before engine entry and against the exact effective environment
   handed to every shell launch, with any drift escaping retries and parallel
   aggregation as a harness failure rather than a comparable trace; and
6. refuse a runtime-guarded original Jenkins definition containing any `PATH`
   identifier, pipeline/stage environment, tools, or options scope, parameter,
   trigger, opaque pipeline/stage section (including `libraries`), stage-agent
   override, post block, nontrivial preamble/epilogue, or structurally reachable
   dynamic environment mutation before scheduling it. The validator walks nested-stage,
   recursive step/options and Groovy script/condition AST surfaces because
   Jenkins offers no trustworthy before-every-shell hook and a later overlay

   must also be unconditional and inherit `agent any`, with its first effectful

7. apply that Jenkins-source validation once before either engine launches, so
   a harness-level Jenkins refusal cannot leave Fogell free to execute the
   rejected source.
