## Defects and pairing

FG-187 stopped a postfix index at a top-level line break by scanning trivia
backward. That cannot recover the true opener of a non-nesting Groovy block
comment whose text contains another `/*`. In the measured FG-190 construction,
Fogell attached `[0].each` to the preceding expression and the strict
`script { }` path failed a pipeline Jenkins ran.

The same unconditional guard over-refused FG-192: `(xs\n[0])` is a continued
index while an expression delimiter is open. Both defects require the same
forward trivia fact, so they are implemented and evidenced as one parser slice.

## Candidate contract

- `ws` scans whitespace, line comments, and block comments forward. Block
  comments use Groovy's non-nesting boundary: the first `*/` closes the comment,
  even when its text contains `/*`. Unterminated block comments refuse.
- A consumed trivia span records its break bit and exact ending stream index.
  Zero-width `ws` does not overwrite it; a guard consults it only at that exact
  index. FParsec `attempt` therefore restores the stream and user state together,
  and a later token cannot consume a stale break.
- Expression-bearing delimiters increment group depth: parentheses, call
  arguments, lists/maps, index expressions, GString `${...}` placeholders, and
  `if`/`while`/`for`/`switch` headers. A postfix index may cross a recorded break
  only while that depth is nonzero.
- Statement bodies reset depth for closures, ordinary blocks, switch arms, and
  single-statement control bodies, then restore the outer depth on successful
  exit. A group nested inside a statement body still establishes its own local
  expression depth.
- Strict statement seams do not inherit the grouped exception. Command-form
  expression and statement-call arguments, typed-function lookahead, and an
  optional `return` value must begin on the head token's line, including when the
  separating break occurs inside a comment.

Implementation is confined to `src/Fogell.Groovy.Parser/Parser.fs`; focused
coverage is in `tests/Fogell.Groovy.Tests/Tests.fs`.

## Limits and non-claims

- This slice governs postfix `[` at the parser's supported expression groups; it
  is not a complete implementation of Groovy newline or semicolon inference.
- It does not add unsupported Groovy delimiters or constructs, change the
  interpreter, or broaden sandbox/step admission.
- Groovy block comments are intentionally non-nesting. Text that looks like an
  opener inside a comment is ordinary text, not a nested span.
- Receipt parity covers the two canonical constructions. Focused unit tests hold
  adjacent group/reset/backtracking rules; they do not turn every tested parser
  shape into tier-1 compatibility evidence.
