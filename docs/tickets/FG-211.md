# FG-211 — JUnit reached-owner testcase identity

Status: **DONE** on 2026-08-22.

## Measured divergence

Pinned Jenkins 2.568.1 with JUnit plugin `1416.vd753e036de5e` treats the XML
document root as one report owner even when its element name is not `testsuite`.
Every reached owner contributes its direct `testcase` children. Reachability
starts at the document root and follows only direct `testsuite` edges; an
arbitrary nested wrapper is not another traversal edge.

A direct testcase has a usable identity from an explicit `classname` attribute,
including the measured empty-string attribute, then from its reached owner's raw
`name`, then from a dotted testcase name. The pinned runtime resolves those
sources in exactly that precedence order. A simple testcase name with none of
them reaches the case parser but terminates publication with
`Cannot invoke "String.lastIndexOf(int)" because "this.className" is null`.
This is distinct from a zero-result report.

The rule applies equally to arbitrary roots and ordinary reached suites.
Pass, failure, error, and skipped markers keep the FG-209 totals and
classification. An unresolved reached case poisons the complete invocation
even beside a valid suite, whether the invalid sibling appears first or last.

An unretained oracle and source-bytecode control also establishes the adjacent
owner-marker rule. A direct `<error>` owned by an arbitrary root synthesizes one
failed case (`1,1,0,0`, UNSTABLE), while a direct `<skipped>` sibling classifies
that synthetic case as skipped in either XML order (`1,0,1,0`, SUCCESS). All
counts are Integer and continuation runs. Focused coverage holds this control;
it is not a seventh retained receipt claim.

Before FG-211, Fogell traversed the document root only to discover direct
`testsuite` children. It did not let an arbitrary root own direct cases and it
did not validate the identity needed by the pinned plugin for direct cases
owned by ordinary suites. The first shape became a false zero-result failure;
the missing-identity shape could become a false successful summary.

## Implementation and retained proof

`Publish.parseJUnitWithAbort` now processes the root and each owner reached by a
direct `testsuite` edge. Every such owner owns its direct testcase children;
only exact unnamespaced `testsuite` elements extend the work stack. Identity
resolution and validation occur before a case contributes to the aggregate.
An unresolved identity terminates the whole invocation rather than being
discarded, converted into a synthetic case, or treated as an empty report.

Existing FG-208 malformed/zero-byte recovery, FG-209 marker precedence and
checked count aggregation, FG-210 zero-result/`allowEmptyResults` behavior,
I/O faults, and interruption precedence remain unchanged.

## Residual boundary

This is not general arbitrary-XML support. Arbitrary descendants do not become
owners unless reached through an exact direct `testsuite` edge. Namespaced or
otherwise nonexact elements, exotic whitespace or duplicate-attribute behavior,
and unrelated report dialects remain unclaimed. FG-212 owns the adjacent missing
testcase `name` boundary: a class fallback admits it, while absence of both name
and class fallback terminates at an earlier constructor diagnostic.
The retained empty-`classname` admission is not a statement about JUnit display,
class/package grouping, history identity, or UI semantics.

JUnit duration, stdout/stderr attachment, the remaining summary object and UI
surface, numeric-width arithmetic, the explicit preexisting-build-result path,
and other options remain outside FG-211.
