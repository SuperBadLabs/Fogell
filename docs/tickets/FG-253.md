# FG-253 — A stage or pipeline agent Jenkins cannot allocate (`label`, `docker`, `dockerfile`) is executed here on the built-in node as if it were `agent any`

Status: **PARTIAL** (P2). The fail-closed source, focused tests, positive
Tier-1 receipt, and bounded unavailable-label evidence are complete locally.
Publication through an exact-head gate, review, protected PR, and merge remains
before DONE.

## Measured, 2026-09-04

The lab has exactly one node, labelled `built-in`. A hand-written one-stage
probe job (not the corpus file; created, cancelled, stopped and deleted, queue
empty afterwards) with

```groovy
agent { dockerfile { filename "back-end/dockerfiles/ci/Dockerfile"; label "webapps" } }
```

and one step `sh "echo fg247-probe"` printed `[Pipeline] Start of Pipeline`
and `[Pipeline] node`, then sat at `building: true, result: null` with the
queue item's `why` reading `‘Jenkins’ doesn’t have label ‘webapps’`, polled
for five minutes; Jenkins never started the stage. `Fogell.Run.Host` on the
corpus file that shape came from ran the same stage on the built-in node and
printed `+ cd back-end`, `cd: can't cd to back-end`, `completed: failure`.

On this engine `AgentLabel`, `AgentDocker` and `AgentDockerfile`
(`src/Fogell.Ir/Pipeline.fs`) are parsed for admission; the differential's
execution preflight (`src/Fogell.Differential/Fogell.fs`) refuses only
`AgentUnmodelled`, and nothing in `Fogell.Execution` reads the agent kind.
A `label` the controller cannot satisfy, or a `docker`/`dockerfile` agent
whose image Jenkins would build or pull before the first step, is therefore
executed here as `agent any`: the divergence is silent and shaped like a
build that ran where Jenkins would have queued forever or failed on the
docker-workflow plugin.

## Chosen boundary and implementation

This ticket takes option 1: **refuse before execution, by name**. The runnable
controller is explicitly single-node, and its local executor offers the exact
`built-in` label. `preflightExecution` therefore admits `AgentAny`,
`AgentNone`, and exact `AgentLabel "built-in"`, and returns
`unsupported_agent` for:

- every other `AgentLabel`, naming the requested label;
- every `AgentDocker` and `AgentDockerfile`, naming the kind; and
- the existing `AgentUnmodelled` cases.

The classifier scans the pipeline agent and every stage returned by
`Pipeline.flattenStages`, so sequential and parallel nesting cannot hide an
unsupported stage agent. It runs before `WalkerCtx`, workspace preparation,
SCM checkout, persistence hooks, or any user step. A later stage's unsupported
agent therefore blocks an earlier stage too; this is whole-model preflight, not
a stage-time allocation model.

The focused `FG-014/FG-253 unsupported Declarative agents fail closed` tests
cover unavailable labels, docker, dockerfile, and plugin agents at pipeline,
stage, sequential-nested, and parallel-nested scopes. They retain a pre-existing
workspace sentinel and prove the user effect absent through fresh, SCM, and
persisted entry paths. The production `Run.Host` also performs the same
preflight after deriving the journal's newline-terminated decoded prefix from
one immutable byte snapshot, before `Journal.repairTail`; the
restart lane supplies a torn journal and proves its SHA-256 is byte-identical
after refusal, while retaining the workspace sentinel and suppressing the user
effect. A second arm proves that a parseable `build-finished` fragment without
its terminating newline is not trusted as durable terminal state and also stays
byte-identical on refusal. A complete newline-terminated terminal journal still
takes the established no-op path and does not require the Jenkinsfile, including
when unrelated torn bytes follow the durable terminal record; that no-op also
leaves the journal byte-identical. Controls execute `agent any` plus pipeline-
and stage-scoped `label 'built-in'`.

## Differential evidence

`agent-label-built-in` is **PROVEN (tier 1)** in the hand-written case
population against Jenkins 2.568.1: both engines succeed, emit the same two
lines, and produce the same `agent-label.txt` bytes and workspace hash. Its
receipt seal is `7b64e05e9a4564d591a410e8b12d2db998f4210090705661998a8a488fe75d8d`.

The unavailable-label fixture is deliberately not a normal differential case:
the ordinary Jenkins runner waits five minutes for a terminal build, while this
shape is supposed to remain queued. The bounded probe in
`evidence/20260906T013715Z-fg253-agent-allocation/` instead observed, within
30 seconds:

- Jenkins build 1 remained `building:true, result:null`, stopped at
  `[Pipeline] node`, and queue item 101656 reported
  `‘Jenkins’ doesn’t have label ‘fg253-not-offered’`;
- its sentinel workspace file returned HTTP 404;
- Fogell exited 2 with `unsupported_agent`, named stage `unavailable` and
  label `fg253-not-offered`, and created neither workspace nor journal; and
- cleanup left the Jenkins job at HTTP 404 and zero matching queue items.

Those outcomes are an intentional conservative divergence, **not Tier-1
parity** and not scheduler modelling. The claim is that Fogell no longer runs
the stage silently where Jenkins cannot allocate it.

The thirteen corpus files remain `admitted`: admission is parse-only, and the
generated ledger cannot honestly encode an execution preflight result. The
focused tests and bounded probe name that refusal. Corpus totals therefore stay
`tier1=12`, `admitted=188`, `tier3=28`; only the hand-written suite moves
from 307 to 308 proven cases.
