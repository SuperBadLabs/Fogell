Jenkins measured FIRST, twice: approving prints **nothing** (no "Approved by …" line), a human abort ends the build **ABORTED** with `Rejected`, and a pending prompt survives a `podman restart` **with the same hex action id** and is still approvable — so the engine needed no new narration, only durable STATE (ADR 0005 updated; that line had been carried unmeasured since the inherited list was written). Shipped: an `input-decision` journal record written **before** the walker acts on the answer; `PersistenceHooks.PollInputAnswer` + a `BranchCtx.DurabilityKey` so a nested prompt can name itself; a controller-side approvals inbox in the host (`<id>.pending` published, `<id>.decision` answered with `approve`/`reject <who>`); and the one exemption to the reconciliation refusal — an interrupted `input` **whose answer is on record** re-runs, because its only effect IS the answer. **MERGED 2026-08-02 as 45deae6, PR #30 — 22 review rounds, 36 findings, the record for this project.** Proven by `scripts/run-approval-lane.sh` (wired INTO the gate, 21 scenarios): a SIGKILL with the prompt unanswered still refuses (exit 3); once answered the resume proceeds **silently** and the next step runs exactly once; with the inbox **deleted** the answer is still read from the journal; `reject` aborts and the following step never runs. Residuals, all stated rather than discovered later: (a0) a deadline is per-attempt — it dies with its run clock — so a bounded gate fails closed wherever eligibility cannot be established after a crash: a late answer is voided, a bounded answer is provisional until ruled on, and an offline answer is not adopted. Making those resume automatically needs an absolute deadline on record: **FG-046c**, measure first; (a) the re-run exemption covers a **bare top-level `input`** only — `timeout { input }` journals as `timeout`, so the answer is still durable and the human is never re-asked, but the interrupted **wrapper** refuses reconciliation like any other wrapper, because re-running its body could re-run sibling steps whose effects landed (**10 of the 22** corpus `input` files use that shape); (b) Jenkins' `ErrorAction$ErrorId: <uuid>` line after `Rejected`, and its placement at end-of-build rather than at the step, are not reproduced (engine-internal mimicry, and no receipt can compare them); (c) the differential path — no journal, no approver — keeps FG-046's named refusal, as does a host started **without** an approvals inbox
