# FG-236 — Separator-inserting transforms cross line-local masking

Priority: **P0**

Status: **PARTIAL**. The bounded source, tests, and blocking mutation proof are
implemented on the candidate branch; authoritative gate, exact-head review,
publication, and accounting remain before DONE.

## Reproduction

Both a 90-character single-line text credential and a 90-byte opaque
invalid-UTF-8 file credential produce 120-character registered base64 forms.
GNU `base64` wraps each form at column 76. Fogell receives two physical lines of
76 and 44 characters after the separators have already been removed. Neither
fragment is the registered form, so both progressive and buffered output
contain the raw encoding, the step succeeds, and no leak warning is emitted.
The opposing `base64 -w0` controls emit the same registered forms unbroken and
Fogell masks them as `****`; for text, its literal xtrace occurrence is masked
too.

This is not an invalid-UTF-8 exception and is not closed by rejecting only
credentials whose own literal value contains CR or LF. Any registered form can
be split by output separators after binding. FG-235 remains a bounded closure
for the direct multiline-literal defect and explicitly disclaims this broader
class.

## Acceptance boundary

Move redaction ahead of physical-line parsing, with:

- independent stdout and stderr matcher state;
- bounded overlap based on the longest registered form;
- ordered publication and an explicit EOF flush;
- adversarial read-chunk boundaries and inserted LF, CR, and CRLF at multiple
  widths for literal, case-folded, and base64 forms;
- ordinary-output controls and a demonstrated memory bound; and
- regression coverage for both buffered and progressive consumers.

Splitting registered forms into independently masked line fragments is not an
acceptable substitute. Common fragments would become false positives, and
fragment presence does not prove adjacency or reconstruct the separator bytes
discarded by the current callback API.

## Implementation candidate

`OutputRedactionPolicy` is an opaque provider of every registered masking form,
including file paths. It creates one mutable matcher per decoded stdout/stderr
stream; matcher state cannot cross streams. Each matcher refreshes that
monotonic inventory before consuming the next decoded chunk, so a credential
registered by a parallel sibling after the shell starts protects its later
output. A newly learned form is seeded only from the still-unpublished suffix;
bytes already proven safe and published are not retroactively recalled. The
matcher permits exactly one LF, CR, or CRLF between adjacent characters of a complete form and
removes the separator with the match. Two physical separators break adjacency,
so unrelated fragments remain unchanged and pending raw state is bounded by
three times the longest form. Per-form failure-linked state advances once per
logical character without replaying the pending suffix; work is linear in
output length times the fixed registered-form count and independent of form
length. Shared prefixes, overlapping suffixes, chunk boundaries, and EOF
resolution are settled before publication. A front character is published as
soon as it no longer begins any unfinished candidate, so an unrelated long
credential cannot stall ordinary short lines.

The walker supplies each step with the live, locked run-wide credential
inventory and the same synchronization root used by registration, rather than
only that branch's current lexical environment or a startup snapshot. Raw
matching holds that lock through separator-aware matching, framing, and
synchronous trace admission, so registration cannot land inside that interval.
External callback transport drains outside the matcher/registration lock. If a
slow earlier callback leaves lines pending, a later binding groups their
structural provenance by raw stream even when unrelated global output is
interleaved, reconstructing the single separators removed by framing. An open
affected stream retains that pending publication epoch until its true EOF, so a
binding which lands between two physical fragments can still mask the completed
form. Reframed results merge back by monotonic output order, and a collapsed
cross-line token takes the order and timestamp of its final contributing line.
ProcessGroup mints independent admission lifecycles for stdout and stderr, so
neither parallel shells nor separate process pipes can compose an invented
credential. A missing lifecycle EOF fails closed at terminal flush. A sticky
external publisher failure suppresses further transport but never throws back
through synchronous raw admission; the reader continues draining the child pipe
and `FlushOutput` later surfaces the typed infrastructure failure. A value
therefore stays protected after its
`withCredentials` block exits and when it is registered by a sibling branch
after the step starts. The walker rechecks already-redacted lines against the
current inventory while holding the same lock as registration and output
append. A binding that lands after a raw matcher snapshot but before trace
admission, or after trace admission while external transport is pending,
therefore cannot pass the publication boundary unmasked; canonical
tokens carry per-character provenance from the raw matcher and remain stable
for short all-star credentials. Literal `****` output carries no such tag and
remains eligible for a credential learned before publication; genuine tokens
cannot be crossed by a later form, shorter unmatched fragments stay unchanged,
and adjacent tokens retain their cardinality. Executor
applies a separator-aware final live-inventory pass to public `StepResult`
buffers, closing the corresponding stale matcher snapshot.

Secret-bearing non-capture shells use raw `StreamReader` tasks in
`ProcessGroup`, feed the matcher before an incremental ReadLine-equivalent
framer, and retain the existing serialized callback tail and bounded EOF wait.
The stderr reader parses and suppresses the private PGID bootstrap frame before
redaction; a registered form overlapping `__FOGELL_PGID` therefore cannot
disable process containment. Capture-mode stdout remains raw for Jenkins
`returnStdout` semantics, while the public `StepResult.Stdout` copy is redacted
with the same policy. A true reader EOF completes that matcher; a bounded
snapshot publishes only its proven-safe prefix and withholds an ambiguous
suffix. Stderr owns a separate streaming matcher. The raw readers use
asynchronous reads, and reader faults are propagated after containment and
secret-file cleanup instead of becoming a green run with truncated logs. Both
the queued provenance callback and the synchronous trace-admission callback
require the corresponding reader to reach EOF inside the bounded drain window,
so selecting the newer callback cannot bless a truncated stream. Lines
already canonicalized by the raw matcher use an idempotent walker publication
path: ordered emission and unregistered-transform screening remain, but a
literal credential equal to `*` cannot remask `****` into a different token.
That provenance is shell-only; ordinary `echo`, archive, and JUnit callbacks
retain the run-wide literal mask. Executor-generated leak warnings use that
ordinary path too, so a variable name overlapping another credential is masked.
If no ordinary callback exists, that warning remains unreported until the
buffered result pass appends it to stderr; a raw-only callback cannot make the
warning disappear.
ProcessGroup-generated timeout and cancellation narration follows the same
ordinary path; a credential equal to a fixed line such as `Terminated` cannot
escape through engine-authored output. A historical direct caller supplying
only `OnLine` receives generated narration through a live-inventory mask. A
caller supplying only the provenance-aware raw callback receives an explicit
no-op generated-output sink rather than falling back to that callback. The
shared masking-form inventory is deduplicated once before its length ordering
is applied.

## Boundaries

- This masks only complete registered forms. It does not claim to recognize
  arbitrary encodings or transformations.
- At most one physical line ending may appear in each inter-character gap. A
  second ending terminates adjacency instead of allowing attacker-controlled
  pending growth.
- A real EOF may publish an incomplete near-match unchanged. A reader fault or
  bounded cutoff cannot flush ambiguous pending text.
- Multiline credential values remain refused under FG-235. FG-236 protects a
  single-line registered form from separators inserted by output formatting; it
  does not make CR/LF-bearing values compatible.
