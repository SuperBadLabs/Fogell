# FG-268 — Bounded resumable historical retention

Status: DONE. Owner: retention subagent. Milestone: M3, production gate.
Completion scope: local implementation and measured acceptance (2026-09-23); publication remains separate.

Problem: frequent agent iterations accumulate logs, workspaces, snapshots and
artifacts; aggregate workspace bounds alone eventually halt admission.

Scope: operator age/count/size policies and bounded sweeps over terminal,
unreferenced data. Design database/filesystem ownership, deletion state machine,
reconciliation holds and cursor semantics before implementing deletion. Keep
active and uncertain attempts protected; expose expired evidence explicitly.

Acceptance: concurrent sweeps, interruption at each deletion boundary, changed
filesystem identity and database/filesystem disagreement fail safely; active,
retry-parent and reconciliation evidence survives; a workload exceeding policy
returns below target within a declared sweep bound. Prove known-bad cleaners
are rejected. Measure capacity recovery under the M1 loop workload.

This ticket implements the retention gate in PRODUCT_DIRECTION.md; it does not
replace it or permit broad unattended deployment before its evidence exists.

Implemented:
- [Ownership/state-machine design](../architecture/RETENTION.md), migration0017,
  `Fogell.Retention` maintenance CLI and [operator runbook](../runbooks/retention.md).
- Bounded age/count/logical-byte planning, descriptor-bound identity checks,
  nonce quarantine, resumable deletion cursors, conservative lineage/effect holds,
  definition payload expiry with request digests preserved, database write guards.
- Root integrates explicit410 evidence reads and expired admission refusal.

Evidence: [23 focused real PostgreSQL/filesystem tests, three repetitions](../../evidence/20260922-retention/README.md)
pass, including seven interruption boundaries, concurrent sweep refusal, replaced
identity and database/filesystem disagreement controls, protected evidence, bounded
capacity recovery, unsafe CLI controls and a deliberately bad cleaner checker.
Review additionally covered exact build-scoped HOME/stash roots and exposed a
classification-lock regression from a redundant effect trigger. The revised
candidate repeats all 23 tests three times and passes the unchanged existing
Store classification-order regression; original receipts remain preserved.

Integrated acceptance: the [sustained pilot](../../evidence/20260922-ai-e2e/pilot/receipt.json)
runs six retention phases over 60 real builds. Each takes three bounded sweeps
and returns state-file content inventory from 64–77 MB to at most 12,846,422 bytes,
with no pending deletions or holds. Payload includes workspace, source, artifacts, HOME and stash.
The complete API project passes 116 tests, including authenticated 410 behavior
for selected/deleting/expired/held evidence and status/lineage preservation.
The [complete repository gate](../../evidence/20260922-ai-e2e/validation.json)
passes all 1,385 tests and every required proof lane.
