# `currentBuild` as a nominal interpreter value

Priority: **P1**

Verb: **read** and **set** the build result from a script.

Status: **TODO**. Filed 2026-09-10 by the Track 4 re-cut (`adr/0009`).

## Demand

The `currentBuild.` row of [FG-263](FG-263.md)'s table, the most-used
construct the engine has no model for: the bare name faults `UnknownProperty`.

## Design

- `Value.fs` gains `VCurrentBuild` (nominal, the `VJUnitSummary` precedent);
  `Interpreter.fs` dispatches by property name. Reads: `result`,
  `currentResult`, `number`, `displayName`, `description`, `id`. Writes:
  `result` (through `WalkerCtx.Bump`; it is monotone and Jenkins ignores a
  downgrade — measure), `displayName`, `description`. Everything else
  (`previousBuild`, `rawBuild`, `getBuildCauses`, `changeSets`,
  `durationString`, `timeInMillis`) refuses by name.
- Journal records `BuildResultAssigned`, `BuildDisplayAssigned`, written
  through `PersistenceHooks` before the step's `StepFinished` (the
  `StepStageWarning` precedent), and REPLAYED by `Resume.plan` before any
  finished step is skipped: the plan carries the last durable result bump and
  display/description values, and the walker seeds `WalkerCtx` from them
  before running, so a build killed after a finished `script` step set
  `currentBuild.result` and before terminal publication resumes with that
  result, not SUCCESS (Codex, PR #446). The persisted `builds.display_name`
  and `builds.description` columns (a new migration) are set through a fenced
  worker callback and reconciled from the replayed journal values at resume.

## Acceptance

A tier-1 receipt for a corpus file whose `post { }` reads
`currentBuild.currentResult` and whose `script { }` sets `currentBuild.result`;
a hand-written case per refused member proving the refusal names the member;
a crash-lane case that SIGKILLs Run.Host after a `script` step setting
`currentBuild.result = 'UNSTABLE'` has finished and proves the resumed build
publishes UNSTABLE with the display name intact.

## Jenkins probe first

Measure on luigi: `currentBuild.result` before any step (null), after
`unstable()`, after a failed `sh`; whether setting `result = 'SUCCESS'` after a
failure changes the terminal result (it should not); the exact exception for
an unknown member.
