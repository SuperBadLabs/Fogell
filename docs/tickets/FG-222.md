# FG-222 — Isolate build environment from controller authority

Status: **PARTIAL — technical acceptance complete; publication and hosted checks remain**

## Problem

Fogell previously treated the controller process environment as implicit build
input in three independent places:

1. simple and expression GString lookup;
2. shell `ProcessStartInfo`, whose inherited dictionary was only overlaid; and
3. Git subprocesses, which used the same ambient launch behavior for a
   controller Jenkinsfile fetch and for build-side checkout/`git` steps.

A controller token, database URL, credential-store path, SSH agent socket, proxy,
or Git helper configuration could therefore become observable by an untrusted
Jenkinsfile even when the pipeline never declared it.

## Implemented boundary

The build-visible implicit baseline is exactly a fixed system PATH plus a run-scoped,
mode-0700 neutral Fogell HOME beneath the explicit execution root. The controller's
HOME and TMPDIR do not select it. HOME is retained because three sealed pinned
cases exercise it; using `/home/srikanth` was rejected because HeMan has a user
Git configuration there. No pinned case requires ambient USER, LOGNAME, SHELL,
HOSTNAME, JAVA_HOME, TMPDIR, locale, or controller-specific variables.

Fogell adds its synthetic Jenkins metadata, then applies pipeline/stage
environment, `withEnv`/`PATH+`, credential, and checkout overlays. Simple and
complex GStrings, shell, and build-side Git now consume that one explicit map.
Every process launcher clears `ProcessStartInfo.Environment` before applying its
explicit input, and Git executable lookup uses the corresponding profile's PATH.
The controller input is opaque; the build input remains a raw list behind internal
call sites, so fully typing both sides is future hardening rather than a current claim.

Controller Jenkinsfile verification uses an opaque `ControllerScmEnvironment`.
The build launcher cannot accept that type. The default snapshot allowlists Git
transport/configuration names; deployments may opt additional names in through
`FOGELL_SCM_ENV_ALLOWLIST`, whose own value is never copied. Controller SCM URLs
containing password userinfo, query, fragment, or unsafe decoded path delimiters
fail before process launch; username-only SSH userinfo remains supported.

## Evidence in the tree

- Execution tests pre-seed a launch dictionary, prove exact replacement, and run
  a real shell with only neutral metadata plus a declaration.
- Differential tests prove both GString paths use explicit maps and use a real
  recording Git executable to verify all six controller fetch subprocesses see
  only the opaque SCM profile. The same test proves inline-credential URL refusal
  occurs before Git starts. An integrated SCM-defined run then makes the controller
  sentinel causally necessary for a real definition fetch and proves a subsequent
  explicit `checkout(scm)` uses a separate recording build Git with no controller
  authority.
- `scripts/prove-control-env-isolation.sh` runs the Release host with planted
  credential, database, API, SSH-agent, askpass, and TMPDIR controls. It drives simple and
  complex GStrings, shell, declarations, `withEnv`/`PATH+`, a bound credential,
  and a recording build-side Git process. Eleven planted status/content mutations
  prove the checker rejects false evidence.
- The differential CLI canonicalizes the neutral Fogell HOME, not the controller
  process HOME. When that fold actually decides a comparison, the receipt stores
  and seals `${HOME}` on both sides; byte-equal literals remain literal. This keeps
  a secure per-run directory from resealing the three HOME-dependent receipts.

## Compatibility matrix

The pinned suite has 275 cases. Of those, 227 can launch shell or SCM processes.
Direct ambient dependencies are only:

- HOME: `env-inherited-output-fold`, `parallel-inherited-env-fold`, and
  `xtrace-continuation-inherited`;
- base PATH: `gstring-inherited-env-resolves`, `withenv-path-augmentation`, and
  `withenv-path-no-base`;
- explicit PATH precedence controls: `withenv-path-last-wins` and
  `withenv-path-same-list`.

The recheck must also cover all eight credential cases, twenty `withEnv` cases,
five SCM-defined checkout cases, and four Git-step cases before compatibility is
claimed.

## Explicit residuals

- This is environment isolation, not same-UID filesystem, `/proc`, cgroup,
  namespace, or network containment.
- A controller credentialed pre-definition fetch does not make credentialed
  workspace checkout safe. That requires a controller-side prepared immutable
  source/mirror whose checkout path is credential-free; controller SCM authority
  must never be passed to Git in a build workspace.
- The neutral HOME is run-scoped, but hostile same-UID processes can still inspect
  one another outside this environment boundary. Multi-job separation remains the
  responsibility of the agent-account/VM boundary in ADR 0008.
- Additional build-visible metadata needs a pinned Jenkins probe before the
  allowlist can expand.
