# FG-223 — Make evidence sealing fail closed

Status: **DONE**

## Problem

`scripts/seal-evidence.sh` used to continue after a failed corpus verification,
Release build, or test project. It then generated a valid `SHA256SUMS` and printed
`sealed`. A checksum proved only that the failure logs had not changed; it did not
prove the measurements passed.

The HeMan pre-fix control forced a nonexistent corpus path. The script returned
zero, its log contained `CORPUS GATE FAILED`, and the emitted manifest verified.
That counterexample is retained outside the tree at
`/tmp/fg223-pre-fix-negative-evidence` with manifest digest
`24899e95576922a4329145c2c5c3e83cc64997d8adca68460052f08fbb8140de6`.

## Implemented boundary

The sealer now validates its ticket path and every caller-supplied extra, refuses
reserved or duplicate extra basenames, writes into an exact
`mktemp` staging directory, and publishes the final ticket directory only after:

1. corpus verification exits zero;
2. the Release build exits zero;
3. at least one tracked `tests/**/*.fsproj` project is discovered recursively,
   and every discovered project exits zero and emits an Expecto completion
   summary; and
4. the completed manifest verifies against the staged payloads.

Any failure exits nonzero, names the failed prerequisite, removes the exact
staging directory, and leaves no `SHA256SUMS` or final evidence directory. An
existing final destination is refused instead of overwritten, and GNU `mv -T`
plus no-clobber publication preserves even an empty destination created during
the run instead of replacing it or absorbing the staging tree.
Caller-supplied measurements are copied before prerequisites run. The candidate
diff uses Git's binary/full-index form, so dirty binary bytes are part of the
receipt rather than merely reported as changed. The captured base and patch are
applied to an isolated detached worktree, verified byte-for-byte against the
captured candidate identity, and every prerequisite runs from that materialized
source rather than the publishing checkout. Materialization disables repository
hooks and filesystem-monitor commands on every snapshot Git operation, then
refuses any non-ignored or ignored untracked path in the fresh worktree before a
prerequisite can consume it. Effective Git content-filter attributes are refused
before the first diff; only the textually ambiguous configured driver names
`unset` and `unspecified` are conservatively refused when inactive, so an unrelated
machine-wide LFS driver does not disable sealing. The detached worktree is
established without checkout, its private index is populated with the captured
base plus patch, and that exact candidate's attributes are audited in the linked
worktree conditional-config context before `checkout-index` can execute a
clean/smudge/process driver. Candidate files can themselves make a conditional
include visible only after checkout, so exact-context config and attributes are
audited again immediately after materialization and after prerequisites, before
any sealer diff/status operation can execute a newly visible driver.
Filter-free raw audits require every publishing and materialized stage-0 regular
file or symlink (including executable mode) to match its candidate-index blob
before measurement, then repeat the materialized audit and exact index comparison
after prerequisites. Tracked symlink targets must also resolve within the isolated
candidate root and outside its `.git` administrative namespace, so a prerequisite
cannot consume mutable source reached through an absolute or parent-escaping
link, or the linked-worktree pointer to external Git metadata. Git-clean checkout
transforms therefore cannot hide physical bytes from the sealed candidate.
Ambient `GIT_INDEX_FILE`, `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, and object
locator variables are not candidate inputs, nor may repository-local
`core.worktree` redirect physical source: the sealer binds Git to the repository
and worktree containing the script, gives the captured-inventory derivation its
own private index, gives the linked worktree its own index, and removes ambient
redirects from prerequisite child processes. A foreign index or worktree
therefore cannot substitute a different candidate or be overwritten by snapshot
operations. Git color is disabled for machine-parsed status and diff output, and
the test-project process substitution is waited explicitly so an inventory read
error cannot be misreported as an empty inventory.
Gitlinks and other unsupported index modes fail closed. After all prerequisites and before
publication, the sealer also
re-captures the publishing checkout's diff, status,
base commit, and candidate inventory and refuses any lasting drift. That inventory
is derived by applying the captured patch to a private temporary index, so an
unstaged tracked deletion is represented as absent rather than inherited from the
publishing index. Untracked-source refusal runs before and after each candidate
capture, rather than only in an early preflight, so a stable file created in the
preflight-to-capture window cannot survive merely as an unbound `??` status line.
A second audit
refuses any lasting tracked-content, staging-state, HEAD, inventory, or
non-ignored mutation the prerequisites leave in the materialized source.

`scripts/prove-seal-evidence.sh` exercises the script in scratch Git repositories
with fake corpus and .NET executors. It plants corpus, build, test-exit,
missing-summary, missing-test-inventory, unsafe-ticket, reserved-extra, and
missing-extra failures, and checks that none publishes a
manifest or leaves a partial directory. Its positive control verifies the final
manifest and test summary. An always-green permissive sealer is rejected first,
so the proof's exit-code oracle is itself observed failing. Existing-destination
and simultaneous-publisher controls preserve the first owner and prove exactly
one atomic winner without nesting the losing staging tree. A lasting build-window
edit proves source drift cannot publish, and a dirty binary control applies the
sealed patch to a fresh baseline checkout and byte-compares the reconstruction.
Nested and direct-under-`tests/` nonconforming projects prove Git's explicit
glob pathspec cannot silently omit part of the tracked test inventory. A
synchronized edit-measure-restore control proves transient publishing-checkout
bytes cannot reach the isolated source consumed by the build; dirty-text and
shared-cwd controls prove corpus, build, and tests consume that materialization.
Dirty-deletion controls prove an unstaged tracked removal remains absent even
when an empty directory replaces its path, and that staged additions, deletion,
and a broken symlink are represented identically in the isolated build and
sealed candidate inventory. A prerequisite-planted source mutation, a hidden
extra colliding with staging internals, and a synchronized empty-destination race
all refuse without publication. An injected ordinary atomic-move failure is
independently rejected without being mislabeled as that destination race.
A synchronized delayed-copy control creates untracked source after the initial
preflight but before capture and proves it is named and refused without a partial
or manifest.
A live hostile `post-checkout` control first proves the configured hook creates
ignored input during an ordinary worktree add, then proves hook-free sealer
materialization and its build never observe that input.
A live clean/smudge control proves an ordinary worktree can contain altered
physical source while Git still reports it clean, then proves the sealer refuses
the effective filter before it executes. A second executable control hides its
driver behind a linked-worktree-only `includeIf.gitdir` configuration, proves an
ordinary linked checkout executes it, then proves the no-checkout sealer audits
and refuses that conditional context before driver, build, or publication. A
bystander LFS-style driver with no effective candidate attribute provides the
opposing portability control: sealing succeeds and the driver remains inert. A
delayed-include control tracks the include and global-attributes files that make
a non-special driver visible only after checkout; ordinary Git executes it, while
the sealer's post-materialization audit refuses before driver, build, or
publication. A
built-in `ident` transform provides the opposing non-executable control: ordinary
checkout changes Git-clean physical bytes, and the raw identity audit refuses
before build or publication.
A tracked absolute-link control proves external mutable source is refused before
build or publication, while the staged broken-link control proves a confined
link remains supported and is bound to its exact link-target bytes.
A second confined-link control ends its target in `.` and proves the complete
target bytes reach both candidate patch and materialized build unchanged.
A separate live control proves a tracked `.git` link can expose an ordinary
linked worktree's external administration pointer, then proves the sealer rejects
that namespace before build or publication.
Foreign-index and decoy-repository controls inject absolute Git repository/index
locators and a local `core.worktree`, prove ordinary Git observes the planted
foreign deletion/decoy, then prove sealing measures the script repository,
preserves both caller-owned indexes byte-for-byte, and publishes no foreign
deletion. Forced-color and planted test-inventory failures prove ANSI bytes do
not alter evidence-path filtering and producer failure retains its own refusal.
The binary full-index assertion derives the fixture object-ID length, and the
complete proof passes with both SHA-1 and `GIT_DEFAULT_HASH=sha256` repositories.

## Acceptance

- The retained pre-fix control demonstrates a checksum-valid false seal.
- Every planted prerequisite failure exits nonzero and publishes no bundle.
- A complete positive run publishes atomically and verifies standalone.
- The proof is blocking in `scripts/build-and-test.sh`.
- The unmodified authoritative gate passed on the exact signed source head.

The scope is evidence-command integrity. It does not attest the semantic quality
of a passing test, replace differential receipts, or change GitHub publication
authority. The source bookends refuse lasting tracked-content, staging-state,
HEAD, and tracked-inventory drift;
the detached materialization isolates execution from edits to the publishing
checkout, including edit-and-restore races. It is not an operating-system
security boundary against a malicious same-UID actor that deliberately locates
and rewrites the temporary worktree, or against a prerequisite that mutates and
restores source between its own reads and the final materialized-source audit.
Ignored inputs are not admitted into the captured candidate.
