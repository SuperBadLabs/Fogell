# FG-223 — Make evidence sealing fail closed

Status: **PARTIAL — technical acceptance complete locally; publication and hosted checks remain**

## Problem

`scripts/seal-evidence.sh` used to continue after a failed corpus verification,
Release build, or test project. It then generated a valid `SHA256SUMS` and printed
`sealed`. A checksum proved only that the failure logs had not changed; it did not
prove the measurements passed.

The HeMan pre-fix control forced a nonexistent corpus path. The script returned
zero, its log contained `CORPUS GATE FAILED`, and the emitted manifest verified.
That counterexample is retained outside the tree at
`/tmp/fg223-pre-fix-negative-evidence` with manifest digest
`24899e95576922a4329145c2c5c3e83cc64997d8adca68460052f08fbb8140de6`.

## Implemented boundary

The sealer now validates its ticket path and every caller-supplied extra, refuses
reserved or duplicate extra basenames, writes into an exact
`mktemp` staging directory, and publishes the final ticket directory only after:

1. corpus verification exits zero;
2. the Release build exits zero;
3. at least one test project is discovered, and every project exits zero and
   emits an Expecto completion summary; and
4. the completed manifest verifies against the staged payloads.

Any failure exits nonzero, names the failed prerequisite, removes the exact
staging directory, and leaves no `SHA256SUMS` or final evidence directory. An
existing final destination is refused instead of overwritten, and GNU `mv -T`
prevents a destination created during the run from absorbing the staging tree.

`scripts/prove-seal-evidence.sh` exercises the script in scratch Git repositories
with fake corpus and .NET executors. It plants corpus, build, test-exit,
missing-summary, missing-test-inventory, unsafe-ticket, reserved-extra, and
missing-extra failures, and checks that none publishes a
manifest or leaves a partial directory. Its positive control verifies the final
manifest and test summary. An always-green permissive sealer is rejected first,
so the proof's exit-code oracle is itself observed failing. Existing-destination
and simultaneous-publisher controls preserve the first owner and prove exactly
one atomic winner without nesting the losing staging tree.

The staged authoritative HeMan gate passes 795/795 project tests, the focused
8/8 FG-207 durability tests, every blocking proof (including FG-223), the live
228-file compatibility regression check, restart and approval lanes, and terminal
`OK`. The repaired production sealer then bound that complete log under
`evidence/20260825T121723Z-fg-223/`. The exact committed-head rerun remains the
last local acceptance step.

## Acceptance

- The retained pre-fix control demonstrates a checksum-valid false seal.
- Every planted prerequisite failure exits nonzero and publishes no bundle.
- A complete positive run publishes atomically and verifies standalone.
- The proof is blocking in `scripts/build-and-test.sh`.
- The unmodified authoritative gate passes on the exact signed source head.

The scope is evidence-command integrity. It does not attest the semantic quality
of a passing test, replace differential receipts, or change GitHub publication
authority.
