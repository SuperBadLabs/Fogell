# FG-220 — JUnit `skipOldReports` on fresh runs

Status: **DONE** (closed 2026-08-23). Production behavior, focused suites, two
promoted tier-1 receipts, retained evidence, and the authoritative gate are
complete.

## Claim

For a fresh Fogell run, literal `skipOldReports: true` filters each matched JUnit
report before XML parsing when its last-modified time satisfies the pinned JUnit
predicate

```text
lastModifiedMillis < buildStartTimeInMillis - 3000
```

The comparison is strict: a report exactly 3000 ms older than the captured run
origin is retained. Future-dated reports are retained. Default and explicit
`false` do not read timestamps or filter reports. After filtering, the existing
no-result and `allowEmptyResults` paths apply unchanged.

Pinned Jenkins/JUnit passes `min(Run.getStartTimeInMillis(),
Run.getTimeInMillis())` into `TestResult` and obtains the 3000 ms margin from
`hudson.tasks.junit.TestResultfiletime.precision.margin`, whose pinned default
is 3000. Fogell captures one fresh-run origin at execution entry before
preflight; this ticket claims that fresh-run boundary only.

A resumed persisted Fogell run cannot reconstruct the original run cutoff from
the current durable state. It therefore refuses `skipOldReports: true` by name
before report scanning instead of silently applying the newer process-attempt
timestamp. Default and explicit `false` remain admitted on resume.

## Measurement and proof

report skipped before parsing, fresh and future reports, the strict equality
boundary, mixed old/fresh aggregation, all-old no-result behavior, typed
`allowEmptyResults` zero, a selected report already vanished before metadata
inspection failing unreadable rather than being misclassified stale. It passes
56/56. The Differential suite passes 154/154, retains the fail-closed
named-argument matrix, and proves the cutoff is captured at build entry rather
than JUnit invocation. The real durable-host restart lane proves resumed `true`
refuses before scanning while resumed omitted and explicit `false` parse an old
report and continue successfully.

Two canonical receipts are promoted and tier-1 PROVEN:

- `fg220-junit-skip-old-mixed` skips an ancient failing report, publishes one
  fresh passing report, returns typed `1,0,0,1` with duration `1.0`, and
  continues successfully.
- `fg220-junit-skip-old-all-allow-empty` skips the only ancient report, takes
  the existing no-result/allow-empty path, returns typed zero counts and
  duration `0.0`, and continues successfully.

The pinned 228-file corpus has 36 direct JUnit calls and zero occurrences of

## Scope boundary

FG-220 does not claim `skipOldReports: true` on resumed persisted runs until the
original cutoff is durable. Runtime overrides of the pinned 3000 ms property,
queue/start-time fidelity beyond the fresh-run origin, filesystem races,
symlink timestamp behavior, platform-specific timestamp resolution, clock skew,
and nonliteral coercion are outside scope. JUnit object/raw UI operations,
generic decimal or numeric-width behavior, `currentBuild`, and remaining glob or
report-ingest residuals remain separate. FG-216 through FG-219 selection behavior
and shared archive/stash matching are unchanged.
