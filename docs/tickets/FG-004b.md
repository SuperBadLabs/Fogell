# FG-004b — Deterministic admission-negative robustness sweep

Status: **PARTIAL — corrected runtime candidate and focused proof complete;
exact-head source publication and post-merge accounting remain** (P1).

## Implemented boundary

Fogell accepts untrusted Jenkinsfile text at its admission and parser boundary.
The fixed-seed FG-004b campaign sends exactly 10,000 unique inputs through the
same Declarative `Parser.parse` entry point used by callers. Every source is
guaranteed to be refused at that boundary: recipe families supply empty/trivia
input, a valid scripted source with no Declarative `pipeline` block, incomplete
Declarative structure, unclosed delimiters, or named admission-limit boundaries
for UTF-8 source bytes, node count, nesting depth and UTF-8 scalar-content
bytes. A successful Declarative parse is therefore a failure of the campaign,
not another outcome to classify.

The initial generator implementation landed in signed commit
`2029b027dceb43a63f66412a2b00413d45276386`. During closure, the required
whole-boundary audit found that the advertised byte limits actually counted
.NET UTF-16 code units and that the ASCII-only corpus could not expose the
distinction. The first signed correction source
`3925467413a4b37802fce26445503fc29f2d1592` (tree
`998d8580caa419dad21749af800c4e9442996550`, parent
`310c0750733fe69e860ed7f1c60872d50ac1de75`) makes the limits explicitly
UTF-8, fixes the scalar-content off-by-one, bounds an overlong unterminated
scalar before parsing, preserves a typed refusal for null CLR callers, and adds
opposing BMP and astral controls. Codex then found that its closing-quote test
looked only at the immediately preceding backslash, so an even backslash run
could turn a real delimiter into apparent content and falsely refuse an
exact-limit scalar. Current signed candidate
`388bb50906e9dfb6a0be9430f547aa62eddcc9fe` (tree
`72fd4a99d20ef94abe2fd01b7d61dd4166060871`, parent
`a0f64790b98fd2af33fcc993dc63c6c172a57ad3`) counts the complete run and pins
both even-run termination and odd-run escaping for single and double quotes.
The resulting length-delimited corpus is replay-pinned to SHA-256
`31d944f3af50640f81904787bc753d2b0e1d4bd6e315184db2880bddaf5fb7b0`.

## Scope and nonclaims

This is a deterministic, bounded admission-negative robustness campaign. It is
not a grammar-aware or coverage-guided fuzzer, does not claim to enumerate
arbitrary malformed Groovy or Jenkinsfile text, and makes no compatibility claim
against a Jenkins oracle. Some controls are valid scripted inputs and are
negative only at the Declarative boundary. The guarantee is narrower and
falsifiable: these exact 10,000 replay-pinned inputs must continue to return
typed, positioned refusals without escaping the Declarative parser boundary as
exceptions.

FG-004 owns the admission limits themselves. FG-004b implements the standing
campaign that continuously drives guaranteed-refused input through those
limits and the Declarative parser; it does not expand the configured limits or
parser grammar.
