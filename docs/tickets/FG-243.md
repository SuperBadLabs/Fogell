# FG-243 — The trace comparator cannot seal a build Jenkins fails with a remoting-wrapped, multi-line exception

Status: TODO (P3). Filed 2026-09-04 (committer's local clock) from the
FG-241 lane run, measured by that run before filing. Numbered FG-243 because
a concurrent session had already taken FG-242 for its corpus-receipt work
when this filing was committed.

## Measured, 2026-09-04

The first lane attempt of the FG-241 case carried a stage whose `when {
expression { return 'ab' ==~ /a)b|ab/ } }` throws on both engines. Both
builds ended FAILURE with the next stage `skipped due to earlier failure(s)`
and identical workspaces, and the receipt read `VERDICT: DIVERGED (2)`:

```text
- output line 2: jenkins=Also:   hudson.remoting.ProxyException: org.jenkinsci.plugins.workflow.actions.ErrorAction$ErrorId: e1fe9236-… fogell=<absent>
- jenkins failed without reporting a reason
```

Jenkins' compared output kept 72 lines Fogell has no counterpart for — these
four and, because the head never opened the stack-trace window, all 66 `at …`
frames beneath them:

```text
Also:   hudson.remoting.ProxyException: org.jenkinsci.plugins.workflow.actions.ErrorAction$ErrorId: e1fe9236-9654-4145-9786-b50ba11ba1e7
hudson.remoting.ProxyException: java.util.regex.PatternSyntaxException: Unmatched closing ')' near index 0
a)b|ab
^
```

(Retried three times by the lane; the same two divergences each time.)

## Why

`src/Fogell.Differential/Trace.fs`:

- `isErrorActionIdDiagnostic` recognises `^(Also:\s+)?org\.jenkinsci…ErrorAction$ErrorId: <uuid>$`;
  on this lab the line arrives as `Also:   hudson.remoting.ProxyException: org.jenkinsci…`,
  and the `hudson.remoting.ProxyException: ` wrapper defeats the anchor.
- `startsStackTrace head next` suppresses an exception head (and counts it
  as a reported failure reason) only when the NEXT line is a stack frame.
  A `PatternSyntaxException` message spans three lines — the description,
  the pattern, a caret — so the frames start three lines below the head,
  the head is compared as ordinary output, and the failure counts as
  unreported. Any Groovy exception whose message contains a newline has the
  same shape.

Both rules are context-gated on purpose (FG-102: nothing is excluded on
wording alone), so the fix is not a looser regex. The remoting wrapper is
lab infrastructure (the controller runs the build on an agent), and a
multi-line message needs the head to look PAST its own continuation lines
for the first frame — bounded, and only when a frame does follow.

## What would close it

Teach `isErrorActionIdDiagnostic` to accept a `hudson.remoting.ProxyException: `
prefix before the `ErrorAction$ErrorId` marker (the head rule already
matches the wrapped head — `ProxyException` is itself an exception name),
and teach the head rule to treat the lines between a head and its first
frame as the message's continuation when a frame follows within a small
bound; then re-run the
FG-241 `when` shape (kept in the ticket) as a case and seal it. A planted
build that ECHOES the same four lines must still compare them (the FG-102
look-alike rows).

## Not measured

- Whether Jenkins prints the `hudson.remoting.ProxyException` wrapper on a
  built-in-node build (the lab runs on an agent) — if not, the wrapper rule
  is lab-specific and the multi-line rule alone closes it.
- How many existing receipts would change under the new rule (expected
  none: the rule only widens suppression when a frame follows).
