## Measured, 2026-09-04

The first lane attempt of the FG-241 case carried a stage whose `when {
expression { return 'ab' ==~ /a)b|ab/ } }` throws on both engines. Both
builds ended FAILURE with the next stage `skipped due to earlier failure(s)`
and identical workspaces, and the receipt read `VERDICT: DIVERGED (2)`:

```text
- output line 2: jenkins=Also:   hudson.remoting.ProxyException: org.jenkinsci.plugins.workflow.actions.ErrorAction$ErrorId: e1fe9236-… fogell=<absent>
- jenkins failed without reporting a reason
```

Jenkins' compared output kept 72 lines Fogell has no counterpart for — these
four and, because the head never opened the stack-trace window, all 66 `at …`
frames beneath them:

```text
Also:   hudson.remoting.ProxyException: org.jenkinsci.plugins.workflow.actions.ErrorAction$ErrorId: e1fe9236-9654-4145-9786-b50ba11ba1e7
hudson.remoting.ProxyException: java.util.regex.PatternSyntaxException: Unmatched closing ')' near index 0
a)b|ab
^
```

(Retried three times by the lane; the same two divergences each time.)

## Why

`src/Fogell.Differential/Trace.fs`:

- `isErrorActionIdDiagnostic` recognises `^(Also:\s+)?org\.jenkinsci…ErrorAction$ErrorId: <uuid>$`;
  on this lab the line arrives as `Also:   hudson.remoting.ProxyException: org.jenkinsci…`,
  and the `hudson.remoting.ProxyException: ` wrapper defeats the anchor.
- `startsStackTrace head next` suppresses an exception head (and counts it
  as a reported failure reason) only when the NEXT line is a stack frame.
  A `PatternSyntaxException` message spans three lines — the description,
  the pattern, a caret — so the frames start three lines below the head,
  the head is compared as ordinary output, and the failure counts as
  unreported. Any Groovy exception whose message contains a newline has the
  same shape.

Both rules are context-gated on purpose (FG-102: nothing is excluded on
wording alone), so the fix is not a looser regex. The remoting wrapper is
lab infrastructure (the controller runs the build on an agent), and a
multi-line message needs the head to look PAST its own continuation lines
for the first frame — bounded, and only when a frame does follow.

## What would close it

Teach `isErrorActionIdDiagnostic` to accept a `hudson.remoting.ProxyException: `
prefix before the `ErrorAction$ErrorId` marker (the head rule already
matches the wrapped head — `ProxyException` is itself an exception name),
and teach the head rule to treat the lines between a head and its first
frame as the message's continuation when a frame follows within a small
bound; then re-run the
FG-241 `when` shape (kept in the ticket) as a case and seal it. A planted
build that ECHOES the same four lines must still compare them (the FG-102
look-alike rows).

## Implemented boundary

`src/Fogell.Differential/Trace.fs`, 2026-09-04. One helper,
`stackTraceContinuation`, now decides for both the output normaliser and
`reportedFailureReasonWhen` whether an exception head is confirmed: by any
frame-shaped line on the very next line (the FG-002f rule and its stated
known limit, unchanged), or by two consecutive JVM-shaped frames — each an
optional module (`java.base/`) or plugin-loader
(`PluginClassLoader for x//`) prefix, a class path of at least three dotted
segments, and a source location such as `Foo.java:12`, `Unknown Source`,
`Native Method` or any identifier with an optional `:line` (a Groovy
`Script:12`; the location is shape-checked only, so `at a.b.c(d)` confirms
too — the three-segment class path is the guard); a package-less script
frame such as `at WorkflowScript.run(WorkflowScript:49)` does not confirm —
after at most
`stackTraceMessageContinuationBound = 8` non-empty, non-annotation, non-head
lines, which are then the message's own and excluded with the head and the
frames. A second head inside the span ends the first head's claim. The
JVM-shape requirement across a span is what keeps the FG-002f look-alike row
(an exception name, a line of the build's own, then `at index.js(10)`)
compared: the loose frame shape confirms only on the next line.
`isErrorActionIdDiagnostic` accepts the `hudson.remoting.ProxyException:`
wrapper before the marker — only behind the `Also:` prefix it was measured
with (Codex on PR #388: the bare wrapped form is unmeasured and stays a
build's own line, pinned by a test row); the head rule needed nothing, since
`ProxyException` is itself an exception name. The comparison contract
printed in every new receipt states the exclusion and its gate.

Tests (`FG-002f user output is never mistaken for engine narration`, the new
"FG-243: a multi-line exception message is the head's, when a frame confirms
it"; Differential 350/350): the measured shape (wrapped marker, wrapped
head, pattern, caret, frames) normalises to the two build lines and counts as
a reason; the same head with no frame within the bound keeps every line and
counts as none; a frame one past the bound does not reach back; a frame at
the bound does; two heads in a row confirm only the one a frame follows; the FG-002f look-alike row survives; two `java.base/` frames confirm on their
own, two plain package frames confirm, a package-less script frame does not,
and ONE frame-shaped line after a build's own report does not (Codex's P1 on
PR #390: a single line eight lines after an echoed report was thin evidence,
so the delayed branch requires two consecutive JVM-shaped frames — every
measured trace has dozens; the sealed receipt has 66).

The read-only verifier's probe against the first cut found every `java.base/`
frame rejected by the frame shape — the receipt was being confirmed after six message lines by a Groovy frame,
not after two by the JDK's — so the module prefix was added and the `jdkOnlyFrames` row pins it.

Proof of failure: the first FG-241 lane attempt is the measurement — the
`DIVERGED (2)` receipt quoted above — and the new test's first row fails
against the previous rule by construction (it asserts the two-line result the
old comparator did not produce; the existing FG-002f look-alike test also
caught the first cut of this change, which used the loose frame shape across
the span and swallowed its `at index.js(10)` row).

## Not measured

- Whether Jenkins prints the `hudson.remoting.ProxyException` wrapper on a
  built-in-node build (the lab runs on an agent) — if not, the wrapper rule
  is lab-specific and the multi-line rule alone closes it.
- How many existing receipts would change under the new rule: none can —
  a sealed receipt is verified from its own content — and no existing case
  prints an exception head followed within eight lines by a JVM-shaped frame
  that the old rule kept (the rule only widens suppression when such a frame
  follows).
- The bound of 8 is a judgement, not a measurement: `PatternSyntaxException`
  needs 2 (its first frame is the JDK's `Pattern.error`), and no measured
  exception needs more. A multi-line message whose continuation lines and any following
  package-less script frames together exceed the bound before a JVM-shaped
  frame appears leaves the head compared, as before this ticket; a one-line
  message is confirmed by any next-line frame, as before.
- An EMPTY line inside a message ends the head's claim (blank lines are
  already outside the comparison); such a head stays compared, fail-closed.
