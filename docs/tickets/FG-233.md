## Acceptance (falsifiable)

1. Every container the hosted gate starts, execs into, stops, inspects or
   pulls goes through `FOGELL_CONTAINER_RUNTIME`, and the workflow sets it to
   `podman` at both of its switch sites. `rg -c '\bdocker\b'` over `gate.yml`,
   every `scripts/prove-*.sh` (including `prove-backup-restore-drill.sh`) and
   both drill scripts is zero outside the runtime switch itself, its refusal
   message, and registry image names such as `docker.io/...` — comments,
   `docker-stop.stderr`-style file names and fake-runtime shim paths all count
   and must be renamed or removed.
2. The hosted Postgres comes from a `podman run` step, not `services:`; the
   drills still borrow exact-major `pg_dump`/`pg_restore` from that container.
3. The FG-224 PID-1 proof and the FG-231 six-arm bounds harness pass on
   `ubuntu-latest` under podman with their measured budgets intact, and the
   FG-231 planted-hang arms still become named refusals under podman.
4. The two drill scripts default to `docker` when run without the variable
   (`runtime="${FOGELL_CONTAINER_RUNTIME:-docker}"`); after this ticket the
   default is `podman`, so a bare local run of either drill uses the owner's
   runtime. (The local gate, `scripts/build-and-test.sh`, never runs the
   drills or the FG-224/FG-231 proofs — they are hosted-only — so it is not a
   measurement of this ticket and is not claimed as one.)

## To measure first, not assume

- Rootless podman's `--network host` and `--user "$(id -u):$(id -g)"`
  semantics against the digest-pinned `mcr.microsoft.com/dotnet/sdk` image
  the PID-1 proof uses; `/proc/1/exe` identity inside the container.
- Whether the runner's podman honours `stop --time`, `exec`, `image inspect`
  and `pull` exit codes the way FG-231's bounds and diagnostics expect (124,
  137, "No such image").
- Cold-pull time of the ~850 MB image under podman; Docker measured 14 s on
  run 33567174871.
- Whether the runner image's podman is recent enough for digest pins and
  `--rm` semantics; pin the version in the workflow if it matters.
