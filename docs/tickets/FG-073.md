# FG-073 — Current-tree threat model

Status: **DONE on 2026-08-27**. The current-tree model was independently
reviewed against source and executable proof; the audit's secret-file,
exception-cleanup, binary-log-protection, and allocation findings are closed by
load-bearing regressions; and the authoritative final-tree HeMan gate is green.
Exact-head hosted checks and repository review coverage remain publication
controls completed before handoff. Merge remains a separate owner decision.

The unpublished 2026-08-24 draft supplied a useful asset/actor/trust-boundary
structure, but was not safe to publish unchanged: 73 later mainline commits had
implemented several controls it still called absent. The draft was therefore
re-derived instead of cherry-picked. Publication is allowed only after the
rewritten model and implementation share one proved commit and GitHub confirms
that exact head; no earlier review or check is carried forward.

## Deliverable

The [current-tree threat model](../THREAT_MODEL.md) records assets, actors,
trust boundaries, abuse cases, deployment requirements, review triggers, and
hard non-claims for the runnable controller. It covers the hosted API and RLS,
parser/interpreter, registered steps, execution, secrets/logs, local and target
remote agents, network/dependencies, and evidence/release boundaries.

Its deliberately narrow supported deployment is one mutually trusting execution
domain on a dedicated Linux VM. It does not describe Fogell as a hostile
multi-tenant execution service.

## Highest residual risks

1. No hostile-workload VM/container containment or enforced no-egress boundary.
2. No tenant identity, membership, or RBAC behind the global operator bearer.
3. No secret or local Controller/Run.Host protocol isolation from same-UID code.
4. No remote-agent mTLS/session protocol, hostile-agent attestation, or
   authenticated approval broker.
5. Durable effect/retry foundations are not universally integrated into steps.
6. Dependency/evidence checks make bounded integrity claims, not a broad
   supply-chain or semantic-correctness claim.

## Audit finding closed in this change

The review found that secret companion files were created under the process
umask and chmodded to 0600 only after their content was written. Fogell now opens
new text and binary secret files no broader than 0600, restores exact 0600 on the
open descriptor, and observes that boundary while the file is empty before any
write. A restrictive-umask subprocess and text/binary content checks cover both
mode and usability. Catchable host failures also revoke bindings through
`finally`, and a later construction failure revokes every binding already
created in the same wrapper. This removes the different-UID pre-chmod and
lexical-exception windows; it does not isolate secrets from the shared UID,
process death, or a failed best-effort deletion.

A final semantic review also found that non-UTF-8 file content contributed no
log-protection forms. The binding now precomputes immutable textual forms once,
masks exact base64, and reports lower/uppercase hex without reintroducing
empty-string false positives or repeatedly encoding a full credential per log
line. The binding adds no second raw-byte copy; the credential store's source
bytes and the run-scoped managed strings are not memory-zeroized.

## Non-claims

This ticket does not add tenant authorization, no-egress enforcement, hostile
process isolation, same-UID controller/workload separation, a remote agent
protocol, universal effect/retry integration, authenticated manifests, or
reproducible packages. The threat model makes those residuals visible; it does
not close them by documentation.
