## Deliverable

The [current-tree threat model](../THREAT_MODEL.md) records assets, actors,
trust boundaries, abuse cases, deployment requirements, review triggers, and
hard non-claims for the runnable controller. It covers the hosted API and RLS,
parser/interpreter, registered steps, execution, secrets/logs, local and target
remote agents, network/dependencies, and evidence/release boundaries.

Its deliberately narrow supported deployment is one mutually trusting execution
domain on a dedicated Linux VM. It does not describe Fogell as a hostile
multi-tenant execution service.

## Highest residual risks

1. No hostile-workload VM/container containment or enforced no-egress boundary.
2. No tenant identity, membership, or RBAC behind the global operator bearer.
3. No secret or local Controller/Run.Host protocol isolation from same-UID code.
4. No remote-agent mTLS/session protocol, hostile-agent attestation, or
   authenticated approval broker.
5. Durable effect/retry foundations are not universally integrated into steps.
6. Dependency/evidence checks make bounded integrity claims, not a broad
   supply-chain or semantic-correctness claim.
7. Deep acyclic `Value` display and equality remain capable of exhausting the
   host stack as FG-191 records; this audit finds the analogous recursive
   ordering path in `Value.tryCompare`.

## Audit finding closed in this change

The review found that secret companion files were created under the process
umask and chmodded to 0600 only after their content was written. Fogell now opens
new text and binary secret files no broader than 0600, restores exact 0600 on the
open descriptor, and observes that boundary while the file is empty before any
write. A planted exact-path collision proves `CreateNew` refuses without
truncating a canary, and full-width GUIDs keep fail-closed collisions remote.
A restrictive-umask subprocess and text/binary content checks cover both mode
and usability. Catchable host failures also revoke bindings through
`finally`, and a later construction failure revokes every binding already
created in the same wrapper. This removes the different-UID pre-chmod and
lexical-exception windows; it does not isolate secrets from the shared UID,
process death, or a failed best-effort deletion.

A final semantic review also found that non-UTF-8 file content contributed no
log-protection forms. A resolved source credential now owns one immutable form
object prepared lazily on its first requested binding and shared by repeated
lexical bindings. Binary content at least eight bytes long with at least four
distinct byte values gets exact-base64 masking and lower/uppercase-hex detection;
content at that length with lower diversity retains base64 masking but omits
terminal hex detection, reducing false refusals from repeated-zero encodings.
Shorter binary content gets neither, avoiding `DE AD` versus ordinary `dead`. Empty
text still cannot cause a phantom literal warning, and
output lines never re-encode a full credential. The binding adds no second
raw-byte copy; credential-store bytes and managed strings are not zeroized.

Hosted review also found that the Jenkinsfile-controlled environment key was
interpolated into the companion filename. Companion leaves are now GUID-only,
and invalid environment keys fail explicit validation before file creation.
