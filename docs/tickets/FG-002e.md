# FG-002e — Sweep the interrupt/deadline surface for remaining early-return paths

**Status:** **SUPERSEDED by FG-101**  ·  **Priority:** P1

Archived from the execution board on 2026-08-02. The board carries the
outcome; this file carries the reasoning, which is what a future reader
needs and what a planning table cannot hold.

---

Reviews 9-12 of PR #14 each found ONE more code path that returns before polling the abort predicate: archive mid-loop, archive after the final copy, archive zero-match, junit mid-loop, junit zero-match. The pattern is "every early return is a missed poll", and it was found one instance per round rather than swept. **Raised to P1 and widened after PR #15**: the same pattern recurred in brand-new code four more times (`stash` copy loop, `stash` predicate missing the deadline, `unstash` restore, `deleteDir` recursive delete), and a sibling pattern appeared alongside it — an interrupted step reporting `Aborted` when a failFast *sibling* was the cause, which is the collateral-outranks-cause bug already fixed twice elsewhere. Acceptance: enumerate every return point in `Publish`, `Executor` and the walker; assert each either polls or provably cannot be reached after an interrupt; and assert every abort classifies its CAUSE (deadline → aborted, sibling → failure) rather than assuming one. **The cause-classification half is swept, and then had to be swept AGAIN**: a sixth instance appeared as an ordering RACE rather than a missing check — `input`'s wait tested deadline expiry before the already-signalled sibling, so a sibling failing during the final sleep lost to an expiry in the same instant and the build reported `aborted`. Testing the sibling first is the invariant; "does every site check?" was the wrong question, "does every site check in the right ORDER?" is the right one. Every `Sink BuildStatus.Aborted` site in the walker was enumerated and each either tests the deadline explicitly or distinguishes a sibling interrupt: the pre-step deadline check, `deleteDir`, `stash`, `unstash` and `input`. `input-failfast-is-failure` proves the invariant end-to-end — a failFast sibling failing while another branch waits at a gate gives **failure** on both engines, not aborted. The bug had appeared five times before it was swept (shell steps, stash, unstash, deleteDir, input); the polling half of this ticket remains open
